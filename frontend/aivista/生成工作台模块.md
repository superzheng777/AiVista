# AiVista 生成工作台模块

> 对应迭代：前端迭代 2——生成工作台
> 当前状态：已完成（真实后端联调待执行）
> 维护规则：本文记录普通文生图的页面交互、任务状态和接口消费；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

接入已完成的普通文生图后端闭环，使已登录用户能创建或选择会话、确认第三方处理规则、提交任务、实时查看状态、取消任务并查看成功图片。

本迭代不包含局部重绘、会话或图片删除、收藏、发布和社区展示。

后端业务事实与接口契约以 [图像生成任务模块.md](../../backend/aivista/图像生成任务模块.md) 为准。

## 2. 已确认约束

- 仅接入普通文生图；`imageCount` 为 `1`～`6`，服务端是最终校验方。
- 进入页面加载会话列表。首次使用展示不在列表中的空白创作框；首次成功提交不传 `sessionId`，以后端 `202 Accepted` 返回的 `sessionId` 建立当前会话。
- 空白创作框成功提交前不允许再开启新的空白会话；同一会话有未完成任务时禁用再次提交。
- 每次用户主动提交生成新的 UUID v4 幂等键；重复点击、超时和网络重试复用原键。
- 用户最多四个未完成任务，每日最多请求 12 张；前端负责提示，后端负责最终限制。
- 同一会话会继承历史提示词。工作台必须提示用户：一个会话只围绕一个主题创作，更换主题时新建会话。
- 注册、登录或会话恢复时统一确认用户协议与第三方数据处理规则；生成页面不再单独弹出同意流程。
- 结果只展示成功转存图片；取消和失败不展示虚构图片占位。

## 5. 页面、路由与交互设计

路由为 `/generate`，仅认证用户可访问。页面左侧始终展示会话列表；无 `sessionId` 时右侧为新绘画状态，居中展示生成输入区；选择历史会话或创建任务成功并获得 `sessionId` 后，右侧切换为会话工作区，上方滚动展示历史内容，下方固定生成输入区。移动端须保证会话切换、提交、取消和结果查看可达。

每轮历史内容拆分为两个角色区域：用户正向提示词和可选负向提示词使用右侧气泡；AI 的排队、处理、模型重试、失败、终态数量和生成图片使用左侧回复。用户气泡在移动端最多占可用宽度约 88%，桌面端约 72%；AI 回复和当前任务操作卡保持左侧并允许图片网格使用更宽内容区域。

| 场景 | 前端行为 |
| --- | --- |
| 登录/恢复 | 登录后先查询活跃任务，随后建立 SSE；收到 ready 后再次对账并进入 READY。 |
| 创建任务 | 校验输入；全局用户协议确认完成且 SSE READY 后才发送 POST，成功后按 `202` 快照立即显示排队。 |
| 活动任务 | 首次 `QUEUED` 显示排队；`RUNNING` 显示处理中；重试的 `QUEUED/RUNNING` 显示模型重试 `n/3` 和取消入口。 |
| 终态任务 | 成功、部分成功、失败、取消分别显示后端数量和安全错误提示；只显示成功图片。 |
| 取消 | 提交取消请求；等待权威快照收敛，不按本地猜测覆盖更高 `taskVersion`。 |
| 无数据/网络错误 | 提供明确空状态、重试和重新连接；不清空已有内存结果。 |

## 6. API、前端模型与状态管理

| 目的 | 接口 | 前端约定 |
| --- | --- | --- |
| 用户协议 | `GET /api/policies/user-agreement`、`POST /api/users/me/consents/user-agreement` | 由全局认证流程展示；生成页面只消费其已确认状态。 |
| 创建任务 | `POST /api/generation-tasks` | 必带 `Idempotency-Key`；`202` 后使用任务概要更新本地状态。 |
| 任务详情/取消 | `GET /api/generation-tasks/{taskId}`、`POST /api/generation-tasks/{taskId}/cancel` | 详情为权威快照，取消后回查。 |
| 活跃任务对账 | `GET /api/generation-tasks/active` | SSE ready 后读取全部非终态任务；同时逐个查询连接前已知的非终态任务详情，再与可见查询按版本合并。该过程每次连接只执行一次，不是轮询。 |
| 会话与消息 | `GET /api/generation-sessions`、`GET /api/generation-sessions/{sessionId}/messages`、`PATCH /api/generation-sessions/{sessionId}` | 使用后端游标分页，不伪造总数。 |
| 实时信号 | `GET /api/events` | Header 带 Bearer Token，不将 Token 放入 URL；开发环境由 `src/app/api/events/route.ts` 流式转发，生产环境由 Nginx 直接代理到 Spring Boot。 |

每个浏览器标签页最多维护一条认证用户级 SSE。认证完成后，前端先查询活跃任务，随后建立并维持该连接；多个会话和最多四个并行任务复用同一条连接，不随生成页、会话或 `taskId` 切换而重复建立。连接建立或断开后会持续自动重试：首次约等待 500ms，之后约 1s、2s，最大间隔为 3s；手动重试会重置计数。创建任务仍以 SSE READY 为门禁，等待上限为 10 秒，超时则不发送 POST。收到事件时先按 `taskVersion` 更新状态与模型重试进度；终态再查询完整详情和图片。该标签页内还维护全站任务提示：非生成页的导航图标显示 `QUEUED`/`RUNNING` 总数；所有活跃任务结束后，未查看的成功结果显示蓝点，失败或取消显示红点；生成页中非当前会话的 `QUEUED`/`RUNNING` 统一显示加载图标，终态未查看结果显示蓝点或红点。成功或部分成功事件会使活跃资产列表失效并重新请求。每次收到 ready 后保存活跃任务，并逐个复查连接前已知的非终态任务详情，避免任务在连接空窗期结束后从 active 列表消失而滞留旧状态。同版本 REST 可补全数据，旧版本响应不得覆盖新事件。

## 8. 异常场景、可靠性与安全

- `40100` 交由全局认证拦截器刷新并重放；`40102` 按工程基础文档清理会话。
- `409` 的活动任务、幂等键或同意规则冲突必须展示可行动提示；`429` 提示稍后重试；`50000` 系统繁忙时提供稍后重试。
- 任务结果、SSE 和签名 URL不得写入持久化存储、埋点或错误监控。图片页设置 `Referrer-Policy: no-referrer`。
- 会话中的签名 URL 临近到期或图片加载失败时回查消息快照；后端返回 `url: null` 的已删除图片保留原位置并显示删除占位。
- 网络重试必须复用原幂等键；前端不得自行拼接历史提示词、传服务商参数或推断任务终态。
- SSE 初次连接与断线后均会持续自动重连，重连间隔最大为 3 秒；提交前等待 SSE READY 最多 10 秒，超时则不发送创建请求。任务一旦创建，后端执行不依赖浏览器连接，重连后通过快照恢复。
