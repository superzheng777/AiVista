# AiVista 前端发现能力模块

> 对应迭代：前端迭代 7——发现与关注列表
> 当前状态：已完成
> 维护规则：本文记录发现与关注列表的当前交互、接口消费和验收；代码、测试、接口契约或交互变化时必须同步修改。

## 1. 目标与范围

在 `/inspirations` 提供“灵感 / 关注”两类作品列表。

## 2. 已确认约束

- 灵感允许匿名浏览；关注要求登录。
- 两类列表复用瀑布流、公开图片卡片、统一图片模型和作品详情。
- 前端只消费 `items` 与 `nextCursor`，不计算页码、游标或排序。
- 列表数据和签名 URL 只保留在运行时缓存，不写入持久化存储或监控上下文。
- 页面不订阅 SSE。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 页面地址 | `/inspirations` 显示灵感，`?view=following` 显示关注。 | URL 可刷新和回退。 | `/` 重定向到 `/inspirations`，未知 `view` 回退灵感。 |
| 查询状态 | 两类列表使用独立查询键。 | 避免分页数据串用。 | 切换时保留各自分页和滚动位置。 |
| 匿名关注 | 不请求关注接口，显示登录引导。 | 区分未登录与空列表。 | 复用现有认证弹窗。 |
| 空状态 | 按 `followingCount` 区分未关注作者与暂无公开作品。 | 给用户明确下一步。 | 空结果时按需读取当前用户公开资料。 |
| 图片续期 | 过期或加载失败时刷新单图并最多重试一次。 | 避免定时器和无效请求。 | 刷新后的 DTO 更新两类列表缓存。 |

## 5. 页面、路由与交互设计

- `/inspirations` 默认展示灵感；`/inspirations?view=following` 展示关注。
- 双标签工具栏吸顶，使用链接切换并提供当前态和键盘焦点。
- 初始加载显示骨架；首屏失败整体重试；加载更多失败保留已有内容。
- 未登录关注页显示登录入口；登录状态恢复中显示骨架；空列表显示对应引导。
- 作品详情继续使用 `/inspirations/[imageId]` 和拦截路由覆盖层，关闭后返回灵感页。
- 瀑布流和工具栏适配窄屏，标签不换行。

## 6. API、前端模型与状态管理

| 用途 | API | 状态规则 |
| --- | --- | --- |
| 灵感列表 | `GET /api/inspirations` | 查询键 `inspirations/discovery`。 |
| 关注列表 | `GET /api/inspirations/following` | 查询键 `inspirations/following`，仅登录时启用。 |
| 单图刷新 | `GET /api/inspirations/{imageId}` | 更新所有灵感类分页缓存中的同一图片。 |

首次请求不带游标，后续只传服务端 `nextCursor`；退出登录或会话失效时清理查询缓存。

## 8. 异常场景、可靠性与安全

- `nextCursor` 为空后停止加载；加载更多失败不清空已展示作品。
- 图片 URL 过期或首次加载失败时只刷新对应图片并最多重试一次。
- 登录失效由会话层清理缓存并将关注页切换为登录引导。
- 签名 URL、图片 DTO 和提示词正文不得进入 URL、持久化存储、埋点或错误监控。
