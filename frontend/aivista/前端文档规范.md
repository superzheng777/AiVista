# AiVista 前端文档规范

> 适用范围：AiVista 前端项目的项目总览、工程基础文档和全部业务模块文档
> 当前状态：生效中
> 维护规则：本规范变更前必须先讨论确认。代码、测试、接口契约、页面交互、前端状态和运行约定的变更，按影响范围同步更新对应文档。

## 1. 文档体系与职责

| 文档 | 职责 |
| --- | --- |
| `前端项目开发文档.md` | 项目总览：一期目标、跨模块边界、迭代路线和文档索引；不复制模块细节。 |
| `前端工程基础开发文档.md` | 工程运行、通用架构、配置、认证、请求和联调约定；不承载业务页面设计。 |
| `中文业务名模块.md` | 同一文件贯穿模块设计、实施和完成，记录用户交互、接口消费和最终维护信息。 |
| `前端文档规范.md` | 本规范，约束前端文档的职责、状态、结构和同步方式。 |

每个业务模块只保留一份模块文档。模块完成后整理为最终参考文档，并保留仍影响维护的关键决策与实施摘要。

## 2. 状态与准入条件

业务模块只使用：`设计中 → 实施中 → 已完成`。

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| 设计中 | 正在确认页面、交互和接口消费，不开始业务编码。 | 已建立模块文档，待确认项明确列出。 |
| 实施中 | 设计足以支撑当前迭代编码。 | 目标、范围、交互状态、接口映射、关键决策、异常处理和验收标准已确认。 |
| 已完成 | 当前迭代范围已交付。 | 代码完成；文档整理为最终参考；自动化测试、构建和必要联调/人工验收有记录。 |

已完成模块新增能力时建立新的迭代模块文档，不回退原模块状态。

## 3. 统一元信息与命名

模块文档使用“中文业务名 + 模块.md”，例如 `生成工作台模块.md`、`个人资产模块.md`。标题下固定使用：

```md
> 对应迭代：前端迭代 X——模块名称
> 当前状态：设计中 / 实施中 / 已完成
> 维护规则：本文记录当前迭代的前端范围、交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。
```

不维护“最后同步日期”或文档版本号，具体修改历史以 Git 为准。

## 4. 业务模块统一结构

所有模块使用以下一级章节；设计中未确定的内容必须标注“待确认”，不得伪造接口或实现细节。

```text
1. 目标与范围
2. 已确认约束
3. 关键决策记录
4. 实施计划与进度
5. 页面、路由与交互设计
6. API、前端模型与状态管理
7. 组件与实现位置
8. 异常场景、可靠性与安全
9. 测试与验收
10. 后续边界
```

“页面、路由与交互设计”必须覆盖正常、加载、空、错误和认证失效状态，以及必要的桌面/移动端差异和可访问性要求。“API、前端模型与状态管理”只记录 DTO 映射、分页、缓存、实时状态对账和重试等前端行为，后端业务真相链接至对应后端模块文档。

## 5. 关键决策、计划与实现位置

关键决策只记录最终有效、且影响实现或维护的结论：

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |

实施计划使用：

| 小步目标 | 状态 | 完成内容或当前阻塞 | 验证方式/结果 |
| --- | --- | --- | --- |

状态仅使用“待开始、进行中、已完成、阻塞”。模块完成后压缩为关键实施摘要和验证结果。

实施中和已完成模块必须列出关键代码位置：

| 职责 | 关键文件/目录 | 说明 |
| --- | --- | --- |
| 路由入口 | `src/app/...` | 页面组合、渲染边界与路由参数。 |
| 业务功能 | `src/features/...` | API 适配、状态和交互。 |
| 领域模型 | `src/entities/...` | 前端领域对象与显示规则。 |
| 通用能力 | `src/shared/...` / `src/widgets/...` | HTTP、通用组件、跨页面界面区块。 |

## 6. 测试、验收与同步

模块“测试与验收”必须区分：

| 类型 | 记录要求 |
| --- | --- |
| 自动化验证 | 测试范围、`pnpm lint`、`pnpm build` 和测试命令及结果。 |
| 联调与人工验收 | 后端环境类型、关键用户链路、桌面/移动端和可访问性结果；不得记录敏感数据。 |
| 未覆盖项 | 未执行原因、是否阻塞当前迭代和补充条件。 |

业务规则、接口、前端状态、可靠性或测试变化更新模块文档；工程通用约定变化更新工程基础文档；迭代状态和边界变化同时更新项目总览。
