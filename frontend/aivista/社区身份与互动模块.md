# AiVista 社区身份与互动基础模块

## 已确认的图片与点赞响应契约

图片列表只消费 `ImageDTO`：既有图片字段加 `authorId`、`likeCount`、`likedByCurrentUser`，不显示或携带作者昵称、头像。灵感列表直接返回图片数组；点赞列表项为 `{ image, likedAt }`。用户打开公开图片详情后，再以 `image.authorId` 请求作者公开资料。

点赞和取消点赞成功响应是 `204 No Content`，前端不可读取 JSON 响应体。

点赞列表按点赞时间倒序，列表项为 `{ image: ImageDTO, likedAt }`；`likedAt` 不是图片字段。本人读取 `/users/me/liked-publications`；使用 `/users/me/liked-publications-visibility` 设置 `publicVisible`；访问他人 `/users/{userId}/liked-publications` 时，私密列表按不可见处理。列表图片不会携带作者昵称和头像，详情打开后再用 `authorId` 请求作者资料。

> 对应迭代：前端迭代 5——作者主页、关注与点赞
> 当前状态：后端关系、点赞和消息接口已实现；灵感页、发布详情与官方消息已接入基础公开详情。作者主页、点赞列表与互动消息前端仍待实现。
> 维护规则：本文件定义作者主页与互动的用户可见行为；公开字段、权限与接口以后端同名模块文档为准。

## 1. 页面与交互范围

- `/users/[userId]` 是自己与他人共用的作者主页路由，使用稳定的原始字符串用户 ID；资料区展示头像、昵称、简介、粉丝数、关注数与获赞数。点赞列表是否公开只作为本人可编辑的隐私设置，不向他人额外展示状态文字。
- 自己访问主页时显示资料编辑和“公开点赞列表”设置，默认关闭，不显示关注按钮；访问他人主页时显示关注/已关注按钮。
- 主页的“作品”分区自己与他人均只展示已公开、审核通过的作品；当前用户额外拥有仅自己可见的“审核中”分区，使用发布审核详情，他人永远看不到。
- 作者允许公开点赞列表时展示“点赞”分区，否则不显示该分区；自己与他人的点赞分区都只包含当前仍公开的有效作品。作品下架后，下次刷新或后台重拉不再返回该作品。
- 现有“我的发布”列表的作品卡片与详情加入点赞按钮和点赞数；仅审核通过且当前公开的作品显示点赞交互，审核中作品只展示审核状态。
- 作者主页的作品分区沿用现有整列表加载方式；不为作者主页单独新增分页或“加载更多”，全站灵感流的分页在迭代 6 统一实现。
- 已审核通过的“我的发布”详情与灵感详情复用同一图片详情基础组件和公共交互；通过 `isOwner` 附加撤销发布等作者管理区。审核中作品只在作者发布列表中展示审核状态和取消审核，不进入公共详情，也不显示点赞。
- 作品列表卡片仅展示图片；不在卡片上展示作者头像、昵称或其他作者资料。点击卡片打开详情，只有已公开作品详情才展示作者头像、昵称等资料，并加载一次作者公开资料；作者头像、昵称可跳转至 `/users/[userId]`。资产详情不展示作者入口或请求作者资料。
- 本迭代已实现基础灵感列表与公开作品详情；全站灵感流分页、搜索、热门或推荐仍不在范围。作品被他人首次点赞后，作者消息中心的“互动”页签与未读角标更新属于本迭代范围。

## 2. 统一展示规则

- 已公开作品详情展示作者资料；作者主页 `/users/[userId]` 尚未实现，因此当前不提供跳转入口。
- 自己与他人资料区复用同一公开作者组件；编辑、隐私设置和关注按钮作为页面权限层附加，不复制资料布局。
- 自己的主页同样访问 `/users/[currentUserId]`；现有独立个人主页路由如需保留，只重定向至该地址，不维护第二套页面。
- 图片列表直接消费统一图片 DTO 的 `likeCount`、`likedByCurrentUser` 与轻量作者摘要，不为单张图片的点赞状态发起额外请求。
- 已公开作品详情在取得图片的 `authorId` 后，额外请求一次作者公开资料，用于展示简介、粉丝数、关注数、获赞数和当前用户的关注状态；不区分入口来自灵感列表、自己的已发布列表、他人主页作品或公开点赞列表。详情没有独立 URL，不能直接访问或刷新恢复；打开详情时直接使用列表中的完整图片 DTO。审核中和资产详情不请求作者资料。
- 页面首次加载时以图片 DTO 的 `likedByCurrentUser`、`likeCount` 和作者资料的 `viewerFollowing`、`followerCount`、`likesPublic` 初始化视图。
- 关注、点赞和点赞列表公开设置均采用明确目标状态的幂等接口：`PUT` 确保关系或设置存在，`DELETE` 确保关系不存在；成功统一返回 `204 No Content`。点赞的 `PUT` 与 `DELETE` 均携带列表 DTO 中的字符串 `publicationVersion` 查询参数，只操作该公开周期。当前控件请求期间禁用，成功后前端按本次目标状态更新视图和本地计数，失败则保持原状态并提示。
- 点赞或取消点赞采用乐观更新：点击后立即更新当前详情和已加载列表中的 `likedByCurrentUser`、`likeCount`；请求成功后保持该值，不执行后台重拉；请求失败时恢复操作前的状态与数量并提示失败。其他用户并发、撤销发布或发布版本变化以用户下次刷新取得的服务端快照为准。点赞按钮依据 `likedByCurrentUser` 展示不同图标与操作意图，未登录点击时引导登录。
- 未登录用户可看资料与已发布作品；点击关注或点赞时引导登录，不伪造成功状态。
- 用户撤销发布后，作品的点赞数在服务端归零；重新发布后前端以新的服务端快照展示，不保留旧点赞数。
- 用户撤销发布后，作品立即从灵感、作者“作品”分区和所有点赞列表移除，并回到资产库；再次公开需重新提交审核，旧点赞不会恢复。若用户仍停留在已下架作品的旧详情视图，点击点赞会收到统一“不存在/不可操作”错误；前端据此提示“作品已下架，请刷新后查看”。
- 未登录点击点赞时引导登录。已登录请求先经过服务端限流；前端禁用按钮仅用于防误触，不替代服务端校验。单作品桶容量为 4、每 3 秒恢复 1 个令牌；用户全站桶容量为 10、每秒恢复 1 个令牌。收到 `429 LIKE_RATE_LIMITED` 时按 `Retry-After` 提示稍后重试。
- 他人首次点赞当前公开周期的作品后，作者收到 `interaction.notification.created` SSE 信号；前端不从 SSE 读取点赞人或作品资料，只失效联合未读数查询。消息中心显示“互动”“官方消息”页签，当前页签打开时按需读取列表；离线、断线或重复 SSE 后均以 REST 列表和未读数校正。取消后再点赞不会重复产生互动消息，自赞不生成互动消息。
- 打开“互动”页签不自动将消息标记为已读；点击消息正文或作品缩略图时才标记单条已读。图片仍可访问时打开作者自己的图片详情；否则保留消息并显示“作品已不可用”，不跳转公共详情。
- 互动列表按游标加载且以通知 ID 去重。收到新互动消息后只请求并合并最新第一页：新消息插入已加载列表顶部，已有消息及其相对顺序、已读状态和后续游标页不被替换或重排。用户正在阅读并已离开列表顶部时，先显示“有新消息”提示，待用户点击后再插入顶部，避免视口跳动。
- 互动消息默认一直保留，只有本人手动删除才从列表消失。页签提供“管理”模式：用户可勾选一条或多条已加载消息后批量删除；单条删除和批量删除均须二次确认，取消确认不改变数据。提交成功后仅从本地已加载页移除所选项并后台刷新联合未读数，不影响点赞状态、作品计数或官方消息。单条删除沿用同一软删除语义。
- 互动页签关闭或未激活时不请求互动列表；打开后按页加载。每条可用互动消息直接携带与资产、我的发布和灵感列表一致的完整图片 DTO；点击后以该 DTO 打开详情，不为单条消息追加图片请求。仅当 DTO 的原图 URL 已过期或即将过期时，才在用户显式打开详情后调用一次既有单图资产接口刷新 DTO；刷新失败则显示“作品已不可用”。作品缩略图使用后端即时签发的短期缩略图 URL，前端以原生 `img loading="lazy"`、`decoding="async"` 和低优先级加载，固定缩略图尺寸以防布局跳动；`image` 为 `null`、缩略图 URL 为空或加载失败时显示“作品已不可用”占位，不自动循环重拉列表。缩略图 URL 仅用于该列表展示；嵌套 DTO 的原图 URL 用于详情、复制和下载，不能复用缩略图 URL。

## 3. 隐私与空态

## 图片详情组件边界

- 所有图片详情复用同一份基础内容：原图展示、下载、提示词、负向提示词、生成参数、生成时间、标题、描述和发布状态；列表入口只传入已加载的完整图片 DTO。
- 详情操作由作品生命周期和查看者关系派生，而非由资产页、发布区、消息中心等入口各自复制实现。生命周期为未发布资产、审核中、已公开、审核拒绝或失败；查看者关系为本人或他人。
- 未发布资产仅本人可见，提供收藏、发布、删除、下载和复制；复制只在此状态显示。审核中仅作者可见，提供取消审核和下载。拒绝或失败的原资产仍按资产详情展示；审核原因仅在对应官方消息列表项中展示，不在详情页重复展示。
- 已公开作品统一展示作者公开资料；本人作品提供点赞/取消点赞、撤销发布和下载，但不显示关注自己；他人作品提供点赞/取消点赞、下载、作者资料及关注关系按钮。作者资料在公开详情打开后按 `authorId` 加载，资产与审核中详情不加载作者资料。
- 官方或互动消息点击作品时只传入消息携带的完整 DTO，并按图片当前状态与查看者关系进入同一详情组件；消息列表本身不渲染缩略图或原图。图片不可用时保留消息文案并禁用查看按钮。

- “点赞列表”默认仅自己可见；作者主动公开后才对他人显示入口。切换回私密后立即隐藏入口；直接访问未公开列表时显示统一不存在状态，已加载的旧数据在下一次刷新或后台重拉后移除。
- 本人始终能查看自己的点赞列表和当前隐私状态。
- 用户没有已发布作品、没有点赞作品或主页请求失败时，保留资料区并显示对应空态或重试。

## 4. 验收条件

1. 已公开作品详情中的作者头像、昵称可进入对应作者主页；列表卡片与资产详情不展示作者入口。
2. 用户资料字段在自己与他人主页一致，均展示粉丝数、关注数和获赞数，只有权限操作不同；自己的主页也通过 `/users/[userId]` 加载。
3. 图片列表不为 `likedByCurrentUser` 触发逐图请求；灵感详情仅额外加载一次作者公开资料。关系操作成功以 `204` 为准，前端按目标状态更新后后台重拉，以服务端 DTO 校正状态与计数。
4. 未登录访问公开主页不触发用户协议确认，敏感账户字段不显示。
5. 他人首次点赞作品后，作者的互动未读数在 SSE 到达后刷新；互动列表可展示点赞人的公开资料和作品缩略图，作品下架后不再跳转公共详情。

## 已确认的详情入口复用规则

- 官方消息只在发布审核终态 `APPROVED`、`REJECTED`、`FAILED` 时创建；`PENDING` 不创建官方消息，也不发送对应的官方消息 SSE。
- 官方消息的 `APPROVED` 图片点击“查看图片”时，必须复用已发布作品详情；它与灵感列表、作者主页、点赞列表及发布区中已发布作品的详情是同一组件和同一交互规则。
- 官方消息的 `REJECTED` 或 `FAILED` 图片，只要原资产仍存在，点击后必须复用资产图片详情，布局和操作与从资产页打开完全一致。审核失败或拒绝原因只在官方消息列表项中展示，详情页不因消息入口增加专属文本、操作或布局。
- 原资产不存在或消息未携带图片时，保留消息正文，不提供查看图片入口。
- 已发布作品详情按查看者关系派生操作：本人可查看作者信息但不显示关注自己，并提供点赞/取消点赞、撤销发布和下载；他人提供点赞/取消点赞、作者资料、关注关系按钮和下载。资产详情及审核中详情不请求作者公开资料，也不展示公开互动。
