# AiVista 收藏、审核发布与官方消息模块

> 对应迭代：前端迭代 4——收藏、异步文本审核发布与官方消息
> 当前状态：设计中，待后端审核契约确认后实施

## 1. 范围

本迭代在个人资产页增加收藏筛选、发布文案提交与审核中状态、我的发布列表，以及官方消息抽屉。发布图片不产生公开副本：图片保留在私有 Bucket，后续灵感页只消费匿名接口签发的短期 URL。

资产删除与撤销发布独立。资产删除后，已发布图片仍可在后续灵感页展示；撤销发布后，资产仍可保留并可重新提交审核。

## 2. 用户流程

```text
资产页选择未发布图片
  -> 输入标题、描述并提交
  -> 显示“发布审核中”
  -> 审核通过：进入我的发布列表
  -> 审核拒绝或服务不可用：状态恢复可发布，并在官方消息中提示
```

- 仅 `publicAt` 为空且 `publicationReviewStatus = NONE` 的资产显示“发布”入口。
- `QUEUED`、`REVIEWING` 均显示“发布审核中”，禁用重复提交并提供“撤销审核”。
- `PUBLISHED` 或 `publicAt` 非空时显示“已发布”，可在我的发布中撤销。
- 已发布图片的标题和描述只读，不提供编辑入口；需要修改时先撤销发布，再重新填写并提交审核。
- 审核拒绝后保留用户提交的标题和描述，不在资产卡片展示供应商错误；用户从官方消息查看安全提示后可修改文案并再次提交。
- 审核服务连续三次不可用时，图片保持未公开并恢复可提交；保留原文案，官方消息提示用户稍后手动重新提交，前端不自动重试或自动公开。

## 3. REST 对账与模型

- 提交使用 `POST /api/generation-images/{imageId}/publication-review`，请求体为 `{"title":"...","description":"..."}`，必带 UUID v4 `Idempotency-Key`。响应 `202` 只表示进入审核队列。发布页依赖全局认证流程已确认的当前 `USER_AGREEMENT`，不再单独展示同意弹窗；协议告知标题和描述将发送至阿里云内容安全服务审核。
- 每次新提交生成新的 Idempotency-Key；同一次点击、网络重试或结果未知恢复必须复用同一 key。账号变化、退出登录或超过 10 分钟后清除本地待恢复请求。
- 资产 DTO 在本迭代增加 `publicAt` 与 `publicationReviewStatus`，前端只按后端快照展示，不推断或维护审核状态。
- 撤销使用 `DELETE /api/generation-images/{imageId}/publication`；首次和重复撤销按后端的幂等成功响应处理，成功后刷新资产和我的发布数据。
- 我的发布使用 `GET /api/my-publications?cursor=&limit=`，只返回审核通过且当前已发布图片；图片 URL 均是内存中短期使用的 10 分钟私有签名 URL，必须带过期时间，并在到期前 30 秒或图片加载失败时刷新。撤销发布后不再签发新 URL，已签发 URL 最长保留到自然到期。
- POST 成功后先写入本地 `PENDING` 快照；发布终态通过既有用户级 SSE 的 `publication.updated` 事件即时通知。SSE 断线或离线不影响后端状态，重新进入页面后以资产详情和官方消息 REST 快照对账。

## 4. 官方消息

- 消息铃铛继续使用 `GET /api/official-messages` 和既有用户级 SSE 未读数通知。
- 本迭代至少展示“发布文案未通过审核”和“发布审核服务暂不可用”两类官方消息；不展示审核供应商原始分类、对象路径、异常栈或签名 URL。
- 打开抽屉不自动已读；点击消息正文或“查看图片”才标记已读。图片已从资产删除时，查看资产返回 `404` 并展示“该图片已删除”。

## 5. 验收要点

- 同图重复点击、跨标签并发提交和网络重试不会创建多个审核任务。
- 审核中不可再次提交；撤销后迟到的通过结果不会使界面重新显示为已发布。
- 审核通过后我的发布列表出现该图片；审核拒绝或服务失败后，图片保持未公开且用户可重新提交。
- 删除资产不撤销发布；撤销发布不删除资产；前端不会将资产状态和公开状态互相推断。
- 私有签名 URL 不写入持久化存储、页面 URL、埋点或日志。
