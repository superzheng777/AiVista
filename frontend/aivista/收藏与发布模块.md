# AiVista 收藏、审核发布与官方消息模块

> 对应迭代：前端迭代 4——收藏、异步文本审核发布与官方消息
> 当前状态：设计已确认，待后端完成已确认的 DTO 与个人发布列表契约，再实施前端和联调。

## 1. 范围

本迭代在个人资产页增加收藏筛选和发布文案提交；用户在个人中心的发布区查看审核中和已发布图片，并在全局官方消息抽屉查看审核结果。发布图片不产生公开副本：图片保留在私有 Bucket，灵感页消费匿名接口签发的短期 URL。

资产删除与撤销发布独立。资产删除后，已发布图片仍可在后续灵感页展示；撤销发布后，资产仍可保留并可重新提交审核。

## 2. 用户流程

```text
资产页选择图片
  -> 输入标题、描述并提交
  -> 提示“已提交审核，可在个人中心的发布区查看”
  -> 个人中心发布区显示“审核中”或“已发布”
  -> 审核拒绝或服务不可用：官方消息提示用户回到资产页重新提交
```

- 资产页不展示发布状态。提交成功后仅提示用户到个人中心查看；页面重新进入或刷新时从后端获取最新资产快照。
- 个人中心发布区全量展示 `PENDING` 与 `APPROVED` 图片，混排为一个列表而不分区。`PENDING` 显示“审核中”，`APPROVED` 显示“已发布”；统一按提交审核时间倒序，时间相同按 `imageId` 倒序。审核通过后仅改变状态标签，不改变列表位置。
- 两类图片都只提供“删除发布”按钮。对 `PENDING`，该操作取消审核；对 `APPROVED`，该操作撤销发布。确认提示须说明不会删除资产原图。
- `REJECTED` 与 `FAILED` 不进入发布区。审核拒绝或服务失败后，用户在官方消息中查看安全提示，再回资产页修改文案并重新提交。

## 3. REST 对账与模型

- 提交使用 `POST /api/generation-images/{imageId}/publication`，请求体为 `{"title":"...","description":"..."}`，必带 UUID v4 `Idempotency-Key`。响应 `202` 只表示进入审核队列。发布页依赖全局认证流程已确认的当前 `USER_AGREEMENT`，不再单独展示同意弹窗；协议告知标题和描述将发送至阿里云内容安全服务审核。
- 每次新提交生成新的 Idempotency-Key；同一次点击、网络重试或结果未知恢复必须复用同一 key。账号变化、退出登录或超过 10 分钟后清除本地待恢复请求。
- 资产、个人发布和灵感列表的每张图片均使用同一个完整图片 DTO，不区分网格项和点击详情。DTO 包含 `imageId`、`url`、`urlExpiresAt`、`createdAt`、`finalPrompt`、`finalNegativePrompt`、`generationConfig`、`publicationReviewStatus`、`publicationVersion`、`publicAt`、`title` 和 `description`。`generationConfig` 包含 `width`、`height`、`requestedImageCount` 与 `promptExtend`。
- 资产列表使用 `GET /api/generation-images` 全量加载，不传 `cursor` 或 `limit`，也不处理 `nextCursor`；按 `createdAt DESC, imageId DESC` 显示。当前是有意取舍，资产规模增长后应重新评估首屏加载和签名 URL 签发成本。
- `null` 只表示业务值不存在，不能表示权限裁剪。资产、个人发布和灵感图片详情均展示最终正负提示词与生成配置；灵感页的作者资料、关注关系和点赞等补充信息在点击图片后另行请求。
- 删除发布使用 `DELETE /api/generation-images/{imageId}/publication`。首次和重复调用按成功处理；前端不区分取消审核和撤销发布，成功后提示“已删除发布”并直接从当前标签页的内存列表移除。其他标签页由用户手动刷新。
- 我的发布使用 `GET /api/users/me/publications`，全量、不分页，返回混排的 `PENDING` 与 `APPROVED` 图片。图片 URL 均是内存中短期使用的 10 分钟私有签名 URL，必须带过期时间；URL 到期或加载失败时重新请求当前页面的数据。
- 认证期间维持一条用户级 SSE 连接。仅审核终态发送 `publication.updated`，事件包含 `imageId`、`publicationVersion`、`status` 与 `publicAt`。资产和灵感页不自动更新；用户重新进入或刷新这些页面时再请求最新数据。个人中心发布区若正在打开，则仅合并对应图片的内存数据：低于或等于当前 `publicationVersion` 的事件直接丢弃，`APPROVED` 项仅更新状态标签，`REJECTED`、`FAILED` 项移出发布区。当前标签页删除发布后直接移除该项，不等待 SSE。不同标签页之间不自动同步，用户手动刷新后获取最新列表。该过程不重置当前标签页的列表、滚动位置或当前详情；当前详情被终态移除时保留审核结果提示，用户关闭后回到列表。SSE 同时触发官方消息未读数刷新，并在消息抽屉打开时刷新消息列表。SSE 重连成功且发布区打开时，同样在后台重新请求完整发布列表并合并，不重置页面状态。

## 4. 官方消息

- 消息铃铛使用 `GET /api/users/me/official-notifications/unread-count`；消息抽屉使用 `GET /api/users/me/official-notifications`。收到 `publication.updated` 后重新请求未读数，抽屉打开时也重新请求列表。SSE 不携带消息正文或未读数。
- 本迭代至少展示“发布文案未通过审核”和“发布审核服务暂不可用”两类官方消息；不展示审核供应商原始分类、对象路径、异常栈或签名 URL。
- 打开抽屉不自动已读；点击消息正文或“查看图片”才调用 `POST /api/users/me/official-notifications/{notificationId}/read`。图片已从资产删除时，查看资产返回 `404` 并展示“该图片已删除”。

## 5. 验收要点

- 同图重复点击、跨标签并发提交和网络重试不会创建多个审核任务。
- 审核中和已发布图片都可删除发布；迟到的审核结果不会让用户重新进入发布区。
- 审核通过后个人中心发布区出现该图片；审核拒绝或服务失败后，图片不在发布区且用户可从资产页重新提交。
- 删除资产不撤销发布；删除发布不删除资产；前端不会将资产状态和公开状态互相推断。
- 收到发布终态 SSE 后，消息角标自动更新；抽屉打开时，新消息自动出现在列表顶部。
- 个人中心发布区打开时，发布终态只更新对应图片；不会重置列表、滚动位置或阅读中的其他图片详情。
- 私有签名 URL 不写入持久化存储、页面 URL、埋点或日志。
