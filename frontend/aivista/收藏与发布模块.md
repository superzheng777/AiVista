# AiVista 收藏、审核发布与官方消息模块

> 对应迭代：前端迭代 4——收藏、异步文本审核发布与官方消息
> 当前状态：设计中（设计准入已完成，待开始编码）
> 维护规则：本文记录当前迭代的前端范围、交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

本迭代让用户从资产图片提交发布审核，在个人中心查看自己的发布结果，并通过全局官方消息获知审核终态。

- 资产页只提供发布入口，不显示发布状态。
- `/profile` 是个人中心。左侧个人资料始终显示；右侧为内容区，始终显示“我的发布”和“我赞过的图片”两个页签。迭代 4 实现前者；后者显示“功能开发中”，迭代 6 再替换为真实点赞列表。
- 发布图片不创建公开副本。图片始终在私有 Bucket，后续灵感页使用后端签发的短期 URL。
- 收藏仅保存在资产页当前内存中，不发请求、不持久化。刷新、离开资产页、退出登录或账号变化后均清空。
- 删除资产与删除发布独立。删除发布不会删除原图；删除资产后，已发布图片仍可在后续灵感页展示。

本迭代不实现灵感流、公开作品详情、点赞、关注或跨标签页自动同步。

## 2. 已确认约束

- 资产、个人发布和灵感列表共用完整图片 DTO。列表项和详情不拆成两套 DTO。
- DTO 字段为 `imageId`、`url`、`urlExpiresAt`、`createdAt`、`finalPrompt`、`finalNegativePrompt`、`generationConfig`、`publicationReviewStatus`、`publicationVersion`、`publicAt`、`title`、`description`。`generationConfig` 包含 `width`、`height`、`requestedImageCount`、`promptExtend`。
- `null` 只表示业务值不存在，不表示权限裁剪。所有图片详情都展示最终正负提示词和生成配置。
- 资产和个人发布列表均全量请求，不分页。资产按 `createdAt DESC, imageId DESC` 显示；个人发布按提交审核时间及 `imageId` 倒序显示。审核通过只改变状态，不改变该项位置。
- 个人发布列表只包含 `PENDING` 与 `APPROVED`。前者显示“审核中”，后者显示“已发布”；`REJECTED`、`FAILED` 仅通过官方消息告知。
- 删除发布对两种状态使用同一个按钮。`PENDING` 时取消审核，`APPROVED` 时撤销发布。前端统一称为“删除发布”。
- 每次新的发布提交生成新的 UUID v4 `Idempotency-Key`。同一次提交的重试、结果未知恢复复用原 key；账号变化、退出登录或超过 10 分钟后清除恢复记录。
- 签名 URL、提示词、发布文案和消息正文只保留在内存，不写入本地持久化存储、页面 URL、埋点或错误监控。

## 5. 页面、路由与交互设计

### 5.1 资产页 `/assets`

资产卡片悬停时，右上角显示收藏按钮；点击只切换当前资产页内存中的收藏状态。点击图片进入详情后，详情顶栏右侧也提供同一收藏按钮。收藏状态只使用图标、文字和 `aria-label` 共同表达，不能只用颜色区分。

资产页右上角的“批量操作”中只保留下载、收藏和删除。批量收藏根据选中项计算目标动作：全部已收藏时显示“批量取消收藏”，否则显示“批量收藏”；点击后把全部选中项设为目标状态。批量发布不属于产品范围，按钮不显示。发布仅在单张资产详情中可用。

资产详情保留图片、提示词、配置、下载、复制和删除操作，并新增“发布”按钮。点击后打开模态表单：标题为必填 `1–100` 字，描述为必填 `1–500` 字。字段下方明确说明标题和描述会发送至内容安全服务审核。

表单提交期间禁止重复提交并显示进行中反馈。成功收到 `202` 后关闭表单，显示“已提交审核，可在个人中心的我的发布查看”。网络结果未知时保留同一请求和 Idempotency-Key，以便当前标签页安全重试。`409`、验证错误或普通服务错误都保留用户输入并在表单内显示可操作的错误提示。

资产页继续不显示 `PENDING`、`APPROVED` 等发布状态，也不因发布终态 SSE 自动修改资产内存数据。

### 5.2 个人中心 `/profile`

宽屏下，左栏显示现有个人资料卡片、资料编辑和退出登录；右栏顶部显示“我的发布”“我赞过的图片”两个页签。默认打开“我的发布”，标题下显示当前发布数量和列表状态，列表为图片网格。点击图片打开详情，不跳转路由。“我赞过的图片”显示“功能开发中”，不请求数据。

窄屏下两栏按“资料、我的发布”的顺序纵向堆叠，最小点击目标不小于 44px，焦点状态保持可见。列表加载中显示骨架或等效占位；空状态显示“还没有提交发布的图片”，并提供“前往资产”入口；请求失败保留已显示数据并提供重试。

发布图片详情展示完整统一 DTO：图片、最终正负提示词、生成配置、标题、描述、提交审核时间、公开时间及状态标签。`PENDING` 和 `APPROVED` 均展示“删除发布”。删除确认说明“删除发布不会删除资产原图”；成功后关闭已删除项的详情并从内存列表移除。失败时保留列表项和详情，显示重试提示。

### 5.3 官方消息抽屉

认证用户在桌面端侧边栏底部头像上方、移动端底部导航头像左侧看到铃铛。无未读时不显示角标；有未读时用数字角标，超出两位显示 `99+`。点击后从右侧打开抽屉，焦点进入抽屉，`Escape` 和关闭按钮关闭并将焦点还给铃铛。

抽屉打开时读取消息列表。每条消息显示标题、正文、创建时间与未读状态。点击消息正文或“查看图片”标记已读；后者再读取当前资产详情并打开资产详情。资产已删除返回 `404` 时提示“该图片已删除”。抽屉不显示审核供应商原始分类、对象路径、异常栈或签名 URL。

## 6. API、前端模型与状态管理

| 目的 | 接口 | 查询键与前端行为 |
| --- | --- | --- |
| 全量资产 | `GET /api/generation-images` | 复用 `assetQueryKeys.all`。发布不修改该缓存；URL 到期或加载失败时重新请求资产快照。 |
| 提交发布 | `POST /api/generation-images/{imageId}/publication` | 请求体为 `{ title, description }`，响应为 `{ imageId, status }`，首次成功 `status` 为 `PENDING`。`publicationApi.submit` 生成或复用 Idempotency-Key；`202` 后不伪造审核完成状态。 |
| 删除发布 | `DELETE /api/generation-images/{imageId}/publication` | `publicationApi.remove` 成功后仅从当前标签页的“我的发布”缓存移除该项。 |
| 我的发布 | `GET /api/users/me/publications` | `publicationQueryKeys.mine`，全量数组，不分页。进入“我的发布”区域时读取；发布区打开且 SSE 重连成功时后台重新请求并差量合并。 |
| 消息未读数 | `GET /api/users/me/official-notifications/unread-count` | `officialNotificationQueryKeys.unreadCount`。认证成功后读取，收到发布终态后失效并重新请求。 |
| 消息列表 | `GET /api/users/me/official-notifications` | 每项为 `{ notificationId, eventType, imageId, title, content, metadata, readAt, createdAt }`。`officialNotificationQueryKeys.list`。抽屉打开时读取；抽屉已打开时收到发布终态后重新请求。 |
| 标记单条已读 | `POST /api/users/me/official-notifications/{notificationId}/read` | 成功后更新当前消息项和未读数，不等待下一次全量刷新。 |
| 发布终态 | `GET /api/events` 中的 `publication.updated` | 解析 `imageId`、`publicationVersion`、`status`、`publicAt`。版本不高于本地项时丢弃。 |

后端另提供全部已读、删除单条、清空消息接口，但本迭代不实现这些 UI 和调用。`eventType` 只按 `PUBLICATION_APPROVED`、`PUBLICATION_REJECTED`、`PUBLICATION_FAILED` 展示，拒绝消息的 `metadata.violations` 仅可用于安全地标注标题或描述字段。

在 `features/publication/` 新建 `api/`、`model/`、`ui/`。API 层将完整 DTO 映射为现有 `GenerationAsset` 领域模型；只为状态建立窄类型 `PublicationReviewStatus = "NONE" | "PENDING" | "APPROVED" | "REJECTED" | "FAILED"`，不另建重复图片模型。

现有 `GenerationEventStreamProvider` 目前仅在存在生成任务或提交生成前维持连接，也只解析 `generation.task.updated`。本迭代将它更名或拆分为通用认证事件流：认证成功后保持单条连接，统一解析生成任务和 `publication.updated`。重连成功后并行完成活跃生成任务、未读数，以及“我的发布”打开时的发布列表 REST 对账。SSE 只触发内存合并或缓存失效，REST 响应是图片和消息的权威数据。

发布接口若返回 `40903`（当前用户协议尚未确认）或 `40902`（协议版本已更新），复用生成工作台已有的用户协议读取与确认流程；确认成功后仅重试原发布请求并复用其 Idempotency-Key。

## 8. 异常场景、可靠性与安全

- `40100`、`40102` 按工程基础文档统一处理。会话进入匿名状态时清空发布、消息和资产的 Query 缓存。
- 发布提交结果未知时，不创建新 Idempotency-Key；用户可重试原提交。提交明确失败时保留表单输入。
- `PENDING` 删除发布后，迟到的审核终态不得重新加入当前发布列表。`publicationVersion` 不高于内存版本的事件直接丢弃。
- 发布区正在阅读另一项详情时，终态更新不得重置列表、滚动位置或关闭该详情。当前详情被 `REJECTED`、`FAILED` 移除时，仅保留结果提示，用户关闭后回到列表。
- 不做跨标签页消息、发布列表或图片状态同步；其他标签页由用户手动刷新。
- 全量列表请求、消息读取和图片 URL 刷新失败时，保留当前可见快照并给出重试，不清空界面。
- 模态表单、确认框和抽屉必须支持键盘操作、明确焦点管理、可见焦点样式和语义化标签；状态不只依靠颜色区分。
- 收藏不写入 Query 缓存、`sessionStorage`、`localStorage` 或 URL。资产列表重新加载后收藏状态仍清空，不尝试按 `imageId` 恢复。

## 9. 测试与验收

自动化验证：本迭代引入 Vitest 与 React Testing Library，执行 `pnpm lint`、`pnpm build` 和新增的测试脚本。至少覆盖发布表单校验、Idempotency-Key 重试、收藏单图/批量切换、发布终态合并、删除发布、未读数更新和抽屉已读行为。

真实后端验收至少覆盖：

1. 从资产详情提交发布，收到 `202` 后资产页不显示发布状态，个人中心出现“审核中”。
2. 审核通过后，已打开的个人发布列表原地变为“已发布”，不改变排序或滚动位置；未读消息角标更新。
3. 审核拒绝或服务失败后，图片从个人发布列表移除，官方消息可阅读，资产页可重新提交。
4. 对审核中和已发布图片均可执行“删除发布”，且资产原图仍存在。
5. 发布区关闭或另一个浏览器标签页打开时，不做自动列表同步；手动刷新得到后端快照。
6. 打开消息抽屉、点击消息、查看已删除图片、SSE 断线重连，以及桌面和窄屏键盘操作均符合本文约定。
