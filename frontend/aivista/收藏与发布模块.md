# AiVista 收藏与发布模块

> 对应迭代：前端迭代 4——收藏、发布与官方消息
> 当前状态：设计中
> 维护规则：本文记录当前迭代的前端范围、交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

本迭代在个人生成资产上补充收藏、收藏筛选、异步发布、我的发布列表与官方消息通知。

- 用户只能收藏自己的私有生成资产；资产页支持收藏筛选和条件式批量收藏/取消收藏。
- 用户可为自己的单张图片填写标题和描述后提交发布；发布完成后获得稳定的公开 OSS 图片直链。
- 发布表单与资产详情展示该图所属任务的最终正向、负向提示词；负向提示词为空时不显示该区块。
- 发布失败时，通过全局官方消息通知用户。
- 前端不感知 Outbox 表结构。后端将其重构为项目级通用可靠事件表：生成任务执行、发布执行、官方消息和 SSE 通知使用不同事件类型和各自投递器；REST 快照始终是页面状态的权威来源。

本迭代不实现公开社区列表、公开作品详情、公开提示词浏览、他人主页、点赞、关注、推荐或互动消息。公开作品流和作品详情属于迭代 5；互动消息随点赞迭代实现。

## 2. 已确认业务边界

| 主题 | 已确认规则 |
| --- | --- |
| 收藏 | 收藏是资产所有者的个人布尔标记；资产页通过同一资产列表接口的 `filter=all|favorited` 参数进行服务端筛选和游标分页。收藏不记录时间或备注，也不支持跨用户收藏；每种筛选条件独立维护已加载数据与游标，切换筛选时从该条件第一页重新加载。 |
| 发布请求幂等 | 每次发布在请求前生成 UUID v4 `Idempotency-Key`；同一次点击、结果未知的网络重试和刷新恢复均复用同一 key。请求内容变化时生成新 key。 |
| 公开副本 | 发布时由后端复制私有快照至独立公开作品 OSS bucket；公开 URL 由公开对象键与部署基础域名动态拼出，不覆盖私有资产 URL。当前不接 CDN。 |
| 公开链接失效 | 用户从我的发布列表删除已发布作品时，发布记录立即从业务查询消失，后端异步删除公开 OSS 对象；未来接入 CDN 时才增加缓存刷新。 |
| 生成配置读取 | 前端不提交或改写提示词；作品详情经发布记录的 `source_task_id` 读取任务中不可变的最终提示词和用户可见生成配置。 |
| 发布表单 | 标题必填、1–100 个字符且默认留空；作品描述可选、最多 500 个字符；提交表单即确认公开图片与关联不可变来源任务。当前不实现“添加挑战”。 |
| 单图发布 | 一张图片存在处理中或已发布记录时，不可再次发起发布，资产详情再次点击发布时提示当前状态。用户从我的发布列表删除已发布作品后，若私有资产仍存在，可再次发起一条全新的发布。 |
| 删除边界 | 删除私有资产不影响处理中或已发布作品。我的发布列表允许删除处理中或已发布作品；删除发布记录及其发布快照，已发布时另删除公开副本，不删除私有资产。 |
| 公开访问范围 | 迭代 4 仅提供公开图片直链；公开社区与详情排期至迭代 5，但已确定使用独立的 `GET /api/publications/{publicationId}`。标题、描述保存在发布记录，提示词与生成配置从来源任务读取。 |

## 3. 页面与交互设计

### 3.1 资产页

- 卡片和详情提供单张收藏操作；收藏筛选与当前资产分页、私有签名 URL 刷新机制兼容。
- 批量管理包含下载、删除和条件式收藏操作，不提供批量发布：选中项全部已收藏时显示“取消收藏”；只要包含未收藏项则显示“收藏”，只标记未收藏项，已收藏项保持不变。收藏与取消收藏均立即执行，不需要二次确认。用户可先筛选“已收藏”再进行批量操作。
- 私有资产列表和详情保持资产管理视图，不展示图片是否处理中或已发布，也不承载公开作品信息。
- “我的发布列表”是独立的公开作品视图，展示处理中和已发布作品；“删除发布作品”是唯一的撤销发布操作，处理中和已发布作品均可执行且不影响私有资产。删除后，若私有资产仍存在，用户可重新发起一条新的发布。
- 我的发布作品详情展示作者、标题、描述、发布时间、公开作品信息和创作操作；它与后续灵感作品详情复用公开作品展示模型，但不显示“关注”按钮。灵感作品属于其他用户，才显示作者关注入口。
- 迭代 4 的发布作品详情提供“做同款”：打开生成工作台并预填来源任务中的最终提示词和生成配置，用户确认后才创建新任务。“用作参考图”依赖图生图输入能力，不在本迭代实现。
- 删除私有资产只删除私有资产本身，不根据发布状态改变发布记录、异步发布流程或公开副本；资产页也不展示发布状态与发布删除影响。

### 3.2 发布表单

- 从资产详情打开，左侧预览待发布图片，右侧填写标题和作品描述，并展示正向提示词及非空的负向提示词。
- 发布标题和描述默认留空；发布失败后再次打开仍不带入失败内容。
- 提交成功仅表示后端已接收请求：前端立即以响应快照显示“发布处理中”，而非显示已发布。
- 用户刷新我的发布列表时，以后端发布状态覆盖本地展示：`QUEUED` 与 `PROCESSING` 均持续显示“发布处理中”；`PUBLISHED` 才显示公开链接；失败不显示在发布记录列表中。
- 若发布工作器异常，后端在记录处于 `PROCESSING` 且连续 3 分钟未更新后自动重新排队；前端始终继续展示“发布处理中”，不自行判断或发起重试。
- 一条发布记录最多执行 3 次（首次计入）；复制失败和工作器执行超时共用这一次数。前端持续展示“发布处理中”，仅在第三次仍失败后的终态通过官方消息展示原因。
- 后端收到复制明确失败时，分别在 4 秒和 8 秒后安排下一次执行；这不改变前端的“发布处理中”展示，也不要求前端发起重试。

### 3.3 全局官方消息

- 登录后的左侧导航栏提供消息铃铛；点击后以抽屉展示官方消息。
- 本迭代只实现官方消息。发布失败时，显示关联图片、后端提供的用户可理解失败说明和发生时间；不展示存储路径或原始服务端错误。
- 删除已发布作品不创建官方消息；消息中心仅承载发布失败。
- 打开抽屉不自动标记已读；点击单条消息才将该条标记已读。支持全部已读、单条改回未读、单条清除和全部清除；点击消息正文或“查看作品”均标记已读。
- 铃铛显示未读消息数量；超过 99 条时显示 `99+`。已读消息仍保留，只有用户点击清除后才从消息列表删除。
- 消息按创建时间倒序全量展示；前端以虚拟列表控制渲染数量，不设置自动清理期限。
- 全部清除前必须二次确认，明确会将全部官方消息从用户消息列表中永久移除且无法恢复；单条清除不影响其他消息。
- 官方消息 REST 列表仅返回可空关联 `imageId`，不拼接资产快照或私有签名 URL。
- 点击消息本体仅标记该条已读；点击“查看作品”也标记已读、关闭消息抽屉，并请求 `GET /api/generation-images/{imageId}`。资产仍存在时，该接口返回与资产列表单项相同的 DTO，前端以资产页同一详情组件展示，并提供一致的收藏、发布、下载和删除操作。
- 资产详情请求返回 `404` 时，前端显示“该图片已删除”；不展示详情。没有关联 `imageId` 的消息不显示“查看作品”操作。

## 4. 前端状态与 REST 对账

- 发布状态本身不使用 SSE。POST 接收成功后写入本地“发布处理中”快照；进入我的发布列表、手动刷新或重新获取发布数据时，以 REST 返回的发布状态为准。处理中私有快照 URL 与资产页一致，使用 10 分钟签名、最早到期前 30 秒刷新和图片加载失败刷新。
- 官方消息通过认证后的用户级 SSE 实时推送；它与生成任务状态事件复用同一条标签页生命周期连接。新消息事件携带完整安全通知内容、可空 `imageId` 和未读数量，但不携带资产快照、私有签名 URL 或内部存储字段；抽屉打开时刷新官方消息 REST 列表。REST 快照仍是权威来源。
- 收到新官方消息事件时，若消息抽屉已打开则立即刷新并展示新消息；抽屉关闭时只更新未读数量。
- 标签页不可见时不主动断开 SSE；浏览器或系统挂起、网络恢复或页面重新可见后，重新建立连接并对账活跃任务和未读消息。
- 用户级 SSE 连续 3 次连接失败后，全局导航栏显示非阻塞“实时更新连接已断开”提示和“重新连接”操作。
- 点击“重新连接”开启新一轮最多 3 次连接尝试。消息读写或清除后，后端向同一用户的其他标签页推送未读数量变化并同步更新。
- `QUEUED`、`PROCESSING` 均映射为“发布处理中”；成功与失败必须区分展示，不能将失败误判为已发布。
- 收藏、发布、删除和消息读写成功后，更新受影响缓存；不为私有资产删除或当前筛选内的状态变化重置资产游标。不同资产筛选条件之间不手动插入数据，用户切换筛选时从服务端重新获取该条件的第一页。
- 发布请求发送前在 `sessionStorage` 暂存当前用户、请求体、本地内容指纹、`Idempotency-Key` 和创建时间；结果未知时保留并复用，成功或明确业务错误后清除，账号变化、退出登录或超过 10 分钟时清除。
- 全部已读和全部清除由后端对当前用户全部符合条件的消息执行更新；成功后前端重新请求完整消息列表。
- 批量删除沿用现有逻辑删除模型：接口维持幂等空成功响应，命中的当前可见资产立即从列表移除，私有原图和公开副本由可重试后台清理流程处理；不新增逐项删除结果响应。
- 删除私有资产继续使用 `POST /api/generation-images/delete` 与 `{"imageIds":["101","102"]}` 请求体；它不读取或改变发布状态。已发布作品仅在我的发布列表中通过独立删除操作移除。
- 前端只消费后端返回的私有签名 URL 或公开 URL；不得推断对象路径、拼接私有 URL 或在浏览器持久化私有签名 URL。

## 5. API 与前端模型约束

- 发布请求仅提交图片 ID、标题和可选描述；最终提示词与生成配置由后端从图片所属不可变任务读取，发布记录只保存 `source_task_id`，不冗余写入图片快照。发布 ID、图片 ID、任务 ID 和用户 ID 均由后端以字符串返回；内部 `publicationToken`、对象键、版本和失败码不进入前端模型。
- 每次新的发布操作生成 UUID `Idempotency-Key`；同一次点击及其网络重试复用该值，以取得同一发布记录而不重复提交。
- 发布使用 `POST /api/generation-images/{imageId}/publications`，请求体为 `{"title":"...","description":"..."}`；标题去除首尾空白后为 1–100 个字符、描述最多 500 个字符。首次受理响应为 `202`，安全快照包含发布 ID、`QUEUED` 与创建时间，前端展示为“发布处理中”。相同 key 和相同请求内容返回首次响应；相同 key 与不同内容返回 `409 IDEMPOTENCY_KEY_CONFLICT`；不同 key 在排队或处理中返回 `409 PUBLICATION_IN_PROGRESS`，已发布返回 `409 IMAGE_ALREADY_PUBLISHED`，参数或 UUID 不合法返回 `422`。资产页只提示，不常驻展示发布状态；响应不含对象键、签名 URL、失败原因或内部状态。
- 排队、处理中和已发布作品均使用 `DELETE /api/publications/{publicationId}` 删除发布作品，无请求体和 `Idempotency-Key`。首次删除与本人重复删除均返回 `204`；不存在、非本人或无权访问返回 `404`。首次删除软删除发布记录并安排私有快照清理；已发布时另清理公开副本，不删除私有资产。删除后资产的内部发布状态回退为可发布。
- 若另一标签页已提交同图发布请求，后端拒绝新的不同幂等键请求；前端仅提示“该图片正在发布处理中”。
- 资产列表使用既有 `GET /api/generation-images`，新增可选 `filter=all|favorited` 参数，缺省为 `all`；服务端先按当前用户、未删除状态与筛选条件过滤，再沿用 `created_at DESC, id DESC` 和现有 `cursor`、`limit` 规则分页。不同 `filter` 的游标不得混用。
- 我的发布列表使用 `GET /api/my-publications?cursor=<opaque>&limit=30`，默认 `30`、最大 `60`，按发布记录创建时间倒序并使用不透明游标；从 `image_publications` 查询当前用户的 `QUEUED`、`PROCESSING` 和 `PUBLISHED` 记录，前两者展示为“发布处理中”。当前作者的 ID、昵称与头像在响应顶层只返回一次，列表项不重复作者信息；作者资料更新后重新查询即可同步。每个列表项均为完整作品详情快照，用户点击作品时直接复用该数据渲染，不额外请求详情接口。
- 处理中作品的 `imageUrl` 是发布记录专属私有图片快照的短期签名 URL，返回 `imageUrlExpiresAt`；已发布作品的 `imageUrl` 是稳定公开 URL，`imageUrlExpiresAt` 为 `null`。私有签名 URL 只在前端内存使用，不写入持久化存储、页面 URL、埋点或日志。
- 同一发布的公开副本在后端固定写入预分配对象键；工作器重试只会覆盖同一对象。前端仅在后端快照状态为 `PUBLISHED` 时展示公开 URL。
- 每个发布作品快照返回实际生成时使用的配置：`model`、`promptExtend`、`imageCount`（生成任务的 `n`）、`aspectRatio`、`width` 和 `height`。不返回服务商原始参数、内部重试字段或密钥。
- 每个发布作品快照返回 `author.userId`、当前昵称与当前头像地址；作者信息随用户资料变更实时更新。我的发布详情不显示关注操作；后续灵感详情根据 `author.userId` 不是当前用户才显示关注入口。
- 单图和批量收藏分别共用 `POST /api/generation-images/favorite` 与 `POST /api/generation-images/unfavorite`，请求体均为 `{"imageIds":["101","102"]}`。`imageIds` 非空且不得重复；单图传一个 ID。两接口均幂等并返回空 `data`：他人、不存在或已删除图片不产生影响且按成功处理。批量操作在全部选中项已收藏时调用取消收藏；否则调用收藏，已收藏项重复收藏不报错。
- 资产查询只需返回 `favorited` 状态和私有资产展示字段；失败/拒绝原因通过官方消息接口返回，而非混入私有资产列表。
- 官方消息数据至少需包含消息 ID、类型、关联图片、内容、创建时间和已读状态；前端 ID 一律按字符串处理。
- 官方消息列表使用无查询参数的 `GET /api/official-messages`，按创建时间倒序返回当前用户全部未清除消息 `items` 与当前用户全量 `unreadCount`，不使用游标、`limit`、`nextCursor`、单条详情或搜索。每项包含消息 ID、事件类型、标题、安全内容、可空 `imageId`、创建时间与可空已读时间；不包含资产快照或签名 URL。
- 全部已读和全部清除分别使用 `POST /api/official-messages/read-all` 与 `POST /api/official-messages/clear-all`，均不携带游标；成功以 `200` 返回操作完成后的实际全量 `{"unreadCount": n}`，不返回删除条数。操作完成后新到达的消息不受影响。
- 单条读写使用 `PATCH /api/official-messages/{messageId}` 与 `{"read":true|false}`，单条清除使用 `DELETE /api/official-messages/{messageId}`；三者均以 `200` 返回操作完成后的实际全量 `{"unreadCount": n}`。前端不使用切换式接口，以保证重复请求的幂等性。
- 具体响应 DTO 与幂等契约在后端接口设计确认后补充，不得由前端自行假设。

## 6. 异常场景与验收要点

- 发布参数或 UUID 不合法时就地展示 `422` 校验信息；`409 IDEMPOTENCY_KEY_CONFLICT` 清除该次待恢复请求并提示重新发起，`409 PUBLICATION_IN_PROGRESS` 提示正在发布，`409 IMAGE_ALREADY_PUBLISHED` 引导查看我的发布。`503 PUBLICATION_SNAPSHOT_UNAVAILABLE` 保留原请求与幂等键以允许重试，不展示发布处理中。删除发布遇 `404` 时刷新我的发布列表；官方消息查看作品遇 `404` 时显示“该图片已删除”。
- 认证继续遵循工程基础约定：HTTP `401` 的业务码 `40100` 由全局拦截器刷新 Access Token 并重放原请求，`40102` 才清理会话；网络和 `5xx` 错误不判定用户退出登录。
- 发布请求被接收后刷新页面，仍能从后端快照恢复“发布处理中”。
- 发布成功后在我的发布列表显示公开链接。
- 发布失败不会占据发布记录列表，但会产生未读官方消息；阅读、全部已读、改未读和清除均正确更新未读数量与抽屉。
- 删除私有资产后，私有资产不再展示，但处理中作品仍可完成发布并获得公开 URL，已发布作品保持原状态；删除已发布作品后，仅该发布作品不再展示，私有资产保持不变。
- 公开社区、详情、他人主页及互动消息不因本迭代接口或组件而被提前实现。
- 批量发布不在当前迭代范围内，留待后续单独设计逐图标题、描述与发布队列交互。
- 最低验收覆盖：同键重试与冲突提示、同图并发提示、撤销后重新发布、发布失败与官方消息、对象清理后的状态收敛、消息全量读取与跨标签未读数同步、消息按需查看仍存在或已删除的资产，以及 `40100`、`40102`、网络和 `5xx` 认证边界。

### 7.1 已确认设计决策（2026-08-07）

- “删除发布作品”是撤销该发布，不删除私有资产；删除处理中发布后停止后续发布，删除已发布作品后撤销公开副本。私有资产仍存在时，用户可发起新的发布操作。
- 收藏、取消收藏和私有资产删除仅影响当前用户自己的未删除资产；前端将他人、不存在或已删除图片导致的幂等成功视为正常完成。发布删除遇 `404` 时按“作品已不存在或无权访问”处理，不泄露资源归属。
- 每次新的发布意图生成 UUID v4 `Idempotency-Key`；同一次点击、网络重试或结果未知恢复必须复用该键。前端禁用操作仅改善体验，服务端响应是并发与幂等的唯一事实来源。
- `QUEUED` 与 `PROCESSING` 均显示为“发布处理中”，`PUBLISHED` 与 `FAILED` 必须明确区分。发布状态通过 REST 对账；SSE 不承载发布状态，仅用于发布失败官方消息及未读数变化。失败消息只显示用户可理解的说明，不展示内部错误或存储信息。
- 发布受理完成后，前端只消费后端返回的发布专属图片快照：处理中使用短期私有签名 URL，已发布使用公开 URL。用户删除私有资产不应中断已受理发布；撤销发布后，前端移除对应发布项。私有签名 URL 只在内存中使用，禁止持久化、放入页面 URL、日志或埋点；临近过期或加载失败时按既有机制重新查询权威快照。
- 资产的 `publication_state`、`current_publication_id` 与 `publication_version` 是后端内部并发控制字段，不返回资产 DTO、不在资产页展示，也不由前端推断或维护。前端仅以发布列表和 REST 快照中返回的发布状态为准。
- 官方消息抽屉通过全量 `GET /api/official-messages` 读取数据，按创建时间倒序用虚拟列表渲染；打开抽屉、抽屉打开时收到新消息、读写或清除成功后重新请求完整列表，不做轮询。点击“查看作品”才按 `imageId` 请求当前资产详情；成功时复用资产详情组件，`404` 时显示“该图片已删除”。
- 打开抽屉不自动设为已读；点击消息正文或“查看作品”才调用 `PATCH {"read": true}`。单条读写使用显式目标状态，单条清除只移除该消息；全部已读和全部清除作用于当前用户全部消息，全部清除要求二次确认且不影响关联发布或资产。每次操作响应的 `unreadCount` 更新当前标签页；用户级 SSE 让同账号其他已连接标签页同步铃铛数字，抽屉已打开时重新请求完整列表。SSE 事件不含私有签名 URL、资产快照或内部错误。
- 消息不自动过期，已读消息保留到用户主动清除为止。单条清除和全部清除在服务端均为软删除，对用户不可恢复；列表和未读数排除已清除消息。全部清除不展示或依赖删除条数，只使用响应的最新 `unreadCount` 后重新获取完整列表；清除不影响关联图片、发布或失败记录。
