# AiVista 收藏、审核发布与官方消息模块

> 对应迭代：前端迭代 4——收藏、异步文本审核发布与官方消息
> 当前状态：已完成（实现与真实后端联调验收通过）
> 维护规则：本文记录当前迭代的前端范围、交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

本迭代让用户从资产图片提交发布审核，在个人中心查看自己的发布结果，并通过全局官方消息获知审核终态。

- 资产页只提供发布入口，不显示发布状态。
- `/profile` 是个人中心。左侧个人资料始终显示；右侧为发布区，展示“审核中”与“已发布”图片。
- 发布图片不创建公开副本。图片始终在私有 Bucket，后续灵感页使用后端签发的短期 URL。
- 资产收藏已持久化在图片自身的 `isFavorited` 字段；支持单图和批量收藏/取消收藏，不增加“只看收藏”筛选。
- 删除资产与删除发布独立。删除发布不会删除原图；删除资产后，已发布图片仍可在后续灵感页展示。

本迭代不实现灵感流、公开作品详情、点赞、关注或跨标签页自动同步。

## 2. 已确认约束

- 资产、个人发布和公开作品共用统一图片 DTO。列表与详情字段不拆成两套 DTO，但 URL 按用途裁剪。
- DTO 字段为 `imageId`、`imageUrls`、`createdAt`、`favorited`、`finalPrompt`、`finalNegativePrompt`、`generationConfig`、`publicationReviewStatus`、`publicationVersion`、`publicAt`、`title`、`description`。`imageUrls` 固定含 `thumbnail`、`display`、`original`；列表只有 `thumbnail`，单图详情取得三种 URL。`generationConfig` 包含 `width`、`height`、`requestedImageCount`、`promptExtend`。
- `null` 只表示业务值不存在，不表示权限裁剪。所有图片详情都展示最终正负提示词和生成配置。
- 资产和个人发布列表均全量请求，不分页。资产按 `createdAt DESC, imageId DESC` 显示；个人发布按提交审核时间及 `imageId` 倒序显示。审核通过只改变状态，不改变该项位置。
- 个人发布列表只包含 `PENDING` 与 `APPROVED`。前者显示“审核中”，后者显示“已发布”；`REJECTED`、`FAILED` 仅通过官方消息告知。
- 删除发布对两种状态使用同一个按钮。`PENDING` 时取消审核，`APPROVED` 时撤销发布。前端统一称为“删除发布”。
- 发布审核以图片的 `publicationReviewStatus` 为唯一防重依据：`PENDING` 时再次提交直接返回 `202 PENDING`，不会创建第二个审核任务；`APPROVED` 时必须先撤销发布。
- 签名 URL、提示词、发布文案和消息正文只保留在内存，不写入本地持久化存储、页面 URL、埋点或错误监控。

## 5. 页面、路由与交互设计

### 5.1 资产页 `/assets`

资产页右上角的“批量操作”中提供下载、删除和收藏。所选图片中只要有一张未收藏，操作显示“批量收藏”并将全部选中项设为收藏；全部已收藏时显示“取消收藏”并将全部选中项设为未收藏。发布仍仅在单张资产详情中可用。

资产详情保留图片、提示词、配置、下载、复制和删除操作，并新增“发布”按钮。点击后打开模态表单：标题为必填 `1–100` 字，描述为必填 `1–500` 字。字段下方明确说明标题和描述会发送至内容安全服务审核。

表单提交期间禁止重复提交并显示进行中反馈。成功收到 `202 PENDING` 后关闭表单，立即将详情对象与资产缓存的发布状态同步为 `PENDING`，再显示“已提交审核，可在个人中心的发布区查看”。资产 DTO 为 `PENDING` 时，前端不打开表单而提示“该图片正在审核中”；为 `APPROVED` 时提示先撤销发布。若前端快照过期或响应丢失，后端仍会对 `PENDING` 返回 `202 PENDING`，且不会创建第二个审核任务。验证与其他业务错误均保留输入并显示后端返回的安全业务文案；网络错误显示网络重试提示。

资产页不展示完整发布状态标签，也不因发布终态 SSE 自动修改资产内存数据；但再次进入详情并点击发布时，会依据最新 DTO 做上述操作预检。

### 5.2 个人中心 `/profile`

宽屏下，左栏显示个人资料卡片、资料编辑和退出登录；右栏为发布区，默认展示发布网格，标题下显示当前发布数量和列表状态。点击已审核通过的公开作品以当前个人页为背景打开本地公开详情覆盖层，并用 History API 更新为 `/inspirations?imageId={imageId}`；点击审核中作品仍在页内打开详情，不改变 URL。

窄屏下两栏按“资料、发布区”的顺序纵向堆叠，最小点击目标不小于 44px，焦点状态保持可见。列表加载中显示骨架或等效占位；空状态显示“还没有发布记录”，并提供“回到资产页”入口；请求失败保留已显示数据并提供重试。

发布图片详情展示完整统一 DTO：图片、最终正负提示词、生成配置、标题、描述、提交审核时间、公开时间及状态标签。`PENDING` 和 `APPROVED` 均展示“删除发布”。删除确认说明“删除发布不会删除资产原图”；成功后关闭已删除项的详情并从内存列表移除。失败时保留列表项和详情，显示重试提示。

### 5.3 官方消息抽屉

认证用户在桌面端侧边栏底部、移动端底部导航看到铃铛。无未读时不显示角标；有未读时用数字角标，超出两位显示 `99+`。点击后从左侧打开抽屉，桌面端紧贴侧边栏右侧展开，移动端占满屏宽。

抽屉打开时读取消息列表。每条消息显示标题、正文、创建时间与未读状态。点击消息正文或“查看图片”标记已读；关联已审核通过的公开作品以消息页面为背景打开本地公开详情覆盖层，并用 History API 更新为 `/inspirations?imageId={imageId}`，拒绝或失败作品仍调用 `GET /generation-images/{imageId}` 读取私有资产详情。抽屉支持全部标记已读、单条删除和二次确认后的清空。图片资源不存在（未发布且资产已删除）返回 `404` 时提示“该图片已删除”。抽屉不显示审核供应商原始分类、对象路径、异常栈或签名 URL。

## 6. API、前端模型与状态管理

| 目的 | 接口 | 查询键与前端行为 |
| --- | --- | --- |
| 全量资产 | `GET /api/generation-images` | 复用 `assetQueryKeys.all`。发布不修改该缓存；URL 到期或加载失败时重新请求资产快照。 |
| 单图详情 | `GET /api/generation-images/{imageId}` | 按资源存活性返回：资产页未删除，或已发布（`public_at` 非空）即返回图片；未发布且资产已删除时返回 `40401`。官方消息“查看图片”统一走此接口。 |
| 设置收藏 | `POST /api/generation-images/favorites` | 请求体为 `{ imageIds: string[], favorite: boolean }`，将单图或多张图片设为目标收藏状态；重复设置成功，资产缓存和详情内存对象乐观更新并在失败时回滚。 |
| 提交发布 | `POST /api/generation-images/{imageId}/publication` | 请求体为 `{ title, description }`，响应为 `{ imageId, status }`。图片处于可提交状态时创建审核并返回 `202 PENDING`；已处于 `PENDING` 时也返回 `202 PENDING`，但不重复创建审核；`202` 后不伪造审核完成状态。 |
| 删除发布 | `DELETE /api/generation-images/{imageId}/publication` | `removePublication` 成功后仅从当前标签页的“我的发布”缓存移除该项。 |
| 我的发布 | `GET /api/users/me/publications` | `publicationQueryKeys.mine`，全量数组，不分页。进入发布区时读取；发布区打开且 SSE 重连成功时后台重新请求并差量合并。 |
| 消息未读数 | `GET /api/users/me/notifications/unread-count` | 返回官方、互动及总未读数。认证成功后读取，收到发布终态或互动消息 SSE 后失效并重新请求。 |
| 消息列表 | `GET /api/users/me/official-notifications` | 每项为 `{ notificationId, eventType, imageId, title, content, metadata, readAt, createdAt }`。`officialNotificationQueryKeys.list`。抽屉打开时读取；抽屉已打开时收到发布终态后重新请求。 |
| 标记单条已读 | `POST /api/users/me/official-notifications/{notificationId}/read` | 成功后更新当前消息项和未读数，不等待下一次全量刷新。 |
| 全部已读/删除消息 | `POST /api/users/me/official-notifications/read-all`、`DELETE /api/users/me/official-notifications/{notificationId}`、`DELETE /api/users/me/official-notifications` | 分别更新当前抽屉缓存和未读数；清空前要求确认。 |
| 发布终态 | `GET /api/events` 中的 `publication.updated` | 解析 `imageId`、`publicationVersion`、`status`、`publicAt`。版本不高于本地项时丢弃。 |

`eventType` 只按 `PUBLICATION_APPROVED`、`PUBLICATION_REJECTED`、`PUBLICATION_FAILED` 展示，拒绝消息的 `metadata.violations` 仅可用于安全地标注标题或描述字段。

在 `features/publication/` 新建 `api/`、`model/`、`ui/`。API 层将完整 DTO 映射为现有 `GenerationAsset` 领域模型；只为状态建立窄类型 `PublicationReviewStatus = "NONE" | "PENDING" | "APPROVED" | "REJECTED" | "FAILED"`，不另建重复图片模型。

现有 `GenerationEventStreamProvider` 改造为认证驱动持续连接：认证成功后保持单条连接，统一解析生成任务和 `publication.updated`；重连成功后并行完成活跃生成任务、未读数，以及发布区打开时的发布列表 REST 对账。SSE 只触发内存合并或缓存失效，REST 响应是图片和消息的权威数据。

发布接口若返回 `40903`（当前用户协议尚未确认）或 `40902`（协议版本已更新），复用共享的用户协议读取与确认流程；确认成功后重试原发布请求。

## 8. 异常场景、可靠性与安全

- `40100`、`40102` 按工程基础文档统一处理。会话进入匿名状态时清空发布、消息和资产的 Query 缓存。
- 发布提交结果未知时，用户再次提交同一图片会由服务端的 `PENDING` 状态返回原始的 `202 PENDING`；提交明确失败时保留表单输入。
- `PENDING` 删除发布后，迟到的审核终态不得重新加入当前发布列表。`publicationVersion` 不高于内存版本的事件直接丢弃。
- 发布区正在阅读另一项详情时，终态更新不得重置列表、滚动位置或关闭该详情。当前详情被 `REJECTED`、`FAILED` 移除时，仅保留结果提示，用户关闭后回到列表。
- 不做跨标签页消息、发布列表或图片状态同步；其他标签页由用户手动刷新。
- 全量列表请求、消息读取和图片 URL 刷新失败时，保留当前可见快照并给出重试，不清空界面。
- 模态表单、确认框和抽屉已使用可访问 Dialog：支持 Escape、焦点进入、焦点约束和关闭后的焦点回归，并保留可见焦点样式和语义化标签；状态不只依靠颜色区分。
- 私有签名 URL 不写入持久化存储、页面 URL、埋点或日志。

## 9. 测试与验收

自动化验证：本迭代引入 Vitest 与 React Testing Library，执行 `pnpm test`、`pnpm build`。当前 51 项测试覆盖 SSE 事件解析、消息文案映射、三用途图片 DTO 展开与资产/发布/官方消息/协议 API mapper。

真实后端验收已通过：

1. 从资产详情提交发布，收到 `202` 后资产页不显示发布状态，个人中心发布区出现“审核中”/“已发布”。
2. 审核通过后，已打开的发布列表原地变为“已发布”（SSE 信号→全量重拉），不改变排序或滚动位置；未读消息角标更新。
3. 审核拒绝或服务失败后，图片从发布区移除，官方消息可阅读，资产页可重新提交。
4. 对审核中和已发布图片均可执行“删除发布”，且资产原图仍存在。
5. 发布区关闭或另一个浏览器标签页打开时，不做自动列表同步；手动刷新得到后端快照。
6. 打开消息抽屉、点击消息、查看图片（含资产已删的“该图片已删除”）、SSE 断线自动重连，以及桌面和窄屏键盘操作均符合本文约定。
