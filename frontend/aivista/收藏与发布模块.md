# AiVista 收藏与发布模块

> 对应迭代：前端迭代 4——收藏、发布与官方消息
> 当前状态：设计中
> 维护规则：本文记录当前迭代的前端范围、交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

本迭代在个人生成资产上补充收藏、收藏筛选、异步发布、撤销发布与官方消息通知。

- 用户只能收藏自己的私有生成资产；资产页支持收藏筛选和条件式批量收藏/取消收藏。
- 用户可为自己的单张图片填写标题和描述后提交发布；发布完成后获得稳定的公开 OSS 图片直链。
- 发布表单与资产详情展示该图所属任务的最终正向、负向提示词；负向提示词为空时不显示该区块。
- 发布失败或未来审核拒绝时，通过全局官方消息通知用户。

本迭代不实现公开社区列表、公开作品详情、公开提示词浏览、他人主页、点赞、关注、推荐或互动消息。公开作品流和作品详情属于迭代 5；互动消息随点赞迭代实现。

## 2. 已确认业务边界

| 主题 | 已确认规则 |
| --- | --- |
| 收藏 | 收藏是资产所有者的个人标记；资产页支持“全部/已收藏”筛选，切换筛选时重置游标并按现有排序重新加载。 |
| 公开副本 | 发布时由后端复制私有原图为独立公开 OSS 副本；公开 URL 直接指向该副本，不覆盖私有资产 URL。 |
| 公开链接失效 | 公开副本使用禁止或极短缓存策略；撤销、替换或删除时由后端刷新 CDN 缓存，尽量使旧直链立即失效。 |
| 提示词快照 | 后端从任务的 `final_prompt` 与 `final_negative_prompt` 创建不可变快照；前端不提交或改写提示词。该值是项目提交给模型的最终输入，不声称为模型智能改写后的文本。 |
| 发布表单 | 标题必填、最多 20 个字符且默认留空；作品描述可选、最多 500 个字符；提交表单即确认公开图片与保存提示词快照。当前不实现“添加挑战”。 |
| 单图发布 | 一张图片最多有一条已发布记录；存在审核中或已发布记录时，不可再次发起发布。撤销后可再次发布，且生成新的公开副本和新链接。 |
| 重新发布 | 表单可编辑草稿，但已发布记录不可直接编辑。重新发布创建新审核记录；旧链接保持可用，待新记录发布成功后才撤销旧记录并切换到新链接。 |
| 删除已发布资产 | 删除前明确提示“该图片已公开；删除将同步撤销已公布图片”。确认后后端撤销公开副本并删除私有原图。 |
| 公开访问范围 | 迭代 4 仅提供公开图片直链；不新增公开元数据读取接口。标题、描述和提示词快照保存给迭代 5 的公开详情使用。 |

## 3. 页面与交互设计

### 3.1 资产页

- 卡片和详情提供单张收藏操作；收藏筛选与当前资产分页、私有签名 URL 刷新机制兼容。
- 批量管理包含下载、删除和条件式收藏操作，不提供批量发布：选中项全部已收藏时显示“取消收藏”；只要包含未收藏项则显示“收藏”，只标记未收藏项，已收藏项保持不变。收藏与取消收藏均立即执行，不需要二次确认。用户可先筛选“已收藏”再进行批量操作。
- 单张图片的详情展示发布记录区域：审核中或已发布时可见；不展示撤销、失败或拒绝的历史记录。
- 已发布记录展示标题、描述、发布时间、公开链接和撤销操作；审核中显示“审核中”并禁用再次发布。
- 重新发布审核期间，用户侧仅看到该图片“审核中”，不展示旧发布记录，也不能撤销或再次发布；其他用户仍可通过旧公开链接访问图片。重新发布失败或被拒绝后，恢复原“已发布”状态与撤销操作。
- 删除已发布图片必须在确认对话框中说明同步撤销的影响。
- 批量删除混合选中普通、已发布和审核中图片时，确认对话框汇总各类数量，并说明会分别删除私有原图、撤销公开副本和取消审核请求。
- 审核中记录支持主动撤回，不必删除图片；撤回后可立即重新打开发布表单。审核中图片删除前也需确认，并会取消审核请求后再删除图片。

### 3.2 发布与重新发布表单

- 从资产详情打开，左侧预览待发布图片，右侧填写标题和作品描述，并展示正向提示词及非空的负向提示词。
- 首次发布标题和描述留空；首次发布失败后再次打开仍不带入失败内容。重新发布默认带入当前已发布标题和描述，供用户修改后提交。
- 提交成功仅表示后端已接收请求：前端立即以响应快照显示“审核中”，而非显示已发布。
- 用户刷新资产数据时，以后端发布状态覆盖本地展示：非终态持续显示“审核中”；`PUBLISHED` 才显示公开链接；失败或拒绝不显示在发布记录列表中。
- 公开副本复制的临时失败由后端最多自动重试 3 次；前端持续展示“审核中”，仅在三次失败后的终态通过官方消息展示原因。

### 3.3 全局官方消息

- 登录后的左侧导航栏提供消息铃铛；点击后以抽屉展示官方消息。
- 本迭代只实现官方消息。发布失败或未来审核拒绝时，显示关联图片、后端提供的用户可理解失败/拒绝说明和发生时间；不展示存储路径或原始服务端错误。重新发布失败/拒绝的消息需明确标注“重新发布失败/被拒绝”。
- 用户主动撤销发布、删除已发布资产或重新发布成功不创建官方消息；消息中心仅承载发布失败和未来审核拒绝。
- 打开抽屉不自动标记已读；点击单条消息才将该条标记已读。支持全部已读、单条改回未读、单条清除和全部清除。
- 铃铛显示未读消息数量；超过 99 条时显示 `99+`。已读消息仍保留，只有用户点击清除后才从消息列表删除。
- 消息按创建时间倒序展示，直接请求当前用户全部未清除的官方消息；不设置自动清理期限。
- 全部清除前必须二次确认，明确会将全部官方消息从用户消息列表中永久移除且无法恢复；单条清除不影响其他消息。
- 官方消息 REST 列表为每条消息拼接与资产页单张图片一致的完整资产快照；消息关联图片已删除时该快照为空。
- 点击消息本体仅标记该条已读；点击“查看作品”也标记已读、关闭消息抽屉，并直接以资产页同一详情组件打开该消息携带的资产快照，不跳转资产页或另发图片详情请求。详情中提供与资产页一致的收藏、发布/撤销、下载和删除操作。
- 若关联图片已删除，“查看作品”按钮不可用并提示“该图片已删除”。

## 4. 前端状态与 REST 对账

- 发布状态本身不使用 SSE。POST 接收成功后写入本地“审核中”快照；进入资产页、手动刷新或重新获取资产数据时，以 REST 返回的发布状态为准。
- 官方消息通过认证后的用户级 SSE 实时推送；它与生成任务状态事件复用同一条标签页生命周期连接。新消息事件携带完整安全通知内容和未读数量，但不携带私有签名 URL 或内部存储字段；抽屉打开时刷新官方消息 REST 列表以获得完整资产快照。REST 快照仍是权威来源。
- 收到新官方消息事件时，若消息抽屉已打开则立即刷新并展示新消息；抽屉关闭时只更新未读数量。
- 标签页不可见时不主动断开 SSE；浏览器或系统挂起、网络恢复或页面重新可见后，重新建立连接并对账活跃任务和未读消息。
- 用户级 SSE 连续 3 次连接失败后，全局导航栏显示非阻塞“实时更新连接已断开”提示和“重新连接”操作。
- 点击“重新连接”开启新一轮最多 3 次连接尝试。消息读写或清除后，后端向同一用户的其他标签页推送未读数量变化并同步更新。
- 非终态统一映射为“审核中”；成功、失败和未来审核拒绝必须区分展示，不能将所有终态误判为已发布。
- 收藏、发布、撤销、重新发布、删除和消息读写成功后，失效或更新受影响的资产页、详情和消息查询缓存。
- 批量删除沿用现有逻辑删除模型：接口维持幂等空成功响应，命中的当前可见资产立即从列表移除，私有原图和公开副本由可重试后台清理流程处理；不新增逐项删除结果响应。
- 前端只消费后端返回的私有签名 URL 或公开 URL；不得推断对象路径、拼接私有 URL 或在浏览器持久化私有签名 URL。

## 5. API 与前端模型约束

- 发布请求仅提交图片 ID、标题和可选描述；最终提示词由后端从图片所属任务读取并写入发布快照。
- 每次新的发布或重新发布操作生成 UUID `Idempotency-Key`；同一次点击及其网络重试复用该值，以取得同一审核记录而不重复提交。
- 若另一标签页已提交同图审核请求，后端拒绝新的不同幂等键请求；前端重新获取资产快照并展示已有的审核中记录。
- 资产查询需要返回收藏状态，以及当前审核中或已发布记录所需的展示字段；失败/拒绝原因通过官方消息接口返回，而非混入发布记录列表。
- 官方消息数据至少需包含消息 ID、类型、关联图片、内容、创建时间和已读状态；前端 ID 一律按字符串处理。
- 具体 URL、请求方法、响应 DTO、分页与幂等契约在后端接口设计确认后补充，不得由前端自行假设。

## 6. 异常场景与验收要点

- 发布请求被接收后刷新页面，仍能从后端快照恢复“审核中”。
- 发布成功后仅显示新公开链接；重新发布成功后旧链接失效、新链接可用。
- 发布失败或拒绝不会占据发布记录列表，但会产生未读官方消息；阅读、全部已读、改未读和清除均正确更新未读数量与抽屉。
- 删除已发布资产在用户确认前不改变任何状态；确认后不再展示私有资产或有效发布记录。
- 公开社区、详情、他人主页及互动消息不因本迭代接口或组件而被提前实现。
- 批量发布不在当前迭代范围内，留待后续单独设计逐图标题、描述与审核队列交互。
