# AiVista 前端关键词搜索模块

> 对应迭代：前端迭代 8——关键词搜索
> 当前状态：已完成
> 维护规则：本文记录公开作品关键词搜索的前端范围、交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

在“灵感”菜单下提供独立的公开作品关键词搜索列表，不改变迭代 7 已完成的“发现 / 关注”双列表。

## 2. 已确认约束

- 搜索作为前端迭代 8 独立实施，不回退或扩充前端迭代 7。
- “灵感”是菜单名称；“发现”和“关注”是当前已交付的内部列表名称。
- 搜索字段仅包含公开作品的标题与最终正向提示词；描述、负向提示词、作者昵称和生成配置不参与搜索。
- 规范化后的输入长度为 1～100 个字符；超过 100 个字符时提示且不提交，不静默截断。纯空白不发送请求，单个汉字、字母、数字或标点可以提交。
- 前端使用规范化副本执行空白和 1～100 字符校验、建立查询键，但搜索框和页面 URL 保留用户提交文本；安全检索值由后端生成，前端不解释 Meilisearch 查询语法。
- 英文字母搜索不区分大小写，拉丁字母匹配忽略重音差异，简体与繁体中文互相匹配；搜索框和结果正文保持原文。
- 搜索采用分词、完整词和前缀匹配，不承诺任意中间连续子串命中；最多前 10 个有效检索词参与搜索。
- 多关键词先匹配全部词，结果不足时优先保留更稀有的词并逐步放宽；不承诺每个关键词子集都被完全对称召回。
- 标点、Emoji 和其他符号只作为分隔，不触发引号短语、减号排除等高级查询语法；纯标点、纯符号或纯 Emoji 可以提交，并按图片点赞数、发布时间和图片 ID 倒序返回热门公开作品。
- 启用 Meilisearch 默认拼写容错，精确命中优先于容错命中，纯数字只做精确匹配；搜索框继续显示用户原始输入，不自动替换成推测词。迭代 8 不支持拼音、同义词或语义向量搜索。
- 搜索结果使用 Meilisearch 文字相关性顺序，标题排在最终正向提示词之前；文字相关性完全相同时再按图片点赞数、发布时间和图片 ID 倒序。作者总获赞数和粉丝数不参与排序，前端不重新排序。
- 搜索列表首次最多接收 20 项，后续每次最多接收 40 项；每个关键词最多开放前 200 条结果。
- 前端不传 `limit`，只根据可空 `nextOffset` 继续加载；首次不传 offset，后续原样传回服务端给出的 offset，切换关键词时重置分页位置。
- `nextOffset` 表示后端已经检查过的 Meilisearch 原始候选位置，可能大于本页 `items` 数量；前端不得用 `items.length` 自行推导 offset。
- 搜索分页不使用固定结果快照；索引变化可能造成后续页少量重复或遗漏，重新搜索后读取最新结果。
- 搜索结果复用公开作品卡片、详情和统一图片模型；已撤销作品是否可打开以当前详情接口为准。
- 搜索不是第三个固定标签；发现和关注工具栏均提供搜索入口。
- 搜索使用独立路由 `/inspirations/search?q=关键词`，按 Enter 或搜索按钮明确提交，不在输入过程中请求。
- 搜索建议、搜索历史、热门关键词和高级筛选不进入本迭代。
- 搜索数据与签名 URL 不写入前端持久化存储、页面 URL 的非必要字段、埋点或错误监控。
- 搜索接口超限时返回 HTTP 429、`SEARCH_RATE_LIMITED` 和 `Retry-After`；搜索服务不可用时返回 HTTP 503 与 `SEARCH_UNAVAILABLE`，两者都不得影响发现、关注和已有详情状态。

## 5. 页面、路由与交互设计

搜索位于“灵感”菜单范围内。“发现 / 关注”工具栏右侧显示紧凑搜索框，搜索结果页顶部显示完整搜索框。

- 按 Enter 或搜索按钮提交，输入过程不请求；纯空白不进入结果页。
- 结果路由为 `/inspirations/search?q=关键词`，顶部保留搜索框，下方展示当前关键词及作品瀑布流。
- 纯标点、纯符号或纯 Emoji 查询正常展示热门公开作品，不显示“符号已命中正文”等误导信息。
- 修改输入内容时保留当前结果，再次提交后切换关键词并从第一页加载。
- 点击清除按钮只清空输入，不立即清除当前结果；提供“返回发现”入口退出搜索。
- 点击作品复用公开详情覆盖层；关闭后恢复搜索关键词、已加载分页和滚动位置。
- 浏览器返回时恢复进入搜索前的发现或关注列表及其滚动位置；直接访问搜索 URL 也能加载结果。
- 初始加载、无结果、首屏失败、加载更多失败、达到 200 条上限和图片 URL 续期沿用现有列表交互规则。

## 6. API、前端模型与状态管理

搜索接口为 `GET /api/inspirations/search?q={keyword}&offset={nextOffset}`，消费公开作品 DTO 数组和可空 `nextOffset`。首次请求不带 offset，后续请求原样携带当前查询返回的 offset；前端不发送 `limit`、匹配策略或排序参数，也不依赖 `hasMore`。服务端可能为过滤失效候选检查更多原始结果，因此 `nextOffset` 可以大于本页返回数量，前端不得自行计算或修正。

搜索缓存必须与发现、关注缓存隔离，并按已提交的规范化关键词建立独立查询键；未提交输入不进入查询键，迟到响应不得覆盖当前关键词结果。接口 JSON 使用 `Cache-Control: private, no-store`，不得进入前端持久化缓存；该响应头不改变 OSS 图片的浏览器缓存策略。

## 8. 异常场景、可靠性与安全

- 纯空白不提交；无结果显示当前关键词和明确空状态；首屏失败可整体重试，继续加载失败保留已有结果。
- Meilisearch 或后端搜索链路不可用时只显示搜索错误，不影响返回发现、关注或打开已有公开详情。
- HTTP 429 / `SEARCH_RATE_LIMITED` 显示请求过于频繁并读取 `Retry-After`；HTTP 503 / `SEARCH_UNAVAILABLE` 显示搜索暂不可用。加载更多遇到任一错误都保留已有结果。
- 新关键词不得混入上一关键词的结果；取消或迟到响应不得覆盖当前查询。
- 非法 offset 按参数错误处理；关键词变化时始终从第一页重新搜索。
- 签名 URL、提示词正文和作品正文不得进入前端持久化存储、埋点或错误监控。
