# AiVista 个人资产模块

> 对应迭代：前端迭代 3——个人资产
> 当前状态：设计中
> 维护规则：本文记录个人生成资产的页面交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

接入已完成的个人资产后端能力，使已登录用户能浏览自己的成功生成图片、查看图片与最终提示词，并按单张或手动多选删除。

本迭代不包含收藏、发布、公开展示、点赞、关注和按全部历史一键删除。

后端业务事实与接口契约以 [个人生成历史与资产模块.md](../../backend/aivista/个人生成历史与资产模块.md) 为准。

## 2. 已确认约束

- 资产最小单位是单张成功图片；资产列表只显示当前用户且未删除的图片。
- 列表按成功保存时间倒序，前端使用 `Asia/Shanghai` 按日期分组；跨页结果追加到既有日期组。
- 使用不透明游标分页，默认 `limit=36`、最大 `60`，不显示或推测总数。
- 列表响应同时提供详情展示所需字段；点击图片不新增单图详情请求。
- 私有签名 URL 仅在内存中使用；URL 过期时重新加载当前资产列表。
- 删除使用统一批量接口；只提交用户手动勾选的 `imageIds`，重复删除按成功处理。
- 删除成功即从资产页移除；OSS 后台清理不阻塞前端，也不能恢复可见性。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 详情数据来源 | 复用当前列表项。 | 后端列表已提供详情字段，避免额外请求。 | 详情关闭后不单独缓存资源。 |
| 日期分组 | 前端按北京时间分组，后端保持 UTC 排序和游标。 | 同时保证用户展示习惯与分页稳定性。 | 追加下一页时合并首个同日期分组。 |
| 删除交互 | 单图与多选复用确认和同一接口。 | 删除语义一致，减少重复链路。 | 成功后从本地列表乐观移除；失败则恢复并提示。 |
| 已删除快照 | 资产页不展示已删除图片。 | 当前页仅展示可管理资产。 | 任务/会话中的无 URL 占位由生成工作台模块处理。 |

## 5. 页面、路由与交互设计

路由为 `/assets`，仅认证用户可访问。页面应包含日期分组的图片网格、加载更多入口或等价可访问加载方式、空状态、错误重试、图片详情视图和删除操作。

| 场景 | 前端行为 |
| --- | --- |
| 首次加载 | 请求第一页；空列表显示“尚无生成图片”及前往生成入口。 |
| 加载下一页 | 使用 `nextCursor` 请求并追加；`null` 表示无更多数据。 |
| 查看详情 | 使用列表项打开详情，展示大图、最终正向提示词及可选负向提示词。 |
| URL 到期 | 不继续使用失效 URL，重新加载当前资产列表后更新内存数据。 |
| 删除单图/多选 | 明确永久删除确认，提交用户选中的 ID；成功后从网格移除。 |
| 删除失败 | 保留原项与选择状态，显示安全错误消息并允许重试。 |

移动端需保证图片浏览、详情关闭和多选删除可操作；删除按钮不得与图片预览点击区域混淆。具体视觉和组件取舍待实现前确认。

## 6. API、前端模型与状态管理

| 目的 | 接口 | 前端约定 |
| --- | --- | --- |
| 资产分页 | `GET /api/generation-images?cursor=&limit=36` | 使用 `items`、`nextCursor`；响应按 UTC 排序，前端完成北京时间分组。 |
| 删除图片 | `POST /api/generation-images/delete` | 请求为 `{"imageIds":["101","102"]}`；成功 `data` 为 `null`。 |

领域模型至少保留 `imageId`、`url`、`urlExpiresAt`、`width`、`height`、`createdAt`、`finalPrompt`、`finalNegativePrompt`。不得将 URL 存入本地持久化缓存；删除请求不按资源存在性展示差异，以符合后端归属隔离语义。

## 8. 异常场景、可靠性与安全

- `40100`、`40102` 统一遵循工程基础文档的认证处理。
- 非法游标或 `limit` 的 `422` 应停止本次加载、保留已加载内容并提示重试；不得自行修改游标猜测下一页。
- 删除接口的“已删除、他人或不存在均成功”是安全约束，UI 不得试图区分资源存在性。
- 签名 URL、提示词和图片不得写入持久化存储、URL、埋点或错误监控；详情页面使用 `Referrer-Policy: no-referrer`。
