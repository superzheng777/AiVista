## 2. 一期目标

一期后端围绕“普通用户生成、管理、发布并互动 AI 图片”构建最小完整闭环：

```text
用户提交文生图请求
        ↓
生成结果沉淀为个人历史资产
        ↓
用户收藏图片，或收藏并发布
        ↓
公开图片进入灵感社区
        ↓
其他用户浏览提示词、点赞图片、关注作者
```

一期仅考虑普通用户，不包含付费订阅、权益、计费、订单或支付能力。推荐流（热门推荐、仅关注的人）不属于一期首版范围，后续单独规划。

一期客户端优先完成 Web 端。React Native App 在 Web 端完成后开发。后端认证与数据模型应保留 App 接入空间，但 App 的令牌传输、安全存储、应用完整性校验和设备管理不纳入当前 Web 端实现范围。

## 3. 已确认业务边界

| 主题 | 已确认规则 |
| --- | --- |
| 用户类型 | 一期仅支持普通用户。 |
| 单次文生图 | 当前固定使用 `qwen-image-2.0`，用户可选择生成 1 到 6 张图片；服务端按模型能力校验数量。 |
| 局部重绘 | 后续迭代实现；届时允许用户选择自己生成的图片或上传本地图片作为来源，重绘结果也可继续作为来源。具体输入、结果与原图关系及生成数量在对应迭代文档中确定。 |
| 生成历史 | 所有成功生成的图片均保留在用户历史生成资产中，不以是否收藏作为保留条件；删除与保留规则在迭代 3、4 设计。 |
| 收藏 | 收藏是用户对生成图片的标记；用户可在个人资产中筛选已收藏图片。 |
| 发布 | 用户提交自己的生成图片及标题、描述，异步文本审核通过后写入 `public_at`。原图始终位于私有 OSS Bucket；后续灵感页只为当前已发布图片签发短期 URL。资产删除与撤销发布相互独立。 |
| 提示词公开 | 已发布图片的公开详情从不可变、保留的来源任务关联读取最终提示词与生成配置；成功生成即代表已通过生成链路要求，发布不重复审核提示词。不公开会话历史、内部上下文、服务商参数、工作流配置或系统提示词。公开详情展示留待迭代 5。 |
| 灵感流 | 首版提供全站公开内容浏览；“仅关注的人”“热门推荐”等能力留待后续迭代。 |
| 互动 | 一期包含图片点赞/取消点赞，以及用户关注/取消关注。用户可以点赞自己的或他人的已发布图片。 |

## 4. 迭代原则

1. 按可独立验收的最小闭环推进，每个迭代只解决一个明确目标。
2. 先建立私有生成资产，再开放公共发布与社交互动，保证内容来源和权限边界清晰。
3. 详细文档先行；开始任一迭代编码前，先补充该迭代文档。
4. 代码、测试和文档同步更新；接口契约或数据结构变化必须反映到对应文档。
5. 保持向后演进空间；一期不实现付费和推荐，但不把规则设计成阻碍未来扩展的硬限制。

### 5.4 迭代 3：个人生成历史与资产

状态：已完成。

目标：

- 保存生成图片、历史提示词及必要生成上下文，并设计图片、会话与资产的删除或保留规则。
- 全量查询个人历史生成图片（迭代 4 已确认替代原游标分页）。

详细设计及验收结果见 [个人生成历史与资产模块.md](个人生成历史与资产模块.md)。已完成资产查询、批量软删除与私有 OSS 异步清理；容器化 MySQL 与真实 OSS 集成验收可在具备相应环境的开发或 CI 环境补充执行。

### 5.5 迭代 4：发布与官方消息

状态：已完成。

目标：

- 收藏状态持久化在 `generation_images.is_favorited`，并提供批量设置目标状态的接口。
- 异步审核自己的发布标题和描述；审核通过后将同一张私有 OSS 图片标记为公开，审核前显示发布审核中。
- 撤销已发布作品，并在审核拒绝或审核服务不可用时创建官方消息。

详细设计见 [收藏与发布模块.md](收藏与发布模块.md)。发布审核、V7/V8 迁移、异步文本审核、可靠事件、SSE 通知、官方消息接口、统一图片 DTO、全量资产列表、批量收藏，以及包含 `PENDING`、`APPROVED` 图片的全量个人发布列表均已实现；资产删除与删除发布的独立语义、私有对象短期 URL、审核幂等与并发、异步审核状态机及迟到结果隔离也已落地。灵感社区的分页和详情属于迭代 6。

## 6. 后续迭代方向

以下方向不纳入当前一期首版排期：

- 普通用户之外的付费用户、权益和计费体系。
- 灵感社区的“仅关注的人”、热门排序和个性化推荐。
- 提示词可见范围、复制能力、脱敏策略等内容控制能力。
- 更丰富的生成参数、模型管理、任务调度和生成结果编辑能力。
- React Native App 接入，以及对应的令牌传输、安全存储、应用完整性校验和设备管理。
