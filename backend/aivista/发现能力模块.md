# AiVista 发现能力模块

> 对应迭代：迭代 7——灵感、关注与关键词搜索
> 当前状态：设计中
> 维护规则：本文记录发现能力的后端范围、接口契约、数据与运行约定；代码、测试和文档必须同步修改。

## 1. 目标与范围

在迭代 6 的公开灵感流基础上，为当前仍公开的作品补充三类发现列表；首版优先提供清晰、可预测的浏览与搜索语义：

- 灵感列表。
- 关注列表。
- 关键词查询结果。

灵感列表与关注列表均按公开时间倒序，关键词查询按文本相关性优先。热门排序、随机探索、复杂推荐、评论、个性化画像、付费曝光和对私有/审核中内容的发现不在当前范围。

## 2. 已确认约束

- 仅当前 `APPROVED` 且 `public_at` 非空的作品可被发现；撤销或失效后不得继续出现在结果中。
- 图片项继续使用 `GenerationAssetImageResponse`；不得创建第二套图片响应 DTO。
- 公开内容与现有灵感流一致，不返回会话历史、对象键、审核记录、系统提示词或内部上下文。
- 所有列表采用服务端稳定排序与不透明游标；不得使用客户端页码推算。
- 灵感列表与关键词查询允许匿名访问；关注列表要求登录。无论访问者身份如何，均不得突破公开作品的可见性边界。
- 灵感页和发现能力不订阅 SSE；刷新或重新进入时重新读取当前公开数据。

## 3. 关键决策记录

已确认发现页只包含灵感列表、关注列表和关键词查询结果。灵感与关注列表按公开时间倒序；关键词查询匹配公开标题、公开正向提示词和描述，并独立按文本相关性排序，不依赖灵感列表名次。搜索输入细节、MySQL 索引验证、匿名限流和缓存策略仍待后续确认。

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 发现列表范围 | 灵感列表、关注列表、关键词查询结果 | 作为迭代 7 后续讨论的共同边界。 | 不实现热门排序或其他未确认的发现入口。 |
| 访问条件 | 灵感列表与关键词查询允许匿名访问；关注列表要求登录。 | 关注关系属于当前登录用户；三类结果都不能突破公开可见性边界。 | 关注列表接口必须鉴权，匿名访问返回现有未认证错误；其余两类接口兼容匿名查看者。 |
| 搜索字段 | 匹配公开作品标题、公开正向提示词和描述；不匹配负向提示词。 | AI 图片的主要语义通常位于生成提示词中，仅搜索标题和描述会造成大量漏检；负向提示词表达的是画面中不应出现的内容，参与召回会产生反向误匹配。 | 搜索索引与候选召回覆盖 `publication_title`、`publication_prompt`、`publication_description`；不检索作者昵称、评论、标签或内部提示词。 |
| 搜索输入边界 | 前端仅传递一个 `keyword` 字符串；后端负责校验、规范化、拆词、匹配与排序。 | 不让 Web 或未来 App 自行定义分词、权重或布尔语法，保证所有客户端的搜索语义一致。 | 不接收前端传递的 tokens、权重或排序参数；空白处理、长度、单字符查询和限流策略待确认。 |
| 接口组织 | 采用三个语义独立的列表接口：灵感、关注与搜索。 | 三类查询的认证、输入、缓存和后续限流约束不同，不通过单一接口的 `mode` 参数隐式分支。 | 保留现有公开灵感接口；新增关注与搜索接口；三者复用统一图片 DTO 和 `{ items, nextCursor }` 分页响应。 |
| 关注列表排序 | `public_at DESC, id DESC`。 | 关注流以当前用户所关注作者的最新公开作品为唯一排序目标，不叠加推荐信号。 | 游标编码最后一条记录的 `publicAt` 与 `imageId`；查询使用稳定 keyset 分页。 |
| 分页批大小 | 三类列表首次请求最多返回 20 个作品，后续每次最多返回 40 个作品；客户端不传 `limit`。 | 首批更小以缩短首屏响应并减少初始签名 URL；用户开始滚动后用较大批次降低请求频率。 | 服务端按 `cursor` 是否为空选择批量：无游标查询 21 条并最多返回 20 条，携带游标查询 41 条并最多返回 40 条；多查的一条只用于判断是否返回 `nextCursor`。 |
| 灵感列表排序 | `public_at DESC, id DESC`。 | 首版明确回答“查看最新公开作品”，不把热门、推荐和作者历史影响力隐藏在一个不可解释的综合榜单中。 | 复用稳定 keyset 分页；游标编码最后一条记录的 `publicAt` 与 `imageId`，不新增综合分数、排名快照或后台构建任务。 |
| 灵感列表刷新 | 每次无游标请求读取当时最新的公开作品；同一次向后分页继续使用 `publicAt`、`imageId` 边界。 | 公开时间是已持久化的稳定排序键，无需为了分页一致性维护全站排名快照。 | 刷新时从头读取；已撤销或不再 `APPROVED` 的作品实时不可见，新发布作品在下一次刷新或重新进入时出现。 |
| 搜索排序信号 | 标题、公开正向提示词和描述的文本相关性优先；同等相关性下按 `public_at DESC, id DESC`。 | 搜索首先回答明确查询，新鲜度只处理相关性相同的作品；点赞数、作者粉丝数和作者累计获赞不参与首版搜索排序。 | 排序键为服务端定义的离散 `matchLevel`、确定性整数 `textScore`、`publicAt`、`imageId`；具体匹配等级和字段权重仍需在实施前用样例集确认。 |
| 搜索匹配策略 | 首版使用 MySQL 全文检索加 n-gram 召回候选作品，再由后端按固定字段权重计算最终等级和整数分数。 | 中文检索不能只依赖普通英文分词；MySQL 浮点相关性会随语料变化，不直接作为公开游标边界。 | 实施前核验部署 MySQL 版本与 n-gram parser；搜索游标绑定规范化查询摘要、搜索算法版本和最后一项稳定排序键，不绑定灵感列表或其快照。多关键词语义、查询长度、单字符处理及限流仍待确认。 |

## 6. 数据模型与配置

灵感与关注列表复用现有公开时间索引，不新增排名分数、排行榜快照、快照状态或后台构建任务。搜索倾向在现有公开快照字段上新增 MySQL n-gram 全文索引；实施前必须确认实际 MySQL 版本、字符集、`ngram_token_size` 和查询计划。首版不引入外部检索服务；数据规模或语义搜索需求超出 MySQL 能力后再单独评估。

## 7. API 与权限

采用三个语义独立的接口，不使用 `mode` 参数混合不同的权限和输入规则：

| 方法与路径 | 访问条件 | 已确认参数与响应 |
| --- | --- | --- |
| `GET /api/inspirations` | 匿名或登录 | 保留迭代 6 的公开灵感入口；`cursor` 可选；无游标最多 20 项，携带游标最多 40 项；按 `public_at DESC, id DESC`。 |
| `GET /api/inspirations/following` | 必须登录 | `cursor` 可选；无游标最多 20 项，携带游标最多 40 项；仅查询当前登录用户关注作者的当前公开作品，按 `public_at DESC, id DESC`。 |
| `GET /api/inspirations/search` | 匿名或登录 | `keyword` 必填、`cursor` 可选；无游标最多 20 项，携带游标最多 40 项；查询当前公开作品的标题、公开正向提示词和描述。后端负责输入规范化与匹配；长度、空白、单字符查询和非法输入规则待确认。 |

三者均返回 `GenerationAssetImageResponse` 列表与 `nextCursor`，不创建第二套图片 DTO。每个游标必须绑定创建它的接口语义与服务端稳定排序：灵感和关注游标绑定最后一项的 `publicAt`、`imageId`；搜索游标绑定规范化 `keyword` 摘要、搜索算法版本、最后一项的 `matchLevel`、`textScore`、`publicAt` 与 `imageId`。跨接口或跨搜索词复用游标均为无效请求。首版不创建灵感排名快照，也不让搜索游标依赖灵感列表。后续仍需确定搜索输入校验、具体匹配等级、数据库索引、匿名限流和缓存策略。
