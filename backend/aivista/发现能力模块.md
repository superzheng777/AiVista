# AiVista 发现能力模块

> 对应迭代：迭代 7——发现与关注列表
> 当前状态：已完成
> 维护规则：本文记录发现与关注列表的当前业务规则、实现和验收；代码、测试或接口变化时必须同步修改。

## 1. 目标与范围

在已有公开作品列表上调整分页批量，并新增当前登录用户的关注列表。

## 2. 已确认约束

- 两类列表只返回当前 `APPROVED` 且 `public_at` 非空的作品，按 `public_at DESC, id DESC` 排序。
- 发现列表允许匿名访问；关注列表必须登录。
- 图片项复用 `GenerationAssetImageResponse`，不返回对象键、审核记录、会话历史或内部上下文。
- 客户端不传 `limit`，只消费服务端返回的不透明游标。
- 页面不订阅 SSE；刷新或重新进入时读取当前公开数据。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 分页批量 | 每次最多 30 项。 | 与瀑布流一次追加一批的前端策略统一，首屏与后续加载使用相同契约。 | 服务端查询 31 项，多取一项只判断 `nextCursor`。 |
| 分页方式 | 使用 `publicAt + imageId` 的 keyset 游标。 | 排序键稳定，避免深分页偏移。 | `nextCursor` 为空表示没有下一页。 |
| 游标隔离 | 游标绑定版本和列表作用域。 | 防止发现与关注错误复用游标。 | 跨接口、结构或版本错误返回 `INVALID_CURSOR`。 |
| 关注关系 | 每次请求按当前关注关系查询，不建立快照。 | 关注变化应及时生效，避免维护额外状态。 | 刷新后获得完整的当前关注结果。 |
| 图片续期 | 不定时刷新；过期或实际加载失败时刷新单图并最多重试一次。 | 已加载图片无需续期，定时刷新会产生无效请求。 | 复用公开单图详情接口。 |

## 6. 数据模型与配置

不新增业务表。关注列表关联 `user_follows` 与 `generation_images`；V12 新增索引 `generation_images(user_id, publication_review_status, public_at DESC, id DESC)`。图片继续使用现有 OSS 签名 URL 有效期配置，签名 URL 不持久化。

## 7. API 与权限

| 方法与路径 | 权限 | 契约 |
| --- | --- | --- |
| `GET /api/inspirations` | 匿名或登录 | `cursor` 可选；返回 `{ items, nextCursor }`。 |
| `GET /api/inspirations/following` | 登录 | `cursor` 可选；返回当前关注作者的公开作品。 |
| `GET /api/inspirations/{imageId}` | 匿名或登录 | 返回当前公开单图并重新签发 URL。 |

安全配置不得整体匿名放行 `/inspirations/**`；关注接口必须先匹配认证规则。

## 8. 异常场景、可靠性与安全

- 非法或跨列表游标返回 `INVALID_CURSOR`；匿名访问关注接口返回 401。
- 作品撤销后不再进入新查询，旧列表项打开详情时返回不存在状态。
- API JSON 不缓存签名 URL；OSS 图片可使用浏览器私有缓存。
- 每批点赞状态一次性查询，避免逐项数据库访问。
- 签名 URL、提示词正文和作品正文不得进入持久化浏览器存储、埋点或错误监控。
