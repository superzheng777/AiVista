# AiVista 收藏与发布模块

> 对应迭代：后端迭代 4——收藏、异步发布与官方消息
> 当前状态：设计中
> 维护规则：本文记录迭代 4 的范围、约束、设计结论和实施进度；代码、测试、接口或数据结构变化时必须同步修改。

## 1. 目标与范围

本迭代基于个人生成资产实现：收藏与收藏筛选、异步发布私有图片、撤销与重新发布、已发布资产删除联动，以及发布失败的官方消息通知。

发布成功后，私有原图被复制为独立公开 OSS 副本，系统返回直接指向该副本的稳定公开 URL。本迭代不提供公开社区列表、公开详情、他人主页、点赞、关注、推荐或互动消息。

## 2. 已确认规则

| 主题 | 规则 |
| --- | --- |
| 权限 | 仅图片所有者可收藏、取消收藏、发布、重新发布、撤销或删除自己的未删除资产。 |
| 收藏 | 收藏为 `generation_images` 上的所有者标记；支持单张和条件式批量变更：全部已收藏选择时统一取消收藏，含任一未收藏项时仅将未收藏项设为收藏。未来收藏他人公开作品时另建关系表，不复用本字段。 |
| 发布输入 | 客户端仅提交图片 ID、标题和可选描述。标题必填、最多 20 个字符；描述最多 500 个字符。 |
| 提示词快照 | 服务端从该图片所属 `generation_tasks.final_prompt` 与 `final_negative_prompt` 复制快照。不得接受客户端提交的提示词；快照表示本项目提交给模型的最终输入，不表示提供商智能改写后的文本。 |
| 公开副本 | 复制私有原图至独立、不可猜测的公开 OSS 对象路径；私有 `object_key` 不变。数据库以公开对象键为权威值，公开 URL 由稳定公开域名和对象键构成。 |
| 公开链接失效 | 公开副本使用禁止或极短缓存策略；撤销、替换或删除时删除对象并刷新 CDN 缓存，尽量使旧直链立即失效。 |
| 当前有效发布 | 每张图片最多一条 `PUBLISHED` 发布记录；存在 `PENDING_REVIEW` 或 `PUBLISHING` 记录时不得再次提交。撤销后可重新发布，且不得复用旧链接或旧公开副本。 |
| 重新发布 | 新记录审核期间旧 `PUBLISHED` 记录和旧链接保持可用；新记录发布成功时切换为唯一有效发布、撤销旧记录并删除旧公开副本。新记录失败或被拒绝时旧记录不变。 |
| 撤销与删除 | 撤销删除公开副本但不影响私有原图。删除有有效发布的资产必须由客户端明确确认；确认后同步撤销公开内容并删除私有原图。 |
| 失败通知 | 发布失败或未来审核拒绝不出现在发布记录列表中，改为创建持久化官方消息，含后端映射的用户可理解原因；不得暴露 OSS 路径、异常堆栈或第三方原始错误。 |

## 3. 发布状态机与异步执行

发布请求返回 `202 Accepted`，只表示请求已被接收。发布记录是异步工作的权威状态，不复用图像生成任务状态。

```text
PENDING_REVIEW -> PUBLISHING -> PUBLISHED
       |               |
       +-> REJECTED    +-> FAILED
       +-> WITHDRAWN   +-> WITHDRAWN

PUBLISHED -> REVOKED
```

- 当前无需人工审核时，后台工作器可将 `PENDING_REVIEW` 自动推进到 `PUBLISHING`；前端对两者均展示“审核中”。未来人工审核只需使记录停留在 `PENDING_REVIEW`，不改变客户端对账逻辑。
- 重新发布审核期间，资产查询面向所有者只返回该图片“审核中”状态，不暴露旧发布记录或撤销操作；外部旧公开链接保持有效。新记录 `FAILED` 或 `REJECTED` 后，所有者侧恢复旧 `PUBLISHED` 摘要。
- 只有 `PUBLISHED` 才返回公开 URL 并计入有效发布。
- `FAILED`、`REJECTED`、`WITHDRAWN` 和 `REVOKED` 均为终态，但前两者绝不可被客户端展示为发布成功。
- 异步执行采用可靠事件/Outbox 投递；失败记录须带稳定、可安全展示的原因，并触发官方消息。对外原因必须由后端映射，禁止透传 OSS 路径、异常堆栈或第三方原始错误。
- 公开副本复制等可恢复的临时失败自动重试最多 3 次；超过次数后转为 `FAILED` 并创建官方消息。
- 用户刷新时通过 REST 快照读取状态；本迭代不为发布状态发送 SSE。发布失败或未来审核拒绝落库后，经 Outbox 向该用户的既有 SSE 推送轻量通知事件和未读数量；消息详情仍由 REST 查询。

## 4. 数据模型

### 4.1 资产收藏

在 `generation_images` 增加仅所有者可见的收藏状态和必要索引；资产列表以 `all/favorited` 筛选并保持现有不透明游标排序。

### 4.2 发布记录

新增 `image_publications`（名称在迁移评审时最终确定），至少包含：

- 发布 ID、图片 ID、所有者 ID；
- 标题、可空描述；
- 正向与可空负向提示词快照；
- `PENDING_REVIEW`、`PUBLISHING`、`PUBLISHED`、`FAILED`、`REJECTED`、`WITHDRAWN`、`REVOKED` 状态；
- 公开对象键；仅 `PUBLISHED` 时可派生公开 URL；
- 替换发布关联、失败原因、创建/完成/撤销时间及并发控制字段。

资产详情只返回当前审核中或当前已发布记录。已撤销、已替换、撤回、失败和拒绝记录不向用户展示；为保证 OSS 清理、并发控制和通知关联，可在内部保留到清理与必要关联完成后再删除。每次发布提交保有独立发布 ID；撤回后再次提交必须创建新发布 ID。

### 4.3 官方消息

新增用户通知存储（名称在迁移评审时最终确定），至少包含：

- 消息 ID、接收用户 ID、分类 `OFFICIAL`、事件类型（首次发布失败/拒绝、重新发布失败/拒绝）；
- 关联图片和发布记录、可安全展示的标题与原因；
- `read_at`、创建时间与软删除时间。

本迭代仅写入和查询官方消息；互动消息由点赞迭代扩展。未读状态独立于发布记录，打开消息抽屉不改变它。官方消息按创建时间倒序返回当前用户全部未软删除记录，不设自动清理期限；软删除消息不参与后续列表和未读统计。用户主动撤销发布、删除已发布资产或重新发布成功不创建官方消息；本迭代仅对发布失败和未来审核拒绝写入官方消息。

## 5. API、鉴权与读取边界

- 所有资产和消息接口均要求登录，并按当前用户过滤；图片、发布和消息 ID 对外以字符串返回。
- 发布/重新发布、撤销、收藏、条件式批量收藏和已发布资产删除均必须在服务端再次校验图片所有权、未删除状态及当前发布状态；当前不提供批量发布。
- 发布接口返回接收后的发布 ID 与状态；资产查询返回收藏状态及当前审核中/已发布的必要摘要。失败/拒绝原因仅从官方消息读取。
- 官方消息列表为每条未软删除消息拼接关联图片的完整、当前用户可见的资产 DTO；图片已删除或不再可见时返回空资产快照。该 DTO 与资产页单图数据一致，可供前端直接复用图片详情组件。
- 公开 OSS 直链只提供图片二进制内容；本迭代不提供公开标题、描述或提示词详情 API。相应快照保留给迭代 5。
- 发布及重新发布要求客户端传递 UUID `Idempotency-Key`；同一次用户操作及网络重试复用该键，服务端返回首次接收的发布记录，不得创建重复审核任务或公开副本。服务端以图片为粒度串行化竞争请求：已有审核中记录时，携带不同幂等键的新请求被拒绝，客户端应刷新并展示原审核记录。复制类可恢复失败固定最多自动重试 3 次，不得以客户端状态替代服务端唯一性约束。

## 6. 可靠性与一致性

- 创建公开副本失败时不得将新记录标为 `PUBLISHED`；重新发布失败时旧发布必须保持有效。
- 新记录成功时，状态切换、旧记录撤销和旧副本清理必须可恢复，最终保证每图最多一个有效发布。
- 删除已发布资产前必须取得明确确认；公开副本与私有原图的删除失败须进入可重试的清理流程，并保留足够的内部状态避免泄漏或孤儿对象。
- 批量删除时服务端按每张图片当前状态执行相同的撤回、撤销和删除规则；客户端确认前汇总普通、已发布和审核中数量，后端不得把批量操作简化为绕过这些状态校验。
- 批量删除沿用现有逻辑删除与异步 OSS 清理模型：接口对当前用户不可见、已删除或不存在图片按幂等成功处理，返回空成功响应而不新增逐项结果；命中的资产在事务中标记删除，私有原图及公开副本由可重试清理流程处理。
- 审核中记录允许所有者主动撤回并转为 `WITHDRAWN`；删除审核中图片前也必须确认并先撤回记录。工作器执行前后均校验记录未撤回；与复制并发时清理已产生但不再关联的公开副本。
- 公开直链经过 CDN 时，撤销、替换或删除必须刷新对应缓存；此为部署约束，当前开发环境只记录规则，不配置生产 CDN。
- 未读官方消息持续计入用户的未读数量；点击单条消息标记已读，支持全部已读、单条改未读、单条清除和全部清除。全部已读作用于当前用户所有未读官方消息。清除操作写入软删除时间；全部清除由客户端二次确认后调用，清除消息不影响对应发布或资产状态。
- 新官方消息 SSE 事件可携带完整的安全通知字段和未读数量，但不得携带私有签名 URL、OSS 对象键、内部异常或第三方原始错误；私有图片快照仅经已鉴权的官方消息 REST 列表返回。
- 已读、改未读、单条清除和全部清除后，经同一用户级 SSE 向其他标签页推送未读数量变化；客户端的“重新连接”每次开启新一轮最多 3 次连接尝试。

## 7. 测试与验收要点

- 非所有者、已删除图片和不合法状态均不能改变收藏或发布。
- 发布后刷新仍能读取审核中；成功后仅返回新公开链接；失败/拒绝创建官方消息且不出现在发布列表。
- 重新发布期间旧链接可用；新发布成功后旧链接失效；新发布失败时旧链接保持可用。
- 删除已发布资产的确认、撤销、副本清理与私有原图删除按既定顺序可靠执行。
- 通知的单条已读、全部已读、改未读、红点与清除行为互相独立且可持久化。
