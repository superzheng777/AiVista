# AiVista 收藏、审核发布与官方消息模块

> 对应迭代：后端迭代 4——收藏、异步文本审核发布与官方消息
> 当前状态：后端发布主链路、官方消息读取接口和我的发布列表已实现并通过单元测试；收藏仅为前端当前内存筛选，不持久化；前端尚未实现。
> 维护规则：本文是迭代 4 后端实现的当前依据；代码、测试、接口或数据结构变化时必须同步更新。

## 1. 已实现范围与边界

一张 `generation_images` 记录同时代表用户私有资产和可公开发布的作品，不创建公开 Bucket、公开副本或独立发布表。原图始终位于私有 OSS Bucket。

- 发布仅审核用户本次提交的标题和描述；不审核图片和生成提示词。图片与提示词的安全边界由生成链路负责。
- 审核通过后写入 `public_at`；匿名灵感接口只为已发布图片签发 10 分钟私有 URL。
- 资产删除与撤销发布独立：资产软删除不清空 `public_at`，即使资产已删除仍可撤销发布；只有两者都不可见时才安排 OSS 清理。
- 发布失败原因不写入图片表。用户可见的结果由官方消息展示；技术错误仅保留在 Outbox 的 `last_error`，不对用户暴露。
- 标题、描述分别调用文本审核。拒绝消息只保存安全的字段名和原因码，不保存供应商原始标签、命中词、命中位置或置信度。

## 2. 发布状态与重试

`public_at IS NOT NULL` 是图片当前已公开的唯一事实。`publication_review_status` 是发布流程状态，取值如下：

| 状态 | 含义 | 能否再次提交 |
| --- | --- | --- |
| `NONE` | 从未提交、撤销发布后的初始状态 | 可以 |
| `PENDING` | 等待或正在进行文本审核 | 不可以 |
| `APPROVED` | 审核通过，`public_at` 非空 | 不可以，需先撤销 |
| `REJECTED` | 标题或描述审核未通过，`public_at` 为空 | 可以 |
| `FAILED` | 审核服务连续三次异常后终止，`public_at` 为空 | 可以 |

状态流转：

```text
NONE / REJECTED / FAILED --提交--> PENDING --审核通过--> APPROVED
                                      |--中/高风险--> REJECTED
                                      |--连续三次异常--> FAILED
APPROVED --撤销--> NONE
```

- 每次调用审核服务前递增 `publication_review_attempt_count`。
- 审核服务异常按 30 秒间隔重试，最多 3 次；中、高风险不是技术异常，不重试。工作器领取审核后若 2 分钟未完成，会释放过期领取并按同一上限恢复；不会永久停留在 `PENDING`。
- `none`、`low` 风险等级直接通过；`medium`、`high` 不公开。
- 标题和描述保留在图片记录中，便于用户再次提交；它们在 `public_at` 为空时不会出现在公开查询中。
- `publication_version` 用于隔离撤销或重新提交后迟到的审核结果。旧版本结果条件更新失败时直接丢弃。

## 3. 数据模型

V7 在 `generation_images` 上增加：

| 字段 | 当前用途 |
| --- | --- |
| `public_at` | 非空表示当前公开。 |
| `publication_review_status` | 发布流程状态。 |
| `publication_version` | 发布流程乐观版本。 |
| `publication_review_attempt_count` | 当前提交的审核调用次数。 |
| `publication_review_started_at` | 本次提交开始审核的时间。 |
| `publication_title` / `publication_description` | 审核输入及通过后的公开文案。 |

V7 同时创建：

- `user_notifications`：官方消息，记录接收用户、图片 ID、类型、标题、内容和可选 `metadata_json`。拒绝消息的元数据形如 `{"violations":[{"field":"title","reasonCode":"CONTENT_POLICY"}]}`，可同时包含标题和描述两项。
- 通用 `outbox_events`：文本审核任务和 SSE 状态事件均通过它可靠投递。
- 通用 `idempotency_records`：用于生成任务和发布请求的幂等响应；发布作用域为 `PUBLICATION_REQUEST`，保存 30 分钟。

## 4. 当前接口

| 功能 | 方法与路径 | 当前行为 |
| --- | --- | --- |
| 提交发布审核 | `POST /api/generation-images/{imageId}/publication` | 仅图片所有者可调用；必须携带 UUID v4 `Idempotency-Key`；请求体为 `title`（1–100）和 `description`（1–500）；成功返回 `202 Accepted` 和 `PENDING`。同 key 重试返回首次响应，不同请求内容返回 `409`。 |
| 撤销发布 | `DELETE /api/generation-images/{imageId}/publication` | 清空 `public_at`、发布文案并将状态重置为 `NONE`。 |
| 灵感列表 | `GET /api/inspirations` | 无需登录；只返回 `public_at` 非空且 `APPROVED` 的图片、公开文案、生成提示词和短期私有 URL。当前为固定上限查询，分页与详情待后续完善。 |
| 我的发布 | `GET /api/users/me/publications` | 返回当前用户全部已公开且审核通过的图片，按发布时间和 ID 倒序；不分页。资产已软删除的公开图片仍会返回。 |
| SSE | `GET /api/events` | 复用认证用户级 SSE 连接。发布终态推送事件名 `publication.updated`，数据为 `imageId`、`publicationVersion`、`status`。 |
| 官方消息列表 | `GET /api/users/me/official-notifications` | 返回当前用户全部未删除的官方消息，按创建时间和 ID 倒序；不分页。拒绝消息的 `metadata.violations` 可同时指出标题、描述问题。 |
| 官方消息未读数 | `GET /api/users/me/official-notifications/unread-count` | 返回当前未读官方消息数，用于消息角标。 |
| 标记官方消息已读 | `POST /api/users/me/official-notifications/{notificationId}/read` | 仅当前用户自己的官方消息可操作；重复调用保持成功，其他用户或已删除消息返回 `404`。 |
| 全部标记已读 | `POST /api/users/me/official-notifications/read-all` | 将当前用户全部未删除的官方消息标记为已读；无未读消息时也成功。 |
| 删除单条官方消息 | `DELETE /api/users/me/official-notifications/{notificationId}` | 仅软删除当前用户自己的官方消息；其他用户或已删除消息返回 `404`。 |
| 清空官方消息 | `DELETE /api/users/me/official-notifications` | 软删除当前用户全部未删除的官方消息；空列表时也成功。 |

## 5. 可靠事件与官方消息

发布提交在一个本地事务内写入图片的 `PENDING` 状态和 `PUBLICATION_TEXT_REVIEW` Outbox 事件。审核工作器调用阿里云前不持有数据库事务。

审核终态由 `PublicationReviewOutcomeService` 在同一个本地事务中完成三件事：

1. 条件更新图片的发布状态及 `public_at`；
2. 写入一条 `user_notifications` 官方消息；
3. 写入 `PUBLICATION_STATUS_CHANGED` Outbox 事件。

其中 `eventType` 表示发生的是“发布状态变化”，`aggregateType = GENERATION_IMAGE` 表示该事件归属的实体是生成图片，`aggregateId` 为图片 ID。由于不存在独立的发布表，这不是“生成事件”和“发布事件”冲突。

SSE 分发器消费 `PUBLICATION_STATUS_CHANGED` 并向当前在线用户发送 `publication.updated`。SSE 仅做实时提示，离线或断线不会影响数据库状态；官方消息持久化后可由后续消息读取接口作为权威快照展示。

## 6. 阿里云内容安全配置

当前使用阿里云内容安全增强版的 `ugc_moderation_byllm_pro` 文本审核服务，调用接口为 `TextModerationPlus`。应用暂时复用现有 OSS RAM 凭证；该凭证已增加 `AliyunYundunGreenWebFullAccess`，未在本次实现中改动或新增密钥。

标题与描述分别作为文本请求发送；供应商原始风险标签、命中词、请求内容、对象键、签名 URL 和异常栈不得写入官方消息或普通日志。当前安全原因码为 `CONTENT_POLICY` 与 `SENSITIVE_INFO`，前端按 `metadata_json.violations` 标记对应输入框。
