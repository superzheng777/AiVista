# AiVista 个人生成历史与资产模块

> 对应迭代：迭代 3——个人生成历史与资产
> 当前状态：已完成
> 维护规则：本文记录迭代 3 的范围、数据模型、接口和删除语义；代码、测试和文档必须同步修改。

## 1. 迭代目标

在不创建第二套图片数据的前提下，基于迭代 2 已保存的私有生成结果，为用户提供个人生成历史与资产的查询、浏览和管理能力。

本迭代预期覆盖：

- 分页浏览当前用户所有已成功生成的图片。
- 查看单张图片及其所属任务的可展示生成信息。
- 确定图片、任务、会话与私有 OSS 对象的删除或保留规则。

收藏、发布、点赞和关注不属于本迭代；它们在后续迭代基于已有私有资产继续扩展。

## 2. 已有基础

迭代 2 已提供以下可复用数据和能力：

| 资源 | 当前作用 | 迭代 3 的使用方式 |
| --- | --- | --- |
| `generation_images` | 保存成功转存的私有图片及用户归属、对象键、尺寸、创建时间。 | 作为个人资产的唯一图片来源，不建立重复资产表。 |
| `generation_tasks` | 保存任务状态、图片数量、失败码、创建/完成时间和所属会话。 | 为资产详情提供任务级信息。 |
| `generation_sessions` / `generation_messages` | 保存会话标题和用户提示词历史。 | 按最终确认的隐私与删除规则提供关联信息。 |
| 私有 OSS | 保存 PNG 原图，任务详情按权限签发短期 URL。 | 继续保持私有访问；资产查询不得返回永久对象地址。 |
| 用户认证 | Bearer Access Token 和资源归属校验。 | 所有资产查询与管理操作仅限当前用户。 |

## 3. 已确认约束

- 所有成功生成的图片都属于用户的历史资产，不以是否收藏为保留条件。
- 用户只能查询和管理自己的资产；不存在和无权限资源统一处理，不能泄露其他用户资源是否存在。
- 图片原图保持私有；短期签名 URL 不写入数据库、日志或客户端本地持久化存储。
- 迭代 2 不提供会话、任务或图片硬删除；删除能力必须在本迭代单独设计，不得直接删除已有记录或 OSS 对象。
- 数据库事务不能覆盖 OSS 删除。若需要删除 OSS 对象，必须明确数据库状态、异步执行、失败重试和最终一致性规则。
- 后续发布功能复用私有原图，并通过标题、描述的异步文本审核决定是否写入 `public_at`；私有资产删除不影响审核中或已发布图片。

## 4. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 资产最小单位 | 单张成功图片。一次任务成功生成多张图片时，每张图片都是独立资产卡片。 | 收藏、发布等后续操作应以图片而非任务为对象；现有 `generation_images` 已是一图一条记录。 | 列表与详情均以 `imageId` 为资源标识，不创建第二套资产表。 |
| 列表排序与日期 | 按图片成功保存时间倒序，并按北京时间日期分组展示；同日内继续按成功保存时间倒序。 | 符合用户按生成历史浏览图片的习惯。 | 数据库排序使用 `created_at DESC, id DESC`；客户端根据 UTC 时间按 `Asia/Shanghai` 分组。 |
| 列表分页 | 仍按单张图片使用不透明游标分页，默认 `limit=36`、最大 `60`；前端可按响应式布局在范围内传值。 | 固定数量分页简单、高效；日期跨页时前端将下一页图片追加到已有日期组即可。 | 游标编码 `created_at + imageId`；不引入按日期补齐的特殊 SQL 或协议。 |
| 列表卡片内容 | 只展示图片；日期由分组标题展示，不展示提示词、任务状态或具体时分。 | 保持资产页图片网格简洁。 | 列表响应只返回渲染图片卡片和分页所需的最小字段。 |
| 资产列表响应 | 每张图片返回 `imageId`、短期图片 URL、URL 过期时间、宽度、高度、成功保存时间、最终正/负提示词和本次请求图片数量。 | 同时支持图片网格、日期分组和点击后直接打开详情；当前默认 36 张时数据量可接受。 | 字段固定为 `imageId`、`url`、`urlExpiresAt`、`width`、`height`、`createdAt`、`finalPrompt`、`finalNegativePrompt`、`requestedImageCount`；未来可新增可选字段，但不得删除或改变既有字段语义。 |
| 详情数据获取 | 资产页点击图片继续复用列表项，不额外请求单图详情接口；但发布失败官方消息点击“查看作品”可按 `imageId` 请求独立详情。 | 资产页默认一次仅返回 36 张，完整提示词数据量可接受；官方消息不再批量携带资产快照或签名 URL，按需读取可反映资产当前删除状态。 | 新增 `GET /api/generation-images/{imageId}`，成功返回与资产列表单项相同的 DTO；已删除、不存在或不属于当前用户时返回 `404`。URL 到期时资产页仍重新加载当前列表。 |
| 详情布局与复用 | 图片点击后使用统一图片详情视图：左侧大图，右侧上中下三段信息；个人资产与后续灵感页复用布局，右侧交互按页面不同。 | 统一前端体验与未来详情数据模型；个人资产当前不含关注、点赞。 | 本迭代只提供个人资产详情所需字段，不提前实现社区交互。 |
| 提示词展示 | 只展示该任务实际发送给模型的最终正向提示词；最终负向提示词有值时一并展示。 | 原始本轮输入可能未包含历史拼接内容，最终提示词才准确反映生成依据。 | 详情从 `generation_tasks.final_prompt`、`final_negative_prompt` 读取，不返回完整会话历史。 |
| 个人资产操作 | 图片详情底部提供删除按钮。 | 个人资产必须具备管理能力。 | 本迭代需要设计图片删除接口、数据库状态与私有 OSS 清理链路。 |
| 删除粒度 | 用户删除时只删除当前单张图片，不删除同一次任务生成的其他图片。 | 资产列表以单张图片为最小单位，用户应能独立管理每张结果。 | 删除模型必须以 `generation_images` 单条记录为对象，并保持任务其他结果可见。 |
| 删除后的会话展示 | 被删除图片在会话记录中只变为不可展示位置；其他图片、任务状态、提示词和会话记录保持不变。 | 删除单张资产不应影响同次任务的其他结果或生成历史。 | 必须保留任务内图片位置；会话查询不再为该图签发 URL。 |
| 任务与提示词保留 | 删除单图后保留任务、会话、提示词和原始生成数量；它们表示当时的生成历史。 | 只删除图片资产，不篡改已发生的生成事实；会话仍需保留图片位置。 | 任务快照按原始结果数量保留位置，已删除位置不返回 URL。 |
| 删除可逆性 | 删除为永久操作，不提供撤销或恢复。 | 保持首版操作语义简单明确。 | 用户确认后立即对资产查询不可见；服务端只为 OSS 清理和会话位置保留必要状态。 |
| 删除接口 | 单图和批量删除统一为 `POST /api/generation-images/delete`；请求始终提交用户手动勾选的 `imageIds`，删除一张时数组只有一个 ID。 | 前端没有一键全选全部历史图片的操作，不需要额外的删除范围语义；`POST` 请求体兼容性优于携带请求体的 `DELETE`。 | 仅按当前用户与 `imageIds` 批量标记删除，单图与多图复用同一删除链路。 |
| 删除接口重复请求 | 删除接口幂等；已删除图片的重复删除请求仍返回成功。 | 网络可能在服务端已提交删除后丢失响应，前端重试不应得到“删除失败”的误导。 | 删除条件更新未命中已删除状态时按成功处理，不重复安排无意义的清理。 |
| 删除成功边界 | 数据库提交图片已删除状态后即向用户返回成功；立即停止资产展示和签发 URL，OSS 对象改由后台异步永久清理。 | 数据库事务不能与 OSS 删除原子提交；不应因临时网络故障让用户反复看到或重复删除图片。 | 删除模型需要清理状态和失败重试；OSS 清理失败不恢复用户可见性。 |
| OSS 清理触发方式 | 使用独立定时扫描待清理图片，不复用 RabbitMQ/Outbox 或新增消息类型。 | 删除量低且流程独立；定时扫描简单，并可在应用重启后按数据库状态继续执行。 | 新增清理调度任务与待清理状态查询。 |
| OSS 清理重试 | 默认每 1 分钟扫描待清理图片；失败后默认 10 分钟重试，不设重试上限，直至删除成功。 | 图片已对用户不可见，清理只影响存储回收；低频持续重试可避免复杂退避和人工处理链路。 | 扫描间隔、重试间隔和每批数量均配置化，清理记录保存尝试次数、安全错误摘要和下次重试时间；OSS 失败不恢复用户可见性。 |
| 活动任务限制 | 不需要额外限制。 | 资产仅来自已成功转存的图片，所属任务已经终态。 | 删除接口只处理可见的成功图片，不处理 `QUEUED` 或 `RUNNING` 任务。 |
| 删除状态存储 | 直接扩展 `generation_images`，不创建独立清理表。 | 每张图片只对应一个私有 OSS 对象，删除生命周期不需要独立实体。 | 增加 `deleted_at`、`oss_cleanup_status`、`oss_cleanup_attempt_count`、`oss_cleanup_available_at`、`oss_cleanup_last_error` 字段；清理状态仅为 `PENDING`、`SUCCEEDED`。 |
| 清理状态模型 | 不使用 `PROCESSING`、锁字段或崩溃回收逻辑。 | 单实例低频扫描下，保留 `PENDING` 可使进程崩溃后自然重试；OSS 删除幂等，可接受极少数重复调用。 | 扫描到期 `PENDING` 后直接调用 OSS；成功改 `SUCCEEDED`，失败保持 `PENDING` 并更新下次重试。 |
| 签名 URL 与缓存 | 每次资产列表请求即时签发该页所有图片的短期 URL；该页使用统一过期时间，响应设置 `Cache-Control: private, no-store`。任一图片签名失败时整页返回系统错误。 | 防止签名地址被持久化或返回部分不完整资产列表；签名期限继续复用统一 OSS 配置。 | URL 和过期时间不落库；前端遇到 URL 过期时重新请求列表。 |
| 后续发布边界 | 本迭代不引入发布状态或发布图片删除限制。迭代 4 在同一图片上增加审核状态与 `public_at`；删除私有资产不影响审核中或已发布图片。 | 避免迭代 3 预先耦合尚未存在的审核和社区数据模型。 | 当前删除接口只处理当前用户可见的私有生成图片；迭代 4 再调整对象清理条件。 |
| 查询认证与参数错误 | 资产查询和删除均要求 Bearer Access Token；无认证返回 `40100`。非法游标或超出范围的 `limit` 返回 `42200`；空列表正常返回成功。 | 保持现有认证和参数校验约定。 | 查询始终限制当前用户且过滤 `deleted_at IS NULL`。 |
| 查询与清理索引 | 资产列表使用 `(user_id, deleted_at, created_at, id)`；清理扫描使用 `(oss_cleanup_status, oss_cleanup_available_at)`。 | 分别匹配用户可见资产的游标分页和到期清理扫描。 | 迁移中替换现有 `(user_id, created_at)` 索引，并新增清理索引。 |
| 已删除图片快照 | 任务详情与会话快照保留已删除图片的原始位置。 | 删除不篡改生成历史，客户端仍能正确展示任务结果位置。 | 图片响应新增 `sourceIndex`；已删除图片仍返回 `imageId`、宽高和 `sourceIndex`，但 `url`、`urlExpiresAt` 为 `null`。 |
| 清理批处理 | 默认每批最多清理 100 张图片；单条失败不阻断同批其他图片。 | 防止积压清理占用过长时间，并隔离单个对象存储故障。 | 每张图片独立记录清理结果；OSS 对象不存在视为清理成功。 |

## 5. API 与数据变更约定

### 5.1 资产列表

`GET /api/generation-images?cursor=<opaque>&limit=36`

- 使用当前用户的 Bearer Access Token。
- `cursor` 可选；`limit` 默认 `36`、最大 `60`。
- `data` 固定为 `items` 与 `nextCursor`。`nextCursor` 为 `null` 表示没有更多数据，不返回总数。
- 游标基于最后一项的 `createdAt + imageId` 编码；响应按 `created_at DESC, id DESC` 返回。
- 服务端返回 UTC 时间；前端按 `Asia/Shanghai` 完成日期分组。

### 5.2 单图资产详情

`GET /api/generation-images/{imageId}`

- 仅限当前用户读取自己的未删除资产。
- 成功响应与资产列表中单个 `item` 的字段和签名 URL 规则完全相同，不新增第二套详情 DTO。
- 已删除、不存在或非所有者统一返回 `404`；发布失败官方消息的“查看作品”据此展示“该图片已删除”。

### 5.3 图片删除

`POST /api/generation-images/delete`

- 请求固定为 `{"imageIds":["101","102"]}`。`imageIds` 非空且不得重复，不设置业务数量上限；单图删除传入一个 ID。
- 不提供按当前用户全部历史图片删除的请求语义；前端只能提交用户手动勾选的图片 ID。
- 删除仅改变当前用户可见图片的数据库删除状态并安排 OSS 异步清理。
- 成功响应为 HTTP `200` 与 `{"code": 0, "message": "ok", "data": null}`。
- 已删除、他人或不存在的图片均按成功处理；不泄露资源存在性或归属。

### 5.4 任务与会话快照

- 已删除图片不得在资产列表、任务详情或会话查询中获得签名 URL。
- 任务详情和会话快照的图片项新增 `sourceIndex`。
- 已删除图片仍保留在结果数组中，返回 `imageId`、`sourceIndex`、宽高，且 `url`、`urlExpiresAt` 为 `null`。

### 5.5 数据库迁移

- [V4__add_generation_image_asset_deletion.sql](src/main/resources/db/migration/V4__add_generation_image_asset_deletion.sql)
- 迭代 4 的 V7 会新增单图资产详情接口所需实现，并在既有 `generation_images` 上增加收藏与发布内部字段；该迁移采用清空后的开发数据库结构切换，详见《收藏与发布模块》。

在 `generation_images` 增加：

- `deleted_at DATETIME(3) NULL`；
- `oss_cleanup_status VARCHAR(16) NULL`，仅使用 `PENDING`、`SUCCEEDED`；
- `oss_cleanup_attempt_count INT UNSIGNED NOT NULL DEFAULT 0`；
- `oss_cleanup_available_at DATETIME(3) NULL`；
- `oss_cleanup_last_error VARCHAR(512) NULL`。

迁移同时将当前用户图片索引调整为 `(user_id, deleted_at, created_at, id)`，并增加 `(oss_cleanup_status, oss_cleanup_available_at)` 清理索引。

### 5.5 清理配置与可靠性

- 默认扫描间隔为 1 分钟、失败重试间隔为 10 分钟、每批数量为 100；三项均通过配置管理。
- 每张图片独立清理。OSS 返回对象不存在时标记 `SUCCEEDED`；其他失败记录安全错误摘要并等待下次重试。
