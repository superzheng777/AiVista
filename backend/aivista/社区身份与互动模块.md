# AiVista 社区身份与互动基础模块

## 已确认的图片与点赞响应契约

`ImageDTO` 保持为图片本体，不携带作者昵称或头像；保留既有图片字段，并新增 `authorId`、`likeCount`、`likedByCurrentUser`。匿名读取时 `likedByCurrentUser=false`。灵感列表直接返回 `ImageDTO[]`；点赞列表每项为 `{ image: ImageDTO, likedAt }`。作者资料仅在用户打开图片详情后，使用 `GET /api/users/{authorId}` 获取。

点赞与取消点赞接口成功时返回 `204 No Content`，没有 `ApiResponse` 响应体。

点赞列表按 `generation_image_likes.liked_at DESC, image_id DESC` 排序：先查询当前仍公开且版本匹配的点赞关系，再批量查询图片并按关系顺序组装 `{ image: ImageDTO, likedAt }`。`likedAt` 仅属于点赞关系，不属于图片实体或 `ImageDTO`。`GET /api/users/me/liked-publications` 仅本人可读；`PUT /api/users/me/liked-publications-visibility` 设置 `{ "publicVisible": boolean }` 并返回 `204`；`GET /api/users/{userId}/liked-publications` 仅在该用户公开时可读，私密和不存在统一不可见。

> 对应迭代：后端迭代 5——公开作者主页、关注与点赞
> 当前状态：已完成
> 维护规则：本文件确定公开身份、作品互动与隐私设置的领域事实；灵感流的分页和详情展示由迭代 6 文档承接。

## 当前实施进度

- 已完成：点赞关系、计数、版本隔离、点赞列表隐私及点赞互动通知；关注关系表与双方计数；公开作者资料与公开作品查询；关注/取消关注幂等接口；关注通知与最小 SSE Outbox 事件；互动与官方消息统一为固定 15 条游标列表、已读、软删除、批量删除与联合未读数接口；前端作者主页、关注状态、互动通知和乐观点赞回显均已接入。

## 1. 目标与范围

本迭代先建立所有社区页面共用的作者身份和互动数据，避免灵感页完成后再改图片 DTO、作者卡片、详情页与路由。

- 公开身份使用既有 `nickname`、`avatarUrl`、`bio`；公开资料还返回 `likesPublic`、粉丝数、关注数和获赞数。`loginName`、认证会话和其他账户数据永不公开。
- 个人主页与他人主页展示相同的公开资料、粉丝数、关注数、获赞数和已发布作品；自己的页面只额外显示资料编辑入口与隐私设置。
- 支持关注/取消关注、点赞/取消点赞；用户可以给自己或他人的已公开作品点赞。
- 点赞作品列表默认仅自己可见；用户可主动公开，此设置不影响点赞数、作品点赞状态或自己的可见性。
- 不实现灵感全站流、作品公开详情、关键词搜索、热门排序、推荐或评论；点赞产生的作者互动消息与其 SSE 提示属于本迭代范围。

## 2. 公开资料与主页

| 功能 | 方法与路径 | 契约 |
| --- | --- | --- |
| 公开作者资料 | `GET /api/users/{userId}` | 匿名可读，返回 `id`、`nickname`、`avatarUrl`、`bio`、`followerCount`、`followingCount`、`receivedLikeCount`、`viewerFollowing`、`likesPublic`。 |
| 作者已发布作品 | `GET /api/users/{userId}/publications` | 匿名可读，只返回作者当前 `APPROVED` 且 `public_at` 非空的作品，按 `public_at DESC, id DESC` 返回完整列表；与当前我的发布、资产列表保持一致。 |
| 作者公开点赞列表 | `GET /api/users/{userId}/liked-publications` | 匿名可读；仅当作者选择公开时，按 `liked_at DESC, image_id DESC` 返回已点赞、当前仍 `APPROVED` 且 `public_at` 非空的完整作品列表；下架作品直接过滤，否则统一返回 `40401`。 |
| 我的点赞列表 | `GET /api/users/me/liked-publications` | 仅认证用户；仅返回当前仍 `APPROVED` 且 `public_at` 非空的有效点赞作品，按 `liked_at DESC, image_id DESC` 排序。作品下架后不保留占位，刷新后自然消失。 |
| 更新点赞列表可见性 | `PUT /api/users/me/liked-publications-visibility` | 认证用户设置 `{ public: boolean }`；只影响他人是否可读取点赞列表，成功返回 `204 No Content`。 |

- `/users/{userId}` 使用既有稳定用户 ID（HTTP 中为字符串）作为前端统一作者主页路由；不对 ID 加密或可逆混淆，不得使用可变昵称或登录名作为身份标识。公开访问治理依赖限流，而不是隐藏 ID。
- `viewerFollowing` 对匿名访问固定为 `false`；已登录访问按当前查看者与作者的关系返回。
- 同一用户查看自己的公开资料也走公开资料契约，确保自己与他人看到的资料字段一致。
- 前端自己的主页也使用 `/users/{currentUserId}`；如保留旧个人主页路径，只作为兼容跳转，不再维护另一套页面或数据契约。

## 3. 关注与点赞

| 功能 | 方法与路径 | 契约 |
| --- | --- | --- |
| 关注作者 | `PUT /api/users/{userId}/follow` | 仅认证用户；确保已关注，重复请求成功且不重复计数；禁止关注自己，返回业务校验错误。成功返回 `204 No Content`。 |
| 取消关注 | `DELETE /api/users/{userId}/follow` | 仅认证用户；确保未关注，未关注时也按成功处理，成功返回 `204 No Content`。 |
| 点赞作品 | `PUT /api/inspirations/{imageId}/like?publicationVersion={version}` | 仅认证用户；`publicationVersion` 为必填十进制字符串，确保点赞的是查看者看到的公开周期。仅当前公开作品可点赞；允许点赞自己的作品；重复请求成功且不重复计数，成功返回 `204 No Content`。图片不存在、已下架或版本不匹配均统一返回不存在/不可操作错误。 |
| 取消点赞 | `DELETE /api/inspirations/{imageId}/like?publicationVersion={version}` | 仅认证用户；`publicationVersion` 为必填十进制字符串，确保只取消指定公开周期。未点赞时也按成功处理，成功返回 `204 No Content`；不会影响重新发布后的其他周期。 |

- 分别使用 `user_follows(follower_user_id, following_user_id)` 与 `generation_image_likes(user_id, image_id, publication_version, liked_at)` 关联表。关注关系以 `(follower_user_id, following_user_id)` 唯一；点赞关系以 `(user_id, image_id, publication_version)` 唯一，既保证同一公开周期的幂等，也允许重新发布后重新点赞。点赞表只保存有效关系，不保存下架占位；至少建立 `(user_id, liked_at DESC, image_id DESC)` 与 `(image_id, publication_version)` 索引。
- `generation_images` 维护 `like_count`，并进入统一图片 DTO 的 `likeCount` 字段；图片 DTO 同时携带 `likedByCurrentUser`、`authorId`、`authorNickname`、`authorAvatarUrl`。匿名访问的 `likedByCurrentUser=false`。
- `likedByCurrentUser` 必须通过当前请求的查看者与图片集合的一次批量关联查询得到，禁止对列表中的每张图片额外查询点赞表（N+1）。
- 用户资料维护 `follower_count`、`following_count`、`received_like_count` 三个计数器，分别进入公开资料的 `followerCount`、`followingCount`、`receivedLikeCount` 字段；关联表仍是关系存在性的事实来源。允许自赞，且图片 `like_count`、作者 `received_like_count` 均包含自赞。
- 关注/取消关注在同一事务中写入或删除 `user_follows` 并同步增减双方的关注计数；点赞/取消点赞在同一事务中写入或删除 `generation_image_likes`、原子增减图片 `like_count` 与作者 `received_like_count`。仅关系表实际受影响时才改计数，重复请求不改变计数；计数不得为负。首版要求关系与两个计数强一致，不使用缓存、异步聚合或计数分片。
- 仅 `APPROVED` 且 `public_at` 非空且版本匹配的当前公开作品可点赞；自己发布列表中的审核中作品不提供点赞交互。点赞、取消点赞与撤销发布统一按“图片行 → 点赞关系 → 作者用户行”顺序完成事务，防止并发下的死锁和下架后新增点赞。
- 撤销发布时锁定图片行，删除当前 `publication_version` 的全部点赞关系并取得实际删除数 `N`，将图片 `like_count` 归零，并从作者 `received_like_count` 原子扣除 `N`。正常状态下 `N` 必须等于撤销前 `like_count`；不相等视为内部一致性错误并回滚、告警。撤销后作品立即从灵感列表、作者公开作品列表和所有点赞列表移除；重新公开必须重新提交审核，且是没有点赞的新公开周期。
- 点赞接口在认证后、写入事务前执行服务端令牌桶限流：同时限制 `(userId, imageId)` 的状态变更频率和用户全站总频率，`PUT` 与 `DELETE` 都计入。单作品桶容量为 4、每 3 秒恢复 1 个令牌；用户全站桶容量为 10、每秒恢复 1 个令牌。首版使用有界、可过期的单实例内存状态；超限返回 `429`、`LIKE_RATE_LIMITED` 与 `Retry-After`，不访问点赞表。未来多实例部署时优先以 Redis 替换限流状态，而非改动点赞关系和计数语义。
- 当有效点赞关系首次创建且点赞者不是作品作者时，在同一事务中创建一条作者的互动消息与对应 SSE Outbox 事件；重复 `PUT`、取消后再点赞、以及自赞均不新增消息。取消点赞或撤销发布不撤回已创建的互动消息。
- 迭代 5 沿用迭代 4 的整列表返回策略，不在作者主页单独引入分页；全站灵感流的游标分页留待迭代 6 统一设计。
- 审核通过的“我的发布”作品与公开灵感作品是同一公共作品：使用相同图片详情字段和点赞规则。仅作者查看时，详情额外提供撤销发布等管理能力；审核中作品仅作者可见，提供审核状态与取消审核能力，不属于公共作品详情。
- 不提供公开图片详情的独立 URL 或直接访问接口。公开作品详情只能由已加载的作品列表打开，使用列表中的完整图片 DTO；打开时仅额外请求一次作者公开资料。资产详情不展示作者资料，不请求作者公开资料。

## 4. 互动消息与 SSE

- 复用 `user_notifications` 作为通用消息表。官方审核消息使用 `category = OFFICIAL`；点赞消息使用 `category = INTERACTION`、`event_type = IMAGE_LIKED`，并保存 `actor_user_id`、`image_id` 与 `publication_version`。互动列表读取时关联点赞人的当前公开昵称、头像和当前公开作品 DTO，不保存资料快照或独立缩略图 URL。仅当图片当前 `publication_version` 等于通知记录版本且资源仍可用时才返回 `image`；作品下架后重新发布为新周期时，旧通知返回 `image: null`。列表中的图片使用懒加载；打开详情时仍有效的 URL 直接复用，URL 已到期、无效或距当前不足 30 秒时，仅刷新该图片：已发布作品调用 `GET /api/inspirations/{imageId}`，资产场景调用 `GET /api/generation-images/{imageId}`。加载失败不得自动刷新消息列表或重复签发 URL。
- 对互动点赞消息建立 `(recipient_user_id, actor_user_id, image_id, publication_version, event_type)` 唯一约束。软删除消息不释放该约束：同一点赞人对同一作品的同一公开周期最多通知一次，取消后再点赞不会重新刷出消息或 SSE。
- 点赞事务只在成功插入互动消息后写入 `INTERACTION_NOTIFICATION_CREATED` Outbox 事件。SSE 事件名为 `interaction.notification.created`，最小载荷为 `notificationId`；SSE 只提示客户端失效缓存，离线、断线与重复事件均由 REST 快照对账。
- 消息中心分为“互动”和“官方消息”两个列表。互动消息 API 使用 `/api/users/me/interaction-notifications` 及同一路径下的已读、全部已读、单条删除接口；官方消息继续使用既有 `/api/users/me/official-notifications` 接口。
- 未读角标统一使用 `GET /api/users/me/notifications/unread-count`，一次返回 `officialUnreadCount`、`interactionUnreadCount` 与 `totalUnreadCount`。收到任一消息创建 SSE 后统一失效该查询；打开某个页签时才加载对应列表。
- 打开“互动”页签不自动标记已读；用户点击消息正文或作品缩略图时才标记该条已读。作品仍可访问时，作者可打开自己的图片详情；作品已下架且资源不可用时保留消息但提示“作品已不可用”，不提供公共详情跳转。
- 互动消息按 `(created_at DESC, id DESC)` 提供游标分页，固定每页 15 项，不接受客户端修改 `limit`。SSE 只使最新第一页和联合未读数失效；客户端以通知 ID 合并最新页，不要求服务端为已加载的后续页重排或推送完整列表。
- 互动消息默认永久保留，不设自动过期或后台清理；仅接收者可手动软删除。除单条 `DELETE /api/users/me/interaction-notifications/{notificationId}` 外，提供 `POST /api/users/me/interaction-notifications/deletions`，请求体为 `{ notificationIds: string[] }`，用于批量软删除勾选项。请求只处理当前用户未删除的互动消息；不存在、非本人或已删除的 ID 按已满足目标状态处理，重复调用保持成功。删除不影响点赞关系、作品/作者计数或官方消息；若删除未读项，联合未读数随之减少。

## 5. 隐私默认值

点赞列表默认 `private`。新用户和现有用户的迁移默认值均为仅自己可见；只有用户显式设置 `public` 后，他人才能读取该列表。由公开切换为私密后，后端立即停止提供列表并统一返回不存在；已加载旧页面由客户端下一次刷新或后台重拉移除。

## 6. 验收条件

1. 任意已登录或匿名用户可读取公开资料与作者已发布作品；登录名不会出现在公开响应。
2. 自己与他人页面使用同一公开资料字段，粉丝数、关注数和获赞数一致。
3. 关注、取消关注、点赞、取消点赞均在重复请求下保持最终状态和各级计数正确；图片列表不会因 `likedByCurrentUser` 产生 N+1 查询。
4. 隐藏点赞列表的用户不会向他人暴露该列表；所有点赞列表均不含下架作品，旧详情页的点赞请求不会作用于重新发布后的新公开周期。
5. 他人首次点赞作者作品后，作者离线时可在互动列表读取持久化消息，在线时可经 SSE 及时刷新未读数；同一点赞人反复取消、再点赞不会重复产生互动消息。
