# AiVista 后端文档规范

> 适用范围：AiVista 后端项目的项目总览、工程基础文档和全部业务模块文档
> 当前状态：生效中
> 维护规则：本规范变更前必须先讨论确认。所有代码、测试、接口、数据结构和运行约定的变更，按影响范围同步更新对应文档。

## 1. 文档体系与职责

| 文档 | 职责 |
| --- | --- |
| `后端项目开发文档.md` | 项目总览：一期目标、跨模块边界、迭代路线和文档索引；不复制模块实现细节。 |
| `工程基础开发文档.md` | 工程运行、测试、通用配置、部署与联调约定；不承载业务模块设计。 |
| `中文业务名模块.md` | 同一文件贯穿设计、实施和完成，记录模块的设计过程与最终参考信息。 |
| `后端文档规范.md` | 本规范，约束所有文档的职责、状态、结构和同步方式。 |

每个业务模块只保留一份模块文档，不创建独立的“开发过程文档”和“最终文档”。模块完成时，将同一文件整理为最终参考文档，并保留仍影响维护的关键决策与实施摘要。

## 2. 状态与准入条件

业务模块只使用以下状态：

```text
设计中 → 实施中 → 已完成
```

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| 设计中 | 正在确认范围和方案，不能开始编码。 | 已建立模块文档，待确认项已明确列出。 |
| 实施中 | 设计已足以支撑本迭代编码。 | 目标、范围、约束、关键决策、数据模型/配置、API/权限、异常处理和验收标准已确认。 |
| 已完成 | 当前迭代范围已交付。 | 代码完成；文档整理为最终参考；测试和必要人工验收有记录；未覆盖项已说明且确认不阻塞。 |

模块后续新增能力应建立新的迭代模块文档，不回退已完成模块状态。

## 3. 统一元信息与命名

业务模块文档采用“中文业务名 + 模块.md”，例如 `用户模块.md`、`图像生成任务模块.md`。

模块文档标题下固定使用：

```md
> 对应迭代：迭代 X——模块名称
> 当前状态：设计中 / 实施中 / 已完成
> 维护规则：本文……；代码、测试和文档必须同步修改。
```

不维护“最后同步日期”或文档版本号，具体修改历史以 Git 为准。

## 4. 业务模块统一结构

所有业务模块使用以下一级章节。设计中阶段未确定的内容必须明确标注“待确认”，不得提前写入接口、表字段、状态或实现方案。

```text
1. 目标与范围
2. 已确认约束
3. 关键决策记录
4. 实施计划与进度
5. 设计与实现
6. 数据模型与配置
7. API 与权限
8. 异常场景、可靠性与安全
9. 测试与验收
10. 后续边界
```

### 4.1 关键决策记录

使用以下表格，只记录最终有效且影响实现、维护或扩展的结论；已推翻的临时方案不保留。

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |

### 4.2 实施计划与进度

使用以下表格，状态只使用“待开始、进行中、已完成、阻塞”。模块完成后压缩为关键实施摘要和验证结果，不保留流水账。

| 小步目标 | 状态 | 完成内容或当前阻塞 | 验证方式/结果 |
| --- | --- | --- | --- |

### 4.3 实现位置

实施中和已完成模块的“设计与实现”章节必须列出关键实现位置：

| 职责 | 关键类/文件 | 说明 |
| --- | --- | --- |
| 接口入口 | `…Controller` | 请求、鉴权与响应。 |
| 核心业务 | `…Service` | 业务规则与事务边界。 |
| 数据访问 | `…Mapper` / Flyway | SQL、约束与迁移。 |
| 异步/外部集成 | `…` | MQ、对象存储或第三方服务。 |

设计中模块不填写不存在的代码位置。

## 5. 工程基础文档结构

工程基础文档同样使用统一元信息和维护规则，但一级章节固定为：

```text
1. 项目入口与常用命令
2. 基础能力
3. 工程结构与关键代码位置
4. 通用开发约定
5. 配置与环境
6. 部署与联调
7. 测试与验收
8. 后续工程边界
```

## 6. 项目总览文档结构

项目总览固定只承担以下职责：

```text
1. 文档体系与索引
2. 一期目标
3. 跨模块已确认业务边界
4. 迭代路线与状态
5. 文档同步规则
6. 后续方向
```

数据表、接口、异常场景、实现位置和测试细节只保留在对应模块文档。

## 7. 测试、验收与同步规则

模块“测试与验收”章节必须区分：

| 类型 | 记录要求 |
| --- | --- |
| 自动化测试 | 测试范围、执行命令和结果。 |
| 人工/真实环境验收 | 验收链路、环境类型和结果；不得记录密钥、Token、临时 URL 等敏感数据。 |
| 未覆盖项 | 未执行原因、是否阻塞当前迭代和后续补充条件。 |

文档按影响同步，不机械修改全部文件：

- 业务规则、数据结构、接口、配置、可靠性或测试变化：更新对应模块文档。
- 迭代状态、模块边界或文档索引变化：同时更新项目总览。
- 工程启动、通用配置、部署约定变化：更新工程基础文档。
- 未受影响的模块文档不修改。

敏感信息不得写入任何文档，包括密码、Token、真实 API Key、OSS AccessKey、RabbitMQ 密码、临时 URL、签名 URL和完整生产提示词。
