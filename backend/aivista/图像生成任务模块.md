# AiVista 图像生成任务模块

> 对应迭代：普通图像生成任务（文生图与图生图）
> 当前状态：已完成；资产、发布与社区交互已接入同一图片资产模型
> 用途：本文是后续维护普通文生图代码时的实现说明书。记录已确认的流程、约束和异常处理；代码、测试或规则变化时必须同步修改本文档。

## 1. 范围、完成边界与后续演进

本模块已完成普通文生图、图生图的创建、异步执行、私有存储、查询、取消、发布、点赞与通知闭环。

已完成能力：

- 持久化会话、提示词历史、普通文生图任务、用户同意规则、并发任务和每日额度控制。
- RabbitMQ Outbox 可靠投递、消费者手动 ACK、排队超时和消费失败有限收敛。
- 百炼 Qwen-Image 调用、单实例调用门控、有限重试、结果未知保护和服务商结果快照恢复。
- 私有 OSS 原图流式转存、临时本地上传参考图、服务端持久化 WebP 派生图、统一图片 DTO 的缩略图与展示图签名 URL、任务/会话查询、会话改名、取消任务和 SSE 通知。
- 使用同一 `image_assets` 资产表承载生成结果和上传参考图；支持 0～3 张有序参考图作为图生图输入。
- 作品发布审核、公开灵感列表、点赞、收藏和搜索索引均基于 `image_assets` 与独立的发布/点赞关系表。

不属于当前模块：局部重绘和遮罩、Agent 步骤和工具调用、付费和推荐。

局部重绘及 Agent/工作流可以在后续独立迭代。Agent 应通过内部图像任务入口创建相同的 `generation_tasks`，而非旁路调用模型；来源图片、遮罩和步骤在新增能力时通过 Flyway 扩展，不改变现有任务语义。

## 2. 核心架构与执行流程

### 2.1 组件职责

| 组件 | 职责 |
| --- | --- |
| MySQL | 保存会话、消息、任务、图片、额度、同意记录和 Outbox；是唯一任务真相来源。 |
| RabbitMQ | Durable Direct Exchange `aivista.generation.commands` 按同名 Routing Key 路由至 `generation.task.execute` 与 `generation.image.transfer` 两条 Durable Quorum Queue。 |
| 阿里云百炼 | 使用同步 Qwen-Image API 生成图片。项目的异步性由 RabbitMQ 工作器提供。 |
| 阿里云 OSS | 保存项目拥有的私有 PNG 原图。 |
| SSE | 向在线客户端通知任务状态变化；不作为状态真相或消息回放渠道。 |

### 2.2 正常链路

```text
POST 创建任务
  → 同一 MySQL 事务：会话、提示词消息、任务、每日额度、`GENERATION_TASK_EXECUTE` 与 `GENERATION_TASK_STATUS_CHANGED` 通用 Outbox 事件
  → Outbox 经显式 Direct Exchange 投递生成命令，收到 Publisher Confirm 且消息未被退回后标记已发布
  → 生成消费者领取 QUEUED 任务为 RUNNING，并在同一事务写入状态 Outbox
  → 写入 provider_call_started_at 后调用百炼
  → 同一 MySQL 事务：保存临时 URL 快照、RUNNING → TRANSFERRING、图片转存 Outbox、状态 Outbox
  → ACK 生成消息；前端显示“图片已生成，正在保存”
  → Outbox 将转存命令投递 `generation.image.transfer`
  → 转存消费者从数据库快照读取临时 URL，将响应流转存为私有 OSS 原图，并由 OSS 服务端生成两种 WebP 派生图
  → 同一 MySQL 事务：图片记录、任务终态、`GENERATION_TASK_STATUS_CHANGED` 通用 Outbox 事件
  → ACK 转存消息；状态事件再分发给当前实例的 SSE 连接，REST 返回私有 OSS 签名 URL
```

任务创建接口立即返回 `202 Accepted`。客户端在提交前必须先建立用户级 SSE；创建响应提供新会话和任务标识，前端据 `sessionId` 进入会话并读取会话消息，以展示初始 `QUEUED`。后续状态由 SSE 实时推动；首次连接、重连或进入生成页时，REST 会话列表与当前会话消息快照负责状态恢复。

### 2.3 消费者与调用许可

- 生成队列 `generation.task.execute` 使用 `25` 个消费者；转存队列 `generation.image.transfer` 使用 `15` 个消费者。两者均为 Durable Quorum Queue、持久化消息、`prefetch=1` 和手动 ACK，总消费者线程仍为 `40`。
- 百炼调用门控当前为最多 `25` 个调用许可、每秒最多启动 `2` 次调用。
- 生成消费者只负责调用百炼并可靠创建转存命令；转存消费者只负责来源流、OSS 和图片终态。两个阶段分别 ACK，互不占用对方消费者线程。
- Outbox 发送使用 Publisher Confirm、Mandatory 与 Publisher Return；只有交换机确认且消息成功路由到队列后，事件才标记为 `PUBLISHED`。
- `RUNNING` 表示消费者已领取任务，不表示已经调用百炼。`provider_call_started_at` 才是“请求可能已发出”的经济与幂等边界。

## 3. 任务、会话和请求约束

### 3.1 会话与历史

- 用户首次提交不传 `sessionId` 时，在同一事务创建会话、消息和任务；会话默认标题由首条正向提示词截取生成，可后续改名。
- 同一会话同一时间只能有一个 `QUEUED`、`RUNNING` 或 `TRANSFERRING` 任务；创建已有会话任务时锁定会话行检查。
- 同一用户跨会话、页面和设备最多四个未完成任务；创建任务时锁定用户行并统计状态。
- 每轮保存正向、负向提示词消息；每个任务的最终提示词严格等于本轮输入，历史消息只用于会话记录展示，不作为模型生成上下文。会话可用于归类相关创作记录，但不要求围绕单一图片主题。
- 正向提示词最大 1000 个字符、负向提示词最大 500 个字符。输入超长直接拒绝，不截断。

### 3.2 模型参数

模型固定 `qwen-image-2.0`，任务保存完整标识 `bailian/qwen-image-2.0`；`prompt_extend` 由任务快照决定，默认开启，客户端可按次关闭。无参考图时按文生图请求模型；有 `inputAssetIds` 时按给定顺序将已冻结的参考图 URL 与提示词一起发送，模型自行处理单图编辑或多图融合。

| `aspectRatio` | 百炼 `size` |
| --- | --- |
| `1:1` | `2048*2048` |
| `16:9` | `2688*1536` |
| `9:16` | `1536*2688` |
| `4:3` | `2368*1728` |
| `3:4` | `1728*2368` |

`imageCount` 只能为 `1`～`6`。`promptExtend` 为可选布尔值，控制百炼是否优化提示词，缺省为 `true`。客户端不能传模型、最终提示词、宽高、百炼参数或 OSS 地址。

### 3.3 幂等与每日额度

- 创建任务必须带 UUID v4 `Idempotency-Key`。
- 创建型命令统一使用项目级 `idempotency_records` 防重表，幂等范围为当前用户、操作范围 `GENERATION_TASK_CREATE` 和该键。相同键、相同规范化请求指纹重放首次 `202` 接收响应，不重复创建会话/消息/任务或占用额度；相同键、不同指纹返回 `409 IDEMPOTENCY_KEY_CONFLICT`。
- 防重记录、会话、提示词消息、任务、每日额度和 Outbox 必须在同一事务中写入。实施通用防重能力时直接删除 `generation_tasks` 上的旧幂等键、请求指纹和相关唯一索引，不做数据或代码兼容；当前开发环境单实例重启后执行迁移，不存在滚动部署兼容问题。
- `GENERATION_TASK_CREATE` 防重记录保留 30 分钟；若同键在过期后再次提交，创建事务在锁定原记录后先删除再创建，避免唯一索引冲突。每 10 分钟再按 `expires_at` 索引分批删除最多 1,000 条过期记录，作为存储回收。前端结果未知时仅保留原请求和 key 最多 10 分钟。
- 每日额度按 `Asia/Shanghai` 自然日计算，单用户每天最多请求 12 张，在任务创建事务中原子占用。
- `quota_refunded_at` 保证同一任务最多返还一次额度。

### 3.4 用户协议与第三方数据处理同意

生成与发布不再分别收集同意，而是共用版本化 `USER_AGREEMENT`。注册时必须提交当前 `agreementPolicyVersion`，服务端先校验版本、创建用户后在同一事务写入同意记录；登录或会话恢复响应以 `userAgreementConfirmed` 告知当前状态。若旧用户尚未同意当前版本，客户端在进入业务页面前展示强制确认弹窗，并以 Bearer Token 提交确认。服务端维护完整文案、版本、文案 SHA-256 摘要与确认时间；只有实际展示的当前版本才可提交。

协议必须明确告知：本次生成的正向/负向提示词会发送至阿里云百炼，历史会话消息仅由 AiVista 保存并展示，不作为本次模型输入；发布标题与描述会发送至阿里云内容安全增强版 PLUS 审核；项目会保存会话、任务、图片和同意记录；用户不应输入敏感个人信息。`UserAgreementAccessFilter` 在 Bearer Token 校验后统一拦截未同意或版本过期用户，返回 `409 GENERATION_CONSENT_REQUIRED`；仅放行认证接口、`GET /api/policies/user-agreement`、`POST /api/users/me/consents/user-agreement` 与匿名灵感页，直至确认当前版本。生成或发布审核任务不得写入会话、任务、额度或 Outbox。

## 4. 状态机、取消和额度

### 4.1 状态机

```text
QUEUED → RUNNING → TRANSFERRING → SUCCEEDED | PARTIALLY_SUCCEEDED | FAILED
   ↑         │           │
   └─────────┘           └──────────────────────────────→ CANCELLED
   可重试模型错误：RUNNING → QUEUED，retry_count + 1
   QUEUED / RUNNING ────────────────────────────────────→ CANCELLED | FAILED
```

状态变更均使用带前置状态和 `task_version` 的条件更新；影响行数为 `1` 才代表本工作器获得执行权，终态不可再次执行。数据库事务不得跨越百炼调用或图片响应流至 OSS 的转存过程。

每次用户可见状态变化都在同一事务写入 `GENERATION_TASK_STATUS_CHANGED`。状态事件保存变化发生时的 `task_status`、`task_version` 和模型重试次数，Dispatcher 不使用任务当前状态覆盖或丢弃已被后续版本取代的中间事件。

`TRANSFERRING` 表示百炼结果和后续转存命令已经可靠持久化。此时 REST 与 SSE 不返回百炼临时 URL，图片列表保持为空；前端显示“图片已生成，正在保存”。进入终态后，任务详情与会话消息中的每张图片均返回统一图片 DTO：会话网格使用 `thumbnail`，详情复用 `display`；`original` 不属于普通 DTO，只能由当前认证作者通过 `GET /api/generation-images/{imageId}/original-download` 临时取得。每页会话消息最多返回 5 条。用户删除资产后，历史会话仍保留同一图片 DTO 与 `sourceIndex`，但 `thumbnail` 与 `display` 均为 `null`。

- 所有请求图片都成功转存：`SUCCEEDED`。
- 至少一张成功转存：`PARTIALLY_SUCCEEDED`。
- 没有图片成功转存：`FAILED`。
- 每次状态变化递增 `task_version`；客户端只接受比本地更新的版本。

### 4.2 取消竞争处理

| 场景 | 处理 |
| --- | --- |
| `QUEUED`，或已 `RUNNING` 但未写入 `provider_call_started_at` | 直接 `CANCELLED`，在同一事务返还一次额度；迟到 MQ 消息直接 ACK。 |
| 已写入 `provider_call_started_at` | 直接 `CANCELLED`，不返还额度。同步百炼请求不能被首版中断，返回结果必须丢弃。 |
| 已进入 `TRANSFERRING` | 直接 `CANCELLED`，不返还额度并清除服务商快照；迟到转存消息直接 ACK。 |
| 已上传 OSS、终态提交时发现已取消 | 不写入图片或成功终态，并立即尽力删除刚上传的对象；删除失败记录不含临时 URL 的安全日志。 |
| 重复取消 `CANCELLED` | 幂等成功，返回当前快照。 |
| 取消 `SUCCEEDED`、`PARTIALLY_SUCCEEDED`、`FAILED` | `409 TASK_ALREADY_FINISHED`。 |

### 4.3 额度返还规则

`provider_call_started_at` 是唯一经济边界，而非消费者领取或 `RUNNING` 状态。以下失败，以及调用前取消，返还一次本次请求图片数量：

`PROVIDER_CALL_OUTCOME_UNKNOWN`、`PROVIDER_CONNECTION_FAILED`、`PROVIDER_RATE_LIMITED`、`PROVIDER_SERVICE_UNAVAILABLE`、`QUEUE_DELIVERY_FAILED`、`QUEUE_TIMEOUT`、`QUEUE_CONSUMPTION_FAILED`。

调用开始后的用户取消、内容安全、参数/鉴权/配置错误、服务商配额或计费问题、图片转存全部或部分失败、其他业务失败和部分成功不返还。每日额度用于约束已经发起的模型生成成本，不代表最终成功保存的图片数量。

## 5. 百炼错误、重试和快照恢复

### 5.1 调用约定

- 每次请求带 `X-DashScope-Wait-Timeout: 30`。该值只允许百炼在 `Throttling.BurstRate` 情况下最多服务端排队 30 秒。
- HTTP 连接超时 `5s`，非流式读取超时 `330s`。
- HTTP 客户端不自动重试或重定向，必须校验证书和主机名。

### 5.2 错误决策表

| 识别结果 | 处理 | 自动重试 | 最终稳定失败码 | 返还额度 |
| --- | --- | --- | --- | --- |
| DNS/TCP/TLS 未建立，确认 HTTP 请求未发出 | 清空调用开始标记，重新排队 | 最多 3 次，`1s/2s/4s + 0~1s` 抖动 | `PROVIDER_CONNECTION_FAILED` | 是 |
| `429 Throttling`、`Throttling.RateQuota`、`Throttling.BurstRate` | 重新排队 | 同上 | `PROVIDER_RATE_LIMITED` | 是 |
| 明确 HTTP `5xx` | 重新排队 | 同上 | `PROVIDER_SERVICE_UNAVAILABLE` | 是 |
| `Throttling.AllocationQuota`、`CommodityNotPurchased`、免费额度耗尽、账单问题 | 直接失败 | 否 | `PROVIDER_QUOTA_UNAVAILABLE` | 否 |
| `400 DataInspectionFailed` | 直接失败 | 否 | `PROVIDER_CONTENT_REJECTED` | 否 |
| 其他参数/输入/尺寸错误，或鉴权、业务空间、模型、端点错误 | 直接失败 | 否 | `PROVIDER_CONFIGURATION_ERROR` | 否 |
| 已连接后的读取超时、连接中断、结果无法确认 | 直接失败 | 否 | `PROVIDER_CALL_OUTCOME_UNKNOWN` | 是 |

可重试错误每次均重新经过调用门控，不重复占用用户额度。最大模型重试次数由 `app.generation.bailian.max-retries` 配置，当前为 `3`；首次调用不计入重试次数。调用结果未知不得重试，以避免重复生成与重复计费。

### 5.3 服务商结果快照

百炼返回图片临时 URL 后，在同一短事务保存 `provider_request_id`、`source_index` 和临时 URL 快照，将任务更新为 `TRANSFERRING`，并写入转存 Outbox 与状态 Outbox。快照仅供后端转存消费者恢复使用，不进入 MQ、客户端或普通日志，全部转存完成后立即清除，最长受百炼临时 URL 24 小时有效期约束。

转存期间进程崩溃时，消息未 ACK，RabbitMQ 重投后从 `TRANSFERRING` 快照恢复，不再调用百炼。确定性对象键使重投覆盖同一 OSS 对象，`(task_id, source_index)` 唯一约束避免重复创建图片记录。生成消息在事务提交后、ACK 前丢失连接时，重投读取到 `TRANSFERRING` 后直接 ACK。

转存工作器在完成阶段失去任务所有权时，不会删除确定性 OSS 对象键，避免迟到副本误删已被另一工作器成功提交的资产；只有取消状态赢得竞争时才清理本次未入库对象。极端竞争下宁可留下可后续清理的孤儿对象，也不破坏已成功资产。

## 6. Outbox、MQ 与排队失败

### 6.1 Outbox 规则

创建任务写入 `GENERATION_TASK_EXECUTE` 和初始 `GENERATION_TASK_STATUS_CHANGED`；以后每次任务状态变化都写入 `GENERATION_TASK_STATUS_CHANGED`。状态 Outbox 保存任务版本、状态和模型重试次数；SSE 事件不含提示词、临时 URL、签名 URL或密钥。

- `GENERATION_TASK_EXECUTE`：路由到 `generation.task.execute`；投递重试耗尽后，仅在任务仍为 `QUEUED` 且版本一致时收敛为 `FAILED + QUEUE_DELIVERY_FAILED` 并返还额度。
- `GENERATION_IMAGE_TRANSFER`：路由到 `generation.image.transfer`；消息只携带 Outbox ID、任务 ID 与任务版本。投递重试耗尽后，仅在同版本任务仍为未领取的 `TRANSFERRING` 时收敛为 `FAILED + IMAGE_TRANSFER_FAILED`，不返还额度。
- 两类执行事件均须同时满足 Publisher Confirm ACK 且没有 Mandatory Returned Message，才标记 `PUBLISHED`。Outbox 事件被领取为 `PROCESSING` 后持有 30 秒租约；分发实例在 Confirm 前异常退出时，后续扫描会将过期事件按原有退避规则重新排期。超过投递上限时，仍按对应命令的失败收敛规则处理。RabbitMQ 已接收但没有消费者属于队列积压，由各阶段排队超时规则处理。
- `GENERATION_TASK_STATUS_CHANGED`：只用于在线通知。没有 SSE 连接或写入失败不改变任务状态；事件可标记失败并记录安全日志。事件被领取为 `PROCESSING` 后持有 30 秒租约；分发实例在发送前异常退出时，后续扫描将其重新排期。重复通知由客户端按任务版本合并，REST 快照仍是最终对账来源。
- 所有类型的 `PUBLISHED` 事件保留 7 天后，每小时按 `(status, published_at, id)` 索引分批清理；`PENDING`、`PROCESSING` 与 `FAILED` 事件不自动删除。

### 6.2 消费失败与排队超时

| 场景 | 处理 |
| --- | --- |
| 每次进入 `QUEUED` 后超过 3 分钟未领取 | 按本次入队的 `updated_at` 收敛为 `FAILED + QUEUE_TIMEOUT`，返还额度并写状态 Outbox。 |
| 消息对应任务已终态、已取消或版本过期 | 直接 ACK，不执行模型。 |
| 消费器在百炼调用前处理异常，`x-delivery-count < 3` | `NACK + requeue`。 |
| `x-delivery-count >= 3`，且任务仍为调用百炼前的 `RUNNING` | 写入 `FAILED + QUEUE_CONSUMPTION_FAILED`、返还额度后 ACK。 |
| `x-delivery-count >= 3`，但调用已开始或任务不能条件更新 | 继续 NACK 重投，由任务执行逻辑按调用结果未知保护，不能误判为消费者失败。 |
| 无法解析的 MQ 消息 | 直接 ACK，避免无限循环。 |
| 转存消息等待消费者领取超过 2 分钟 | 仅在 `TRANSFERRING` 且 `transfer_started_at IS NULL` 时收敛为 `FAILED + IMAGE_TRANSFER_FAILED`，不返还额度；迟到消息 ACK。 |
| 转存消费者已领取 | 写入 `transfer_started_at`，不再受两分钟等待超时影响；来源下载与 OSS 上传分别受各自网络超时控制。 |
| 明确单图转存失败 | 记录任务 ID、来源序号和异常类型，继续同任务其他图片，无业务重试，最终部分成功或失败后 ACK。 |
| 转存消费者基础设施异常 | NACK 重投；达到消费上限且数据库可用时将对应 `TRANSFERRING` 任务收敛为失败后 ACK。 |

不配置队列消息 TTL、DLQ、人工重放或运维重放链路。最终失败由用户重新发起。

## 7. 数据模型与存储约定

Flyway 迁移是表结构唯一来源：V1～V15 保留历史演进以保证空库可顺序迁移；`V16__normalize_image_assets_and_generation_inputs.sql` 是当前资产模型切换点，创建新表后删除 `generation_images` 与 `generation_image_likes`；`V17__remove_publication_remix_flag.sql` 删除不再需要的发布二创开关。资源主键统一为 `BIGINT UNSIGNED`，HTTP 响应序列化为字符串；除每日额度业务日期外，时间统一为 UTC `DATETIME(3)`。

| 表 | 保存内容 | 关键约束/用途 |
| --- | --- | --- |
| `generation_sessions` | 用户会话、标题、最近消息时间与软删除时间。 | 按用户和最近消息查询；软删除后不再返回、不可继续写入消息/创建任务，但不级联删除任务、图片或配置。 |
| `generation_messages` | 每轮正向/负向提示词和会话内序号。 | `(session_id, sequence_no)` 唯一。 |
| `generation_tasks` | 用户/会话/消息归属、`TEXT_TO_IMAGE` 或 `IMAGE_TO_IMAGE` 操作、状态、版本、模型、最终提示词、提示词优化开关、尺寸、数量、重试次数、调用时间、转存领取时间、失败码和快照。 | `source_message_id` 唯一；`transfer_started_at` 区分等待转存与正在转存；创建幂等由 `idempotency_records` 统一承担。 |
| `image_assets` | 已成功生成的图片对象组，或用户上传的临时参考图。 | 生成结果通过 `(origin_task_id, source_index)` 唯一；上传资产以 `origin=UPLOADED`、到期时间和清理状态管理。 |
| `generation_task_input_assets` | 图生图任务冻结后的有序输入资产。 | `(task_id, position)` 唯一；任务执行时只读取其冻结引用，避免用户后续调整资产选择影响已创建任务。 |
| `image_publications` | 图片资产的审核状态、版本、标题、描述、公开时间和点赞计数。 | `asset_id` 唯一；仅 `APPROVED` 且 `public_at` 非空时属于公开作品。 |
| `image_asset_likes` | 用户对公开作品当前发布版本的点赞关系。 | 点赞关系绑定发布版本；撤销发布会删除当前版本的关系并回收计数。 |
| `outbox_events` | V7 后为通用事件类型、聚合类型/ID/版本、安全载荷、投递状态、投递重试、可投递时间和安全错误摘要；生成任务状态快照位于对应事件载荷。 | 按状态和 `available_at` 扫描。 |
| `user_generation_daily_usage` | 用户每天的已请求图片数量。 | `(user_id, usage_date)` 主键，创建或返还时原子更新。 |
| `user_consents` | 当前用户对 `USER_AGREEMENT` 等规则的确认版本、内容摘要和时间。 | `(user_id, consent_type)` 主键。 |

不提供任务删除；个人资产删除及私有 OSS 对象清理在[迭代 3 资产模块文档](个人生成历史与资产模块.md)中单独设计。会话删除采用软删除：允许含 `QUEUED`/`RUNNING`/`TRANSFERRING` 任务的会话删除，任务继续完成，结果仍进入资产列表；会话、消息入口对用户不可见且不可继续写入。

## 8. API、SSE 与客户端对账

所有接口使用 `/api` 前缀、统一响应结构和 Bearer Access Token。访问其他用户的私有资源统一返回 `404 GENERATION_RESOURCE_NOT_FOUND`，不泄露资源存在性。

| 功能 | 方法与路径 | 关键约定 |
| --- | --- | --- |
| 创建任务 | `POST /api/generation-tasks` | 带 `Idempotency-Key`；成功 `202 Accepted`。 |
| 任务详情 | `GET /api/generation-tasks/{taskId}` | 返回权威快照和成功图片短期签名 URL。 |
| 取消任务 | `POST /api/generation-tasks/{taskId}/cancel` | 无请求体，按第 4.2 节处理竞争。 |
| 会话列表 | `GET /api/generation-sessions?cursor=&limit=` | 默认 20、最大 50；按最近消息稳定游标分页，返回最新任务摘要。 |
| 会话消息 | `GET /api/generation-sessions/{sessionId}/messages?before=&limit=` | 默认 30、最大 100；按消息序号游标恢复提示词和关联任务快照。 |
| 会话改名 | `PATCH /api/generation-sessions/{sessionId}` | `title` 去空白后长度 1～100；不改变会话排序时间。 |
| 用户协议 | `GET /api/policies/user-agreement`、`POST /api/users/me/consents/user-agreement` | 查询当前协议或确认实际展示的 `policyVersion`。 |
| SSE | `GET /api/events` | `text/event-stream`，单用户最多 3 条、单实例最多 1000 条。 |

创建请求字段：`sessionId`（可选）、`prompt`、`negativePrompt`（可选）、`aspectRatio`、`promptExtend`（可选，默认开启）、`imageCount`、`inputAssetIds`（可选，0～3 个，顺序即模型输入顺序）。客户端不得提交已拼接历史、服务商参数或对象地址；本地上传接口返回临时资产 ID，用户自己的资产与已审核公开作品也可作为输入。所有已审核公开作品均允许被选择为图生图输入，不存在单独的 `allow_remix` 开关。

任务快照包含 `taskId`、`sessionId`、`status`、`taskVersion`、`retryCount`、`maxRetryCount`、请求/成功/失败/取消图片数量、安全失败码和提示、成功图片签名 URL、创建和完成时间。不得返回模型标识、最终提示词、服务商请求 ID、调用时间、临时 URL或密钥。

SSE 建连后先发送 `generation.stream.ready`；任务事件 `generation.task.updated` 只含 `sessionId`、`taskId`、`taskVersion`、`status`、`retryCount` 和 `maxRetryCount`。客户端进入生成页时查询会话列表，且在 URL 带 `sessionId` 时查询该会话消息；SSE 首次连接或重连完成后刷新这些页面快照。收到任务事件时，客户端刷新已打开的会话列表；若事件属于当前会话，还立即刷新其消息快照以补齐终态图片和失败详情。创建得到 `202` 后，客户端仅以 `sessionId` 进入会话并读取消息快照。客户端按版本合并事件与快照；SSE 不支持 `Last-Event-ID` 回放，数据库和 REST 快照仍是状态真相。

常见 HTTP 错误：参数或游标错误 `422`；未认证 `401`；活动任务冲突、幂等冲突、未同意规则、不可取消终态 `409`；每日额度耗尽 `429`；临时服务不可用 `503`。

## 9. OSS、权限、配置与安全

- 百炼成功响应提供可信的 PNG 临时 URL；转存时将 URL 响应 `InputStream` 直接交给 OSS SDK，不在 JVM 堆中完整缓存或解码图片，也不重复校验文件类型、内容长度和文件大小。原图上传成功后，调用 OSS `ProcessObject` 将同一对象服务端持久化为两种 WebP 派生图，不把像素解码到应用内存。
- OSS 上传不设置 `Content-Length`，由 SDK 使用分块传输；服务端通过透传计数流记录实际 `file_size`，图片宽高使用任务已确认的生成尺寸。
- 流式转存保留 HTTPS、连接超时、读取超时和输入流关闭约束；来源下载使用 `app.generation.image-transfer.source-connect-timeout/source-read-timeout`，OSS 上传使用 `app.generation.oss.upload-connect-timeout/upload-read-timeout`，当前分别为 `5s/30s`；不新增业务重试或图片内并发。
- 单张转存失败记录任务 ID、来源序号和异常类型，不记录百炼临时 URL；失败不阻断同任务其他图片继续转存。
- `GenerationAssetOssCleanupService` 只扫描 `image_assets` 中已标记待清理且未被公开发布、未被活动任务引用的资产，不会列举 OSS 并与数据库对账。取消或终态竞争后的即时删除属于尽力操作；若删除失败会记录日志，但当前没有自动清理“OSS 已存在、数据库无图片记录”的孤儿对象。
- 生成资产的 `image_assets.object_key` 保存对象组前缀 `users/{userId}/tasks/{taskId}/{sourceIndex}`，不是具体文件键。每组固定为 `{prefix}/original.png`、`{prefix}/card.webp` 与 `{prefix}/display.webp`；上传资产则直接以 `original_object_key` 作为私有原图键。Bucket 保持私有。
- 签名 URL 有效期 10 分钟，不写入数据库、日志或 SSE；任务详情响应使用 `Cache-Control: private, no-store`。
- 服务商 API Key、OSS 凭证、RabbitMQ 密码、临时 URL、签名 URL和完整提示词不得出现在客户端响应或普通日志。
- 本地真实配置仅放在 Git 忽略的 `application-local.yaml`；仓库配置使用环境变量占位符，生产环境由部署平台注入。
- 单实例阶段不得水平扩容或拆分独立工作器；扩容前必须先设计共享百炼限流和跨实例 SSE 事件分发。
- 网关负责请求级防刷、DDoS 防护、SSE 响应禁缓冲和足够长的读取超时；应用不信任客户端转发 IP 头。

## 10. 验证结论与后续运行保障

当前完整 Maven 测试为 169 项，全部通过，失败和错误均为 0。已验证真实百炼、RabbitMQ 和 OSS 的文生图闭环：任务按 `QUEUED → RUNNING → TRANSFERRING → SUCCEEDED` 收敛；同时验证了发布审核至 `APPROVED`、公开详情读取，以及另一用户的点赞、取消点赞和计数回滚。I2I 参考图的上传、授权、冻结、模型请求和异步转存沿用相同 Outbox/MQ 状态机；应在接入真实参考图后补充一组真实 I2I 端到端验收。

容器化 MySQL/RabbitMQ/OSS 自动集成测试不阻塞本迭代：当前环境无 Docker，后续在具备 Docker 的 CI 或开发环境按关键链路补充，并避免触碰真实 OSS 生产数据。

运行监控暂不实现。后续单独设计分钟级聚合监控表，至少包含任务/队列状态、百炼调用耗时与失败分类、OSS 失败和 Outbox 积压；必须同时确认写入频率、保留周期、查询权限和后台展示。监控表不是逐请求日志，不记录用户 ID、任务 ID、提示词或 URL 等高基数/敏感字段。

后续业务顺序：[个人生成资产](个人生成历史与资产模块.md) → 收藏与发布 → 灵感社区 → 点赞与关注 → 一期闭环；局部重绘和 Agent/工作流在一期闭环后再单独立项。
