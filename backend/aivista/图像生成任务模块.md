# AiVista 图像生成任务模块

> 对应迭代：普通图像生成任务（文生图与图生图）
> 当前状态：已完成；资产、发布与社区交互已接入同一图片资产模型
> 用途：本文是后续维护普通图像生成代码时的实现说明书。记录已确认的流程、约束和异常处理；代码、测试或规则变化时必须同步修改本文档。

## 1. 范围、完成边界与后续演进

本模块已完成普通文生图、图生图的创建、异步执行、私有存储、查询、发布、点赞与通知闭环。

已完成能力：

- 持久化会话、通用创作轮次、双角色消息、普通图像生成任务、用户同意规则、并发任务和每日额度控制。
- RabbitMQ Outbox 可靠投递、消费者手动 ACK、排队超时和消费失败有限收敛。
- 百炼 Qwen-Image 调用、单实例调用门控、有限重试、结果未知保护和 RabbitMQ 重投恢复。
- 私有 OSS 原图流式转存、临时本地上传参考图、服务端持久化 WebP 派生图、统一图片 DTO 的缩略图与展示图签名 URL、任务/会话查询、会话改名和 SSE 通知。
- 使用同一 `image_assets` 资产表承载生成结果和上传参考图；支持 0～3 张有序参考图作为图生图输入。
- 作品发布审核、公开灵感列表、点赞、收藏和搜索索引均基于 `image_assets` 与独立的发布/点赞关系表。

不属于当前模块：局部重绘和遮罩、Agent 步骤和工具调用、付费和推荐。

局部重绘可以在后续独立迭代。Agent 已通过内部图像任务入口创建相同的 `generation_tasks`，没有旁路调用模型；来源图片、生成步骤与普通任务共享现有任务和资产语义。

## 2. 核心架构与执行流程

### 2.1 组件职责

| 组件 | 职责 |
| --- | --- |
| MySQL | 保存会话、消息、任务、图片、额度、同意记录和 Outbox；是唯一任务真相来源。 |
| RabbitMQ | Durable Direct Exchange `aivista.generation.commands` 将单一命令路由至 `generation.task.execute` Durable Quorum Queue。 |
| 阿里云百炼 | 使用同步 Qwen-Image API 生成图片。项目的异步性由 RabbitMQ 工作器提供。 |
| 阿里云 OSS | 保存项目拥有的私有 PNG 原图。 |
| SSE | 向在线客户端通知任务状态变化；不作为状态真相或消息回放渠道。 |

### 2.2 正常链路

```text
POST 创建任务
  → 同一 MySQL 事务：会话、NORMAL 创作轮次、USER/ASSISTANT 消息、任务、每日额度、`GENERATION_TASK_EXECUTE` 与 `GENERATION_TASK_STATUS_CHANGED` 通用 Outbox 事件
  → Java Outbox 经 Direct Exchange 投递生成命令，收到 Publisher Confirm 且消息未被退回后标记已发布
  → TS 以进程内 active task 集合阻止并发重复执行，通过内部 HTTP 将任务推进到 `GENERATING`
  → TS 调用百炼，返回后通过内部 HTTP 推进到 `SAVING`，再连续下载图片、写私有 OSS 原图并生成两种 WebP 派生图
  → TS 通过内部幂等 HTTP 提交 Completion；Java 原子创建图片资产、写任务终态、处理额度并写终态状态 Outbox
  → Java 成功提交权威快照后 TS ACK；Java 状态事件分发给 SSE，REST 返回私有 OSS 签名 URL
```

任务创建接口立即返回 `202 Accepted`。客户端在提交前必须先建立用户级 SSE；创建响应提供新会话和任务标识，前端据 `sessionId` 进入会话并读取创作轮次，以展示初始 `QUEUED`。后续状态由 SSE 实时推动；首次连接、重连或进入生成页时，REST 会话列表与当前会话轮次快照负责状态恢复。

### 2.3 消费者与调用许可

- 生成队列 `generation.task.execute` 使用独立 TS 消费通道，是 Durable Quorum Queue、持久化消息、`prefetch=1` 和手动 ACK。
- 百炼调用门控当前为最多 `25` 个调用许可、每秒最多启动 `2` 次调用。
- TS 只执行百炼调用和 OSS 转存，不写普通生成业务表；Java 是任务、额度、资产、Outbox 与用户可见状态的唯一写入方。Java 中不再保留生成或转存命令消费者。
- Outbox 发送使用 Publisher Confirm、Mandatory 与 Publisher Return；只有交换机确认且消息成功路由到队列后，事件才标记为 `PUBLISHED`。
- Worker 只执行 revision 一致的 `QUEUED` 任务，并在调用 Provider 前成功向 Java上报 `GENERATING`；Java若已提交终态则 TS 直接投递权威结果。进程重启后发现 `GENERATING/SAVING` 表示 Provider 副作用无法判定，TS 不重复调用，而以 `PROVIDER_CALL_OUTCOME_UNKNOWN` 失败收口。

## 3. 任务、会话和请求约束

### 3.1 会话与历史

- 用户首次提交不传 `sessionId` 时，在同一事务创建会话、消息和任务；会话默认标题由首条正向提示词截取生成，可后续改名。
- 同一会话允许连续提交多个任务；创建已有会话任务时锁定会话行，以稳定分配消息序号。
- 同一用户跨会话、页面和设备最多四个未完成任务；创建任务时锁定用户行并统计状态。
- 每轮保存一条 USER 消息和一条 ASSISTANT 消息；USER 内容是正向提示词，负向提示词保存在普通生成请求快照中，ASSISTANT 内容当前为空，生成状态与图片由关联 `generation_tasks` 提供。历史轮次只用于会话记录展示，不作为模型生成上下文。
- 正向提示词最大 1000 个字符、负向提示词最大 500 个字符。输入超长直接拒绝，不截断。

### 3.2 模型参数

模型固定 `qwen-image-2.0`，任务保存完整标识 `bailian/qwen-image-2.0`；`prompt_extend` 由任务快照决定，默认开启，客户端可按次关闭。无参考图时按文生图请求模型；有 `inputAssetIds` 时按给定顺序将已冻结的参考图 URL 与提示词一起发送，模型自行处理单图编辑或多图融合。

| `aspectRatio` | 百炼 `size` |
| --- | --- |
| `1:1` | `2048*2048` |
| `16:9` | `2688*1536` |
| `9:16` | `1536*2688` |
| `4:3` | `2368*1728` |
| `3:4` | `1728*2368` |

`imageCount` 只能为 `1`～`6`。`promptExtend` 为可选布尔值，控制百炼是否优化提示词，缺省为 `true`。客户端不能传模型、最终提示词、宽高、百炼参数或 OSS 地址。

### 3.3 创建、防重与每日额度

- 浏览器创建普通任务不带 `Idempotency-Key`，前端不保存或自动重放未确认的 POST。响应不确定时重新读取会话轮次；同一会话的 `RUNNING` Creation 约束阻止并行重复提交。
- 会话、创作轮次、消息、任务、每日额度和执行/状态 Outbox 必须在同一事务中写入。
- 内部 Worker 的防重只放在真正可能被重投的边界：MQ命令使用 `generationTaskId + expectedRevision`；Completion 使用同一身份和任务终态检查，重复提交返回权威终态。
- 每日额度按 `Asia/Shanghai` 自然日计算，单用户每天最多请求 12 张，在任务创建事务中原子占用。
- `quota_refunded_at` 保证同一任务最多返还一次额度。

### 3.4 用户协议与第三方数据处理同意

生成与发布不再分别收集同意，而是共用版本化 `USER_AGREEMENT`。注册时必须提交当前 `agreementPolicyVersion`，服务端先校验版本、创建用户后在同一事务写入同意记录；登录或会话恢复响应以 `userAgreementConfirmed` 告知当前状态。若旧用户尚未同意当前版本，客户端在进入业务页面前展示强制确认弹窗，并以 Bearer Token 提交确认。服务端维护完整文案、版本、文案 SHA-256 摘要与确认时间；只有实际展示的当前版本才可提交。

协议必须明确告知：本次生成的正向/负向提示词会发送至阿里云百炼，历史会话消息仅由 AiVista 保存并展示，不作为本次模型输入；发布标题与描述会发送至阿里云内容安全增强版 PLUS 审核；项目会保存会话、任务、图片和同意记录；用户不应输入敏感个人信息。`UserAgreementAccessFilter` 在 Bearer Token 校验后统一拦截未同意或版本过期用户，返回 `409 GENERATION_CONSENT_REQUIRED`；仅放行认证接口、`GET /api/policies/user-agreement`、`POST /api/users/me/consents/user-agreement` 与匿名灵感页，直至确认当前版本。生成或发布审核任务不得写入会话、任务、额度或 Outbox。

## 4. 状态机和额度

### 4.1 状态机

```text
QUEUED → GENERATING → SAVING → SUCCEEDED | PARTIALLY_SUCCEEDED | FAILED
```

状态变更均使用带前置状态和 `revision` 的条件更新；影响行数为 `1` 才代表状态迁移成功，终态不可再次执行。数据库事务不得跨越百炼调用或图片响应流至 OSS 的转存过程。

创建与终态变化在业务事务中写入 `GENERATION_TASK_STATUS_CHANGED` Outbox。`GENERATING/SAVING` 是 Worker 的粗粒度在线阶段，由 Java 在阶段事务提交后直接投影到当前 SSE 连接，不额外写 Outbox；断线后 REST 快照返回当前权威阶段。状态事件保存变化发生时的状态、`revision` 和模型重试次数，旧事件不能覆盖客户端已知的新 revision。

`QUEUED` 表示任务等待 Worker，`GENERATING` 表示正在调用百炼，`SAVING` 表示正在下载、处理和转存 OSS；随后进入成功、部分成功或失败终态。Provider 临时 URL 不写入 Java 业务表，也不返回 REST/SSE。进入终态后，任务详情与会话轮次中的每张图片均返回统一图片 DTO：会话网格使用 `thumbnail`，详情复用 `display`；`original` 只能由当前认证作者临时取得。

- 所有请求图片都成功转存：`SUCCEEDED`。
- 至少一张成功转存：`PARTIALLY_SUCCEEDED`。
- 没有图片成功转存：`FAILED`。
- 每次状态变化递增 `revision`；客户端只接受比本地更新的版本。

### 4.2 额度返还规则

以下失败返还一次本次请求图片数量：

`PROVIDER_CALL_OUTCOME_UNKNOWN`、`PROVIDER_CONNECTION_FAILED`、`PROVIDER_RATE_LIMITED`、`PROVIDER_SERVICE_UNAVAILABLE`、`QUEUE_DELIVERY_FAILED`、`QUEUE_TIMEOUT`、`QUEUE_CONSUMPTION_FAILED`。

内容安全、参数/鉴权/配置错误、服务商配额或计费问题、图片转存全部或部分失败、其他业务失败和部分成功不返还。每日额度用于约束已经发起的模型生成成本，不代表最终成功保存的图片数量。

## 5. 百炼错误、重试和快照恢复

### 5.1 调用约定

- 每次请求带 `X-DashScope-Wait-Timeout: 30`。该值只允许百炼在 `Throttling.BurstRate` 情况下最多服务端排队 30 秒。
- HTTP 连接超时 `5s`，非流式读取超时 `330s`。
- HTTP 客户端不自动重试或重定向，必须校验证书和主机名。

### 5.2 错误决策表

| 识别结果 | 处理 | 自动重试 | 最终稳定失败码 | 返还额度 |
| --- | --- | --- | --- | --- |
| DNS/TCP/TLS 未建立，确认 HTTP 请求未发出 | 清空调用开始标记，重新排队 | 最多 3 次，`1s/2s/4s + 0~1s` 抖动 | `PROVIDER_CONNECTION_FAILED` | 是 |
| `429 Throttling`、`Throttling.RateQuota`、`Throttling.BurstRate` | 重新排队 | 同上 | `PROVIDER_RATE_LIMITED` | 是 |
| 明确 HTTP `5xx` | 重新排队 | 同上 | `PROVIDER_SERVICE_UNAVAILABLE` | 是 |
| `Throttling.AllocationQuota`、`CommodityNotPurchased`、免费额度耗尽、账单问题 | 直接失败 | 否 | `PROVIDER_QUOTA_UNAVAILABLE` | 否 |
| `400 DataInspectionFailed` | 直接失败 | 否 | `PROVIDER_CONTENT_REJECTED` | 否 |
| 其他参数/输入/尺寸错误，或鉴权、业务空间、模型、端点错误 | 直接失败 | 否 | `PROVIDER_CONFIGURATION_ERROR` | 否 |
| 已连接后的读取超时、连接中断、结果无法确认 | 直接失败 | 否 | `PROVIDER_CALL_OUTCOME_UNKNOWN` | 是 |

可重试错误每次均重新经过调用门控，不重复占用用户额度。最大模型重试次数由 `app.generation.bailian.max-retries` 配置，当前为 `3`；首次调用不计入重试次数。调用结果未知不得重试，以避免重复生成与重复计费。

### 5.3 Worker 恢复

百炼返回图片临时 URL 后，TS 将任务上报为 `SAVING` 并继续完成 OSS，不持久化临时 URL或 Provider 快照。由于无法在重启后证明外部调用是否已经产生副作用，RabbitMQ 重投时只有 revision 一致的 `QUEUED` 任务能够重新开始；`GENERATING/SAVING` 统一以 `PROVIDER_CALL_OUTCOME_UNKNOWN` 失败并返还额度，避免重复生成和重复计费。

转存工作器在完成阶段失去任务所有权时，不会删除确定性 OSS 对象键，避免迟到副本误删已被另一工作器成功提交的资产。极端竞争下宁可留下可后续清理的孤儿对象，也不破坏已成功资产。

## 6. Outbox、MQ 与排队失败

### 6.1 Outbox 规则

创建任务写入 `GENERATION_TASK_EXECUTE` 和初始 `GENERATION_TASK_STATUS_CHANGED`；Completion 终态再写一个 `GENERATION_TASK_STATUS_CHANGED`。`GENERATING/SAVING` 在提交阶段事务后直接发给在线 SSE，不写状态 Outbox。所有状态事件只含任务身份、revision、状态和模型重试次数，不含提示词、临时 URL、签名 URL或密钥。

- `GENERATION_TASK_EXECUTE`：路由到 `generation.task.execute`；投递重试耗尽后，仅在任务仍为 `QUEUED` 且版本一致时收敛为 `FAILED + QUEUE_DELIVERY_FAILED` 并返还额度。
- 执行事件须同时满足 Publisher Confirm ACK 且没有 Mandatory Returned Message，才标记 `PUBLISHED`。Outbox 事件被领取为 `PROCESSING` 后持有租约；分发实例异常退出时重新排期。
- `GENERATION_TASK_STATUS_CHANGED`：只用于在线通知。没有 SSE 连接或写入失败不改变任务状态；事件可标记失败并记录安全日志。事件被领取为 `PROCESSING` 后持有 30 秒租约；分发实例在发送前异常退出时，后续扫描将其重新排期。重复通知由客户端按任务版本合并，REST 快照仍是最终对账来源。
- 所有类型的 `PUBLISHED` 事件保留 7 天后，每小时按 `(status, published_at, id)` 索引分批清理；`PENDING`、`PROCESSING` 与 `FAILED` 事件不自动删除。

### 6.2 消费失败与排队超时

| 场景 | 处理 |
| --- | --- |
| 每次进入 `QUEUED` 后超过 3 分钟未领取 | 按本次入队的 `updated_at` 收敛为 `FAILED + QUEUE_TIMEOUT`，返还额度并写状态 Outbox。 |
| 消息对应任务已终态或版本过期 | 直接 ACK，不执行模型。 |
| TS 在百炼调用前发生内部 HTTP 或基础设施异常 | `NACK + requeue`；重投后读取非终态任务并重新执行。 |
| TS 在 Provider 调用中异常退出 | RabbitMQ 重投后识别 `GENERATING/SAVING`，不重复调用 Provider，以 `PROVIDER_CALL_OUTCOME_UNKNOWN` 失败收口并返还额度。 |
| 无法解析的 MQ 消息 | 直接 ACK，避免无限循环。 |
| 明确单图转存失败 | 记录任务 ID、来源序号和异常类型，继续同任务其他图片，无业务重试，最终部分成功或失败后 ACK。 |
| 转存阶段基础设施异常 | 当前执行提交 `IMAGE_TRANSFER_FAILED`；若进程直接退出，重投按未知外部结果失败收口，不从头重复 Provider 调用。 |

不配置队列消息 TTL、DLQ、人工重放或运维重放链路。最终失败由用户重新发起。

## 7. 数据模型与存储约定

Flyway 迁移是表结构唯一来源。当前数据库无业务数据，因此通用 `creation_tasks`、`conversation_messages` 和 `generation_tasks.creation_task_id` 直接定义在 V3，`creation_task_input_assets` 随统一图片资产定义在 V16；不存在旧会话消息表、数据回填迁移或兼容代码。V26 删除已不再使用的普通生成 Worker 执行账本；V27 将 `generation_tasks.task_version` 统一为 `revision`，把 `creation_activities` 收敛为最终态不可变步骤，把 Agent Ledger 的 `result_json` 更名为 `completion_json`，并删除通用 `idempotency_records`。V28 保持已执行迁移不可变，将过渡期 `agent_request_id` 规范化为 `tool_call_id`，并新增每会话唯一的 `agent_session_contexts`。V29 新增 `creation_forms` 和 `WAITING_INPUT`，并把 Agent Ledger 扩展为按 `execution_revision` 保存暂停 Context 或最终 Completion 的通用 `payload_json`。资源主键统一为 `BIGINT UNSIGNED`，HTTP 响应序列化为字符串；除每日额度业务日期外，时间统一为 UTC `DATETIME(3)`。

| 表 | 保存内容 | 关键约束/用途 |
| --- | --- | --- |
| `generation_sessions` | 用户会话、标题、最近消息时间与软删除时间。 | 按用户和最近消息查询；软删除后不再返回、不可继续写入消息/创建任务，但不级联删除任务、图片或配置。 |
| `creation_tasks` | 一次普通或 Agent 创作轮次及其所属用户、会话、执行模式和终态。 | 写入 `NORMAL/AGENT`；不重复保存每个图片生成任务的状态。 |
| `conversation_messages` | 每轮固定一条 `USER` 与一条 `ASSISTANT` 消息及会话内序号。 | `(creation_task_id, role)` 与 `(session_id, sequence_no)` 唯一；普通模式的助手内容为空，状态和图片由关联生成任务提供。 |
| `creation_task_input_assets` | 用户在本轮提交的有序候选图片。 | 与具体模型最终使用的图片分层，供后续 Agent 模式在调用生成能力前读取。 |
| `generation_tasks` | 通用创作轮次关联的一次 `TEXT_TO_IMAGE` 或 `IMAGE_TO_IMAGE` 模型调用、状态、revision、模型、最终提示词、尺寸、数量、重试和失败码。 | 普通 Creation 通常一条；Agent 可有多条。Agent 子任务以 `(creation_task_id, tool_call_id)` 唯一。 |
| `image_assets` | 已成功生成的图片对象组，或用户上传的临时参考图。 | 生成结果通过 `(origin_task_id, source_index)` 唯一；上传资产以 `origin=UPLOADED`、到期时间和清理状态管理。 |
| `generation_task_input_assets` | 图生图任务冻结后的有序实际模型输入资产。 | `(task_id, source_index)` 唯一；任务执行时只读取其冻结引用，避免用户后续调整资产选择影响已创建任务。 |
| `image_publications` | 图片资产的审核状态、版本、标题、描述、公开时间和点赞计数。 | `asset_id` 唯一；仅 `APPROVED` 且 `public_at` 非空时属于公开作品。 |
| `image_asset_likes` | 用户对公开作品当前发布版本的点赞关系。 | 点赞关系绑定发布版本；撤销发布会删除当前版本的关系并回收计数。 |
| `outbox_events` | V7 后为通用事件类型、聚合类型/ID/版本、安全载荷、投递状态、投递重试、可投递时间和安全错误摘要；生成任务状态快照位于对应事件载荷。 | 按状态和 `available_at` 扫描。 |
| `user_generation_daily_usage` | 用户每天的已请求图片数量。 | `(user_id, usage_date)` 主键，创建或返还时原子更新。 |
| `user_consents` | 当前用户对 `USER_AGREEMENT` 等规则的确认版本、内容摘要和时间。 | `(user_id, consent_type)` 主键。 |

不提供任务删除；个人资产删除及私有 OSS 对象清理在[迭代 3 资产模块文档](个人生成历史与资产模块.md)中单独设计。会话删除采用软删除：允许含 `QUEUED` 任务的会话删除，任务继续完成，结果仍进入资产列表。

## 8. API、SSE 与客户端对账

所有接口使用 `/api` 前缀、统一响应结构和 Bearer Access Token。访问其他用户的私有资源统一返回 `404 GENERATION_RESOURCE_NOT_FOUND`，不泄露资源存在性。

| 功能 | 方法与路径 | 关键约定 |
| --- | --- | --- |
| 创建任务 | `POST /api/generation-tasks` | 不带客户端幂等键；成功 `202 Accepted`。 |
| 任务详情 | `GET /api/generation-tasks/{generationTaskId}` | 返回权威快照和成功图片短期签名 URL。 |
| 会话列表 | `GET /api/generation-sessions?cursor=&limit=` | 默认 20、最大 50；按最近消息稳定游标分页，返回最新任务摘要和 `hasActiveTask` 聚合标记。 |
| 会话创作轮次 | `GET /api/generation-sessions/{sessionId}/turns?before=&limit=` | 每页最多 5 个创作轮次；每项返回 `creationId`、`mode`、USER/ASSISTANT 消息、普通模式请求参数和关联生成任务快照。 |
| 会话改名 | `PATCH /api/generation-sessions/{sessionId}` | `title` 去空白后长度 1～100；不改变会话排序时间。 |
| 用户协议 | `GET /api/policies/user-agreement`、`POST /api/users/me/consents/user-agreement` | 查询当前协议或确认实际展示的 `policyVersion`。 |
| SSE | `GET /api/events` | `text/event-stream`，单用户最多 3 条、单实例最多 1000 条。 |

创建请求字段：`sessionId`（可选）、`prompt`、`negativePrompt`（可选）、`aspectRatio`、`promptExtend`（可选，默认开启）、`imageCount`、`inputAssetIds`（可选，0～3 个，顺序即模型输入顺序）。客户端不得提交已拼接历史、服务商参数或对象地址；本地上传接口返回临时资产 ID，用户自己的资产与已审核公开作品也可作为输入。所有已审核公开作品均允许被选择为图生图输入，不存在单独的 `allow_remix` 开关。

任务快照包含 `generationTaskId`、`sessionId`、`status`、`revision`、`retryCount`、`maxRetryCount`、请求/成功/失败图片数量、安全失败码和提示、成功图片签名 URL、创建和完成时间。不得返回模型标识、最终提示词、服务商请求 ID、调用时间、临时 URL或密钥。

SSE 建连后先发送 `generation.stream.ready`；任务事件 `generation.task.updated` 只含 `sessionId`、`generationTaskId`、`revision`、`status`、`retryCount` 和 `maxRetryCount`。客户端进入生成页时查询会话列表，且在 URL 带 `sessionId` 时查询该会话的创作轮次；SSE 首次连接或重连完成后刷新这些页面快照。收到任务事件时，客户端刷新已打开的会话列表；若事件属于当前会话，还立即刷新其轮次快照以补齐终态图片和失败详情。创建得到 `202` 后，客户端仅以 `sessionId` 进入会话并读取轮次快照。客户端按 revision 合并事件与快照；SSE 不支持 `Last-Event-ID` 回放，数据库和 REST 快照仍是状态真相。

常见 HTTP 错误：参数或游标错误 `422`；未认证 `401`；活动任务数达到用户上限或未同意规则 `409`；每日额度耗尽 `429`；临时服务不可用 `503`。

## 9. OSS、权限、配置与安全

- 百炼成功响应提供可信的 PNG 临时 URL；TypeScript Worker 转存时使用流式下载和上传，不在内存中完整缓存或解码图片。原图上传成功后，调用 OSS 图片处理将同一对象服务端持久化为两种 WebP 派生图。
- OSS 上传不设置 `Content-Length`，由 SDK 使用分块传输；服务端通过透传计数流记录实际 `file_size`，图片宽高使用任务已确认的生成尺寸。
- 流式转存保留 HTTPS、连接超时、读取超时和输入流关闭约束；来源下载使用 `app.generation.image-transfer.source-connect-timeout/source-read-timeout`，OSS 上传使用 `app.generation.oss.upload-connect-timeout/upload-read-timeout`，当前分别为 `5s/30s`；不新增业务重试或图片内并发。
- 单张转存失败记录任务 ID、来源序号和异常类型，不记录百炼临时 URL；失败不阻断同任务其他图片继续转存。
- `GenerationAssetOssCleanupService` 只扫描 `image_assets` 中已标记待清理且未被公开发布、未被活动任务引用的资产，不会列举 OSS 并与数据库对账；当前没有自动清理“OSS 已存在、数据库无图片记录”的孤儿对象。
- 生成资产的 `image_assets.object_key` 保存对象组前缀 `users/{userId}/tasks/{generationTaskId}/{sourceIndex}`，不是具体文件键。每组固定为 `{prefix}/original.png`、`{prefix}/card.webp` 与 `{prefix}/display.webp`；上传资产则直接以 `original_object_key` 作为私有原图键。Bucket 保持私有。
- 普通图片 DTO 中 `thumbnail/display` 的签名 URL 有效期为 1 天，原图临时 URL 有效期为 10 分钟；URL 不写入数据库、日志或 SSE，任务详情响应使用 `Cache-Control: private, no-store`。
- 服务商 API Key、OSS 凭证、RabbitMQ 密码、临时 URL、签名 URL和完整提示词不得出现在客户端响应或普通日志。
- 本地真实配置仅放在 Git 忽略的 `application-local.yaml`；仓库配置使用环境变量占位符，生产环境由部署平台注入。
- 当前 Java Core 与 TypeScript AI Runtime 各按单实例运行。生成命令只由 TS 消费，TS 通过内部 HTTP 提交结果；旧 Java Worker、Transfer/Result MQ 与切换开关已经删除。扩容前仍需设计跨 TS 实例共享的百炼限流。
- 网关负责请求级防刷、DDoS 防护、SSE 响应禁缓冲和足够长的读取超时；应用不信任客户端转发 IP 头。

## 10. 验证结论与后续运行保障

普通生成采用单命令 Pipeline：Java 创建任务和命令，TS 上报 `GENERATING/SAVING` 并连续完成百炼、下载和 OSS，再通过幂等 HTTP 返回最终图片元数据；Java 原子创建资产并写入终态、额度和 SSE Outbox。TS 不写普通生成业务表。

普通生成与 Agent 共用链路已经完成 Java 185 项、TS 126 项和真实 MySQL V29 Schema 测试；TS 生产构建与前端 83 项测试/生产构建也通过。既有真实文生图、真实参考图图生图、RabbitMQ、百炼和 OSS 联调结论保持有效。发布审核完整保留在 Java 发布领域，不经过 TS 或审核结果消息队列。

本项目按现有开发方式直接启动 Java、TS 和前端，并连接开发环境 MySQL、RabbitMQ、OSS 与模型服务联调；本轮不引入 Docker 验证链路。

运行监控暂不实现。后续单独设计分钟级聚合监控表，至少包含任务/队列状态、百炼调用耗时与失败分类、OSS 失败和 Outbox 积压；必须同时确认写入频率、保留周期、查询权限和后台展示。监控表不是逐请求日志，不记录用户 ID、任务 ID、提示词或 URL 等高基数/敏感字段。

个人资产、收藏与发布、灵感社区、点赞关注及 Agent 一期链路均已接入；后续业务能力包括局部重绘，以及上线前的可观测性、灾备和生产交付闭环。
