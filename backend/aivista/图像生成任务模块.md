# AiVista 图像生成任务模块

> 对应迭代：迭代 2——普通文生图任务
> 当前状态：已完成
> 用途：本文是后续维护普通文生图代码时的实现说明书。记录已确认的流程、约束和异常处理；代码、测试或规则变化时必须同步修改本文档。

## 1. 范围、完成边界与后续演进

本模块已完成普通文生图的创建、异步执行、私有存储、查询、取消和通知闭环。

已完成能力：

- 持久化会话、提示词历史、普通文生图任务、用户同意规则、并发任务和每日额度控制。
- RabbitMQ Outbox 可靠投递、消费者手动 ACK、排队超时和消费失败有限收敛。
- 百炼 Qwen-Image 调用、单实例调用门控、有限重试、结果未知保护和服务商结果快照恢复。
- 私有 OSS PNG 转存、签名 URL、任务/会话查询、会话改名、取消任务和 SSE 通知。

不属于当前模块：局部重绘、上传来源图、遮罩、Agent 步骤和工具调用、资产删除、收藏、发布、社区、点赞、关注、付费和推荐。

局部重绘及 Agent/工作流可以在一期闭环后独立迭代。届时通过 Flyway 新增来源图片、遮罩、步骤或工作流等数据模型及对应执行器；当前普通文生图任务不预留空字段，也不改变已有任务语义。

## 2. 核心架构与执行流程

### 2.1 组件职责

| 组件 | 职责 |
| --- | --- |
| MySQL | 保存会话、消息、任务、图片、额度、同意记录和 Outbox；是唯一任务真相来源。 |
| RabbitMQ | Durable Quorum Queue `generation.task.execute` 承载异步执行消息。 |
| 阿里云百炼 | 使用同步 Qwen-Image API 生成图片。项目的异步性由 RabbitMQ 工作器提供。 |
| 阿里云 OSS | 保存项目拥有的私有 PNG 原图。 |
| SSE | 向在线客户端通知任务状态变化；不作为状态真相或消息回放渠道。 |

### 2.2 正常链路

```text
POST 创建任务
  → 同一 MySQL 事务：会话、提示词消息、任务、每日额度、TASK_EXECUTE Outbox
  → Outbox 收到 Publisher Confirm 后投递 RabbitMQ
  → 消费者领取 QUEUED 任务为 RUNNING
  → 写入 provider_call_started_at 后调用百炼
  → 保存临时 URL 快照，下载并校验 PNG，上传私有 OSS
  → 同一 MySQL 事务：图片记录、任务终态、TASK_STATUS_CHANGED Outbox
  → ACK 原 MQ 消息；状态事件再分发给当前实例的 SSE 连接
```

任务创建接口立即返回 `202 Accepted`。客户端后续通过 REST 查询权威状态，并以 SSE 作为实时刷新信号。

### 2.3 消费者与调用许可

- 队列消费者初始并发 `40`，每个消费者 `prefetch=1`，使用手动 ACK。
- 百炼调用门控初始为最多 `25` 个调用许可、每秒最多启动 `2` 次调用。
- 消费者从收到消息到 ACK 一直占用一个消费者线程；调用许可只覆盖百炼调用门控等待和 HTTP 调用，百炼返回后即释放。消费者数量高于调用许可，使部分消费者在其他任务进行 OSS 转存、数据库提交或 ACK 时仍可继续处理队列消息。
- `RUNNING` 表示消费者已领取任务，不表示已经调用百炼。`provider_call_started_at` 才是“请求可能已发出”的经济与幂等边界。

## 3. 任务、会话和请求约束

### 3.1 会话与历史

- 用户首次提交不传 `sessionId` 时，在同一事务创建会话、消息和任务；会话默认标题由首条正向提示词截取生成，可后续改名。
- 同一会话同一时间只能有一个 `QUEUED` 或 `RUNNING` 任务；创建已有会话任务时锁定会话行检查。
- 同一用户跨会话、页面和设备最多四个未完成任务；创建任务时锁定用户行并统计状态。
- 每轮保存正向、负向提示词消息；调用前由服务端按历史规则拼接并保存最终提示词。当前会话应只围绕一个图片主题创作，换主题时新建会话。
- 正向提示词最大 1000 个字符、负向提示词最大 500 个字符。输入或单条历史超长直接拒绝，不截断；历史从新到旧按整条加入，超过预算即停止，再按旧到新拼接。

### 3.2 模型参数

模型固定 `qwen-image-2.0`，任务保存完整标识 `bailian/qwen-image-2.0`；普通模式固定 `prompt_extend=false`。

| `aspectRatio` | 百炼 `size` |
| --- | --- |
| `1:1` | `2048*2048` |
| `16:9` | `2688*1536` |
| `9:16` | `1536*2688` |
| `4:3` | `2368*1728` |
| `3:4` | `1728*2368` |

`imageCount` 只能为 `1`～`6`。客户端不能传模型、最终提示词、宽高、百炼参数或 OSS 地址。

### 3.3 幂等与每日额度

- 创建任务必须带 UUID v4 `Idempotency-Key`。
- 幂等范围为当前用户和该键。相同键、相同规范化请求指纹返回已有任务，不重复创建会话/消息/任务或占用额度；相同键、不同指纹返回 `409 IDEMPOTENCY_KEY_CONFLICT`。
- 每日额度按 `Asia/Shanghai` 自然日计算，单用户每天最多请求 12 张，在任务创建事务中原子占用。
- `quota_refunded_at` 保证同一任务最多返还一次额度。

### 3.4 第三方数据处理同意

创建任务前必须确认 `GENERATION_THIRD_PARTY_PROCESSING` 当前规则版本。服务端维护规则版本、完整文案和文案 SHA-256 摘要；客户端只提交实际展示的 `policyVersion`。未同意或版本过期时拒绝创建，不写入会话、任务、额度或 Outbox。

规则必须明确告知：本次正向/负向提示词及生成所需会话历史会发送至阿里云百炼；项目会保存会话、任务和图片；用户不应输入敏感个人信息。

## 4. 状态机、取消和额度

### 4.1 状态机

```text
QUEUED → RUNNING → SUCCEEDED | PARTIALLY_SUCCEEDED | FAILED | CANCELLED
    └────────────────────────→ CANCELLED | FAILED
```

状态变更均使用带前置状态和 `task_version` 的条件更新；影响行数为 `1` 才代表本工作器获得执行权，终态不可再次执行。数据库事务不得跨越百炼调用、下载或 OSS 上传。

- 所有请求图片都成功转存：`SUCCEEDED`。
- 至少一张成功转存：`PARTIALLY_SUCCEEDED`。
- 没有图片成功转存：`FAILED`。
- 每次状态变化递增 `task_version`；客户端只接受比本地更新的版本。

### 4.2 取消竞争处理

| 场景 | 处理 |
| --- | --- |
| `QUEUED`，或已 `RUNNING` 但未写入 `provider_call_started_at` | 直接 `CANCELLED`，在同一事务返还一次额度；迟到 MQ 消息直接 ACK。 |
| 已写入 `provider_call_started_at` | 直接 `CANCELLED`，不返还额度。同步百炼请求不能被首版中断，返回结果必须丢弃。 |
| 已上传 OSS、终态提交时发现已取消 | 不写入图片或成功终态，并立即尽力删除刚上传的对象。 |
| 重复取消 `CANCELLED` | 幂等成功，返回当前快照。 |
| 取消 `SUCCEEDED`、`PARTIALLY_SUCCEEDED`、`FAILED` | `409 TASK_ALREADY_FINISHED`。 |

### 4.3 额度返还规则

`provider_call_started_at` 是唯一经济边界，而非消费者领取或 `RUNNING` 状态。以下失败，以及调用前取消，返还一次本次请求图片数量：

`PROVIDER_CALL_OUTCOME_UNKNOWN`、`PROVIDER_CONNECTION_FAILED`、`PROVIDER_RATE_LIMITED`、`PROVIDER_SERVICE_UNAVAILABLE`、`QUEUE_DELIVERY_FAILED`、`QUEUE_TIMEOUT`、`QUEUE_CONSUMPTION_FAILED`。

调用开始后的用户取消、内容安全、参数/鉴权/配置错误、服务商配额或计费问题、其他业务失败和部分成功不返还。

## 5. 百炼错误、重试和快照恢复

### 5.1 调用约定

- 每次请求带 `X-DashScope-Wait-Timeout: 30`。该值只允许百炼在 `Throttling.BurstRate` 情况下最多服务端排队 30 秒。
- HTTP 连接超时 `5s`，非流式读取超时 `330s`（基础 300 秒加服务端可能排队 30 秒）。
- HTTP 客户端不自动重试或重定向，必须校验证书和主机名。

### 5.2 错误决策表

| 识别结果 | 处理 | 自动重试 | 最终稳定失败码 | 返还额度 |
| --- | --- | --- | --- | --- |
| DNS/TCP/TLS 未建立，确认 HTTP 请求未发出 | 清空调用开始标记，重新排队 | 最多 3 次，`1s/2s/4s + 0~1s` 抖动 | `PROVIDER_CONNECTION_FAILED` | 是 |
| `429 Throttling`、`Throttling.RateQuota`、`Throttling.BurstRate` | 重新排队 | 同上 | `PROVIDER_RATE_LIMITED` | 是 |
| 明确 HTTP `5xx` | 重新排队 | 同上 | `PROVIDER_SERVICE_UNAVAILABLE` | 是 |
| `Throttling.AllocationQuota`、`CommodityNotPurchased`、免费额度耗尽、账单问题 | 直接失败 | 否 | `PROVIDER_QUOTA_UNAVAILABLE` | 否 |
| `400 DataInspectionFailed` | 直接失败 | 否 | `PROVIDER_CONTENT_REJECTED` | 否 |
| 其他参数/输入/尺寸错误，或鉴权、业务空间、模型、端点错误 | 直接失败 | 否 | `PROVIDER_CONFIGURATION_ERROR` | 否 |
| 已连接后的读取超时、连接中断、结果无法确认 | 直接失败 | 否 | `PROVIDER_CALL_OUTCOME_UNKNOWN` | 是 |

可重试错误每次均重新经过调用门控，不重复占用用户额度。调用结果未知不得重试，以避免重复生成与重复计费。

### 5.3 服务商结果快照

百炼返回图片临时 URL 后，先在短事务保存 `provider_request_id`、`source_index` 和临时 URL 快照，再开始 OSS 转存。快照仅供后端恢复使用，不返回客户端、不写普通日志，全部转存完成后立即清除，最长保留 24 小时。

进程在转存期间崩溃时，新消费者读取 `RUNNING` 任务：存在快照则只恢复 OSS 转存；不存在快照但调用开始时间非空则归为调用结果未知，不再调用百炼。`(task_id, source_index)` 唯一约束和确定性对象键避免正常恢复重复创建图片记录。

## 6. Outbox、MQ 与排队失败

### 6.1 Outbox 规则

创建任务写入 `TASK_EXECUTE`；任务状态变化写入 `TASK_STATUS_CHANGED`。事件消息只含 `eventId`、`taskId`、`taskVersion`，不含提示词、临时 URL、签名 URL或密钥。

- `TASK_EXECUTE`：收到 RabbitMQ Publisher Confirm 后才标记为 `PUBLISHED`。投递失败有限重试；超过上限时，仅在任务仍为 `QUEUED` 且版本一致时收敛为 `FAILED + QUEUE_DELIVERY_FAILED` 并返还额度。
- `TASK_STATUS_CHANGED`：只用于在线通知。没有 SSE 连接或写入失败不改变任务状态；事件可标记失败并记录安全日志。

### 6.2 消费失败与排队超时

| 场景 | 处理 |
| --- | --- |
| 每次进入 `QUEUED` 后超过 3 分钟未领取 | 按本次入队的 `updated_at` 收敛为 `FAILED + QUEUE_TIMEOUT`，返还额度并写状态 Outbox。 |
| 消息对应任务已终态、已取消或版本过期 | 直接 ACK，不执行模型。 |
| 消费器在百炼调用前处理异常，`x-delivery-count < 3` | `NACK + requeue`。 |
| `x-delivery-count >= 3`，且任务仍为调用百炼前的 `RUNNING` | 写入 `FAILED + QUEUE_CONSUMPTION_FAILED`、返还额度后 ACK。 |
| `x-delivery-count >= 3`，但调用已开始或任务不能条件更新 | 继续 NACK 重投，由任务执行逻辑按调用结果未知保护，不能误判为消费者失败。 |
| 无法解析的 MQ 消息 | 直接 ACK，避免无限循环。 |

不配置队列消息 TTL、DLQ、人工重放或运维重放链路。最终失败由用户重新发起。

## 7. 数据模型与存储约定

Flyway `V3__create_generation_core_tables.sql` 是表结构唯一来源。资源主键统一为 `BIGINT UNSIGNED`，HTTP 响应序列化为字符串；除每日额度业务日期外，时间统一为 UTC `DATETIME(3)`。

| 表 | 保存内容 | 关键约束/用途 |
| --- | --- | --- |
| `generation_sessions` | 用户会话、标题、最近消息时间。 | 按用户和最近消息查询；会话行锁保护单活动任务。 |
| `generation_messages` | 每轮正向/负向提示词和会话内序号。 | `(session_id, sequence_no)` 唯一。 |
| `generation_tasks` | 用户/会话/消息归属、状态、版本、模型、最终提示词、尺寸、数量、重试次数、调用时间、失败码和快照。 | `(user_id, idempotency_key)`、`source_message_id` 唯一。 |
| `generation_images` | 已成功保存的私有对象键、尺寸、文件元数据和来源序号。 | `(task_id, source_index)` 唯一；按用户创建时间查询支持后续资产。 |
| `outbox_events` | 事件类型、任务版本、投递状态、重试、可投递时间和安全错误摘要。 | 按状态和 `available_at` 扫描。 |
| `user_generation_daily_usage` | 用户每天的已请求图片数量。 | `(user_id, usage_date)` 主键，创建或返还时原子更新。 |
| `user_consents` | 当前用户对当前规则的确认版本、内容摘要和时间。 | `(user_id, consent_type)` 主键。 |

首版不提供会话、任务或图片硬删除；个人资产删除及私有 OSS 对象清理在[迭代 3 资产模块文档](个人生成历史与资产模块.md)中单独设计。

## 8. API、SSE 与客户端对账

所有接口使用 `/api` 前缀、统一响应结构和 Bearer Access Token。访问其他用户的私有资源统一返回 `404 GENERATION_RESOURCE_NOT_FOUND`，不泄露资源存在性。

| 功能 | 方法与路径 | 关键约定 |
| --- | --- | --- |
| 创建任务 | `POST /api/generation-tasks` | 带 `Idempotency-Key`；成功 `202 Accepted`。 |
| 任务详情 | `GET /api/generation-tasks/{taskId}` | 返回权威快照和成功图片短期签名 URL。 |
| 取消任务 | `POST /api/generation-tasks/{taskId}/cancel` | 无请求体，按第 4.2 节处理竞争。 |
| 会话列表 | `GET /api/generation-sessions?cursor=&limit=` | 默认 20、最大 50；按最近消息稳定游标分页，返回最新任务摘要。 |
| 会话消息 | `GET /api/generation-sessions/{sessionId}/messages?before=&limit=` | 默认 30、最大 100；按消息序号游标恢复提示词和关联任务快照。 |
| 会话改名 | `PATCH /api/generation-sessions/{sessionId}` | `title` 去空白后长度 1～100；不改变会话排序时间。 |
| 同意规则 | `GET/POST /api/users/me/consents/generation` | 查询或确认当前 `policyVersion`。 |
| SSE | `GET /api/events` | `text/event-stream`，单用户最多 3 条、单实例最多 1000 条。 |

创建请求字段：`sessionId`（可选）、`prompt`、`negativePrompt`（可选）、`aspectRatio`、`imageCount`。客户端不得提交已拼接历史、服务商参数或对象地址。

任务快照包含 `taskId`、`sessionId`、`status`、`taskVersion`、请求/成功/失败/取消图片数量、安全失败码和提示、成功图片签名 URL、创建和完成时间。不得返回模型标识、最终提示词、服务商请求 ID、调用时间、临时 URL或密钥。

SSE 事件只含 `sessionId`、`taskId`、`taskVersion`、`status`。客户端收到事件后查询任务详情；首次连接或重连后必须重新查询会话列表和当前会话消息。SSE 不支持 `Last-Event-ID` 回放，不作为状态真相。

常见 HTTP 错误：参数或游标错误 `422`；未认证 `401`；活动任务冲突、幂等冲突、未同意规则、不可取消终态 `409`；每日额度耗尽 `429`；临时服务不可用 `503`。

## 9. OSS、权限、配置与安全

- 只接受 PNG：响应 `Content-Type`、PNG 文件魔数和实际解析格式必须一致；下载不超过 `30MiB`。
- 对象键为 `users/{userId}/tasks/{taskId}/{sourceIndex}.png`；Bucket 私有。
- 签名 URL 有效期 10 分钟，不写入数据库、日志或 SSE；任务详情响应使用 `Cache-Control: private, no-store`。
- 服务商 API Key、OSS 凭证、RabbitMQ 密码、临时 URL、签名 URL和完整提示词不得出现在客户端响应或普通日志。
- 本地真实配置仅放在 Git 忽略的 `application-local.yaml`；仓库配置使用环境变量占位符，生产环境由部署平台注入。
- 单实例阶段不得水平扩容或拆分独立工作器；扩容前必须先设计共享百炼限流和跨实例 SSE 事件分发。
- 网关负责请求级防刷、DDoS 防护、SSE 响应禁缓冲和足够长的读取超时；应用不信任客户端转发 IP 头。

## 10. 验证结论与后续运行保障

已完成一次真实百炼、RabbitMQ 和 OSS 的端到端验收；当前完整 Maven 单元测试为 71 项，全部通过。已额外验证 RabbitMQ Quorum Queue 的 `x-delivery-count` 行为、消费者失败收敛和快照恢复不重复调用百炼。

容器化 MySQL/RabbitMQ/OSS 自动集成测试不阻塞本迭代：当前环境无 Docker，后续在具备 Docker 的 CI 或开发环境按关键链路补充，并避免触碰真实 OSS 生产数据。

运行监控暂不实现。后续单独设计分钟级聚合监控表，至少包含任务/队列状态、百炼调用耗时与失败分类、OSS 失败和 Outbox 积压；必须同时确认写入频率、保留周期、查询权限和后台展示。监控表不是逐请求日志，不记录用户 ID、任务 ID、提示词或 URL 等高基数/敏感字段。

后续业务顺序：[个人生成资产](个人生成历史与资产模块.md) → 收藏与发布 → 灵感社区 → 点赞与关注 → 一期闭环；局部重绘和 Agent/工作流在一期闭环后再单独立项。
