# AiVista 关键词搜索模块

> 对应迭代：迭代 8——关键词搜索
> 当前状态：实施中
> 维护规则：本文记录公开作品关键词搜索的业务范围、设计决策、实现和验收；代码、测试和文档必须同步修改。

## 1. 目标与范围

在发现与关注列表之外，提供独立的公开作品关键词搜索能力。搜索仍属于“灵感”业务入口，但不改变迭代 7 已完成的发现与关注列表契约。

## 2. 已确认约束

- 关键词搜索作为迭代 8 独立实施，不回退或扩充迭代 7。
- MySQL 是公开作品状态和正文的事实数据源；Meilisearch 只保存可重建的搜索投影，允许与 MySQL 短暂最终一致。
- 搜索结果只允许返回当前仍为 `APPROVED` 且 `public_at` 非空的公开作品；后端不能把搜索索引当作权限或公开状态真相。
- 搜索字段仅包含公开作品的 `title` 与 `finalPrompt`；`description`、`finalNegativePrompt`、作者昵称、生成配置和内部字段不参与搜索。
- 规范化后的输入长度为 1～100 个字符；超过 100 个字符时拒绝请求，不静默截断。纯空白无效，单个汉字、字母、数字或标点可以提交。
- 后端将用户查询分为展示查询与安全检索查询。检索查询去除首尾空白、合并连续空白并统一全角 ASCII 字符；随后保留 Unicode 字母、数字、组合附加符号和空白，其余标点、Emoji 与符号统一转换为空格，不开放引号短语、减号排除等 Meilisearch 查询语法。
- 英文字母匹配不区分大小写，拉丁字母匹配忽略重音差异，简体与繁体中文使用统一检索形式；响应中的标题和最终正向提示词始终保持数据库原文。
- 使用 Meilisearch 的分词、完整词和前缀匹配，不承诺任意中间连续子串命中；引擎最多使用查询中的前 10 个有效检索词。
- 多关键词使用 `matchingStrategy: frequency`：先返回命中全部关键词的作品，结果不足时优先保留更稀有的关键词并逐步放宽，不提供完全对称的 `OR` 召回。
- 纯标点、纯符号或纯 Emoji 等无法形成有效检索词的合法输入转换为 Meilisearch 空查询，按 `likeCount DESC, publicAt DESC, imageId DESC` 返回热门公开作品；这些字符不要求与作品正文匹配。
- 启用 Meilisearch 默认 typo tolerance：1～4 个字符的词不容错，5～8 个字符允许 1 处拼写差异，9 个及以上字符允许最多 2 处；精确命中始终优先于容错命中，纯数字通过 `disableOnNumbers: true` 只做精确匹配。迭代 8 不支持拼音、同义词或语义向量搜索。
- 搜索结果依次使用 `words`、`typo`、`proximity`、`attributeRank`、`wordPosition` 和 `exactness`；`title` 排在 `finalPrompt` 之前，文字相关性完全相同时再按 `likeCount DESC, publicAt DESC, imageId DESC`。作者总获赞数和粉丝数不参与排序。
- 搜索列表首次最多返回 20 项，后续每次最多返回 40 项；客户端不传 `limit`，响应只使用 `items + nextOffset`，不返回 `hasMore`。
- 搜索直接使用 Meilisearch `offset + limit`，每个查询最多开放前 200 个排序结果；首次不传 offset，后续原样传回服务端给出的 `nextOffset`，没有更多结果或到达上限时返回 `null`。
- 搜索分页不建立固定结果快照；索引更新可能使后续页出现少量重复或遗漏，刷新搜索后读取最新索引结果。
- 不将候选作品加载到 Java 后全量打分或排序。Meilisearch 返回候选 ID 后，后端按 MySQL 当前状态校验并组装公开作品 DTO。
- MySQL 校验过滤掉已撤销、不存在或不再公开的候选后，后端继续从当前 Meilisearch 原始位置分批取数，尽量补足本页 20 或 40 项；`nextOffset` 按本次已经检查过的原始候选位置推进，而不是按最终返回数量累加。
- 单次搜索补页必须保持 Meilisearch 原始顺序并按 `imageId` 去重，补满、候选耗尽或检查到第 200 个原始结果时立即停止，不允许无边界递归查询。
- 搜索响应不暴露对象键、审核记录、内部上下文或会话历史；签名 URL 即时生成且不写入搜索索引。
- 点赞、发布审批结果和撤销发布必须先在 MySQL 事务内完成；搜索索引更新只作为同一事务写入的 Outbox 后续事件，不得阻塞或决定业务操作是否成功。
- 搜索索引同步不进入 RabbitMQ。独立 Outbox 调度器认领事件后读取 MySQL 最新状态，并据此向 Meilisearch 执行幂等新增、更新或删除；事件只携带 `imageId`，不携带可能过时的作品快照。
- 应用启动时仅在正式索引不存在的情况下自动初始化索引；正式索引已经存在时不得因重启自动全量重建。后续恢复或配置升级通过管理员显式执行的重建命令完成，不提供公开管理接口。
- Meilisearch 作为固定版本的独立容器运行并使用独立持久化卷，初期允许与后端位于同一服务器；服务端口只加入后端可访问的私有容器网络，不向公网开放。本地开发仅允许绑定回环地址。
- Meilisearch 不可用不得阻止后端启动，也不得影响搜索以外的业务；搜索接口独立返回 `503 SEARCH_UNAVAILABLE`，Outbox 事件保留并在服务恢复后继续重试。
- Meilisearch Master Key 只配置在 Meilisearch 实例，用于创建和管理受限 API Key，不进入 Spring 配置，也不参与日常搜索或索引同步。
- 后端分别使用只具备搜索权限的 Search Key 和具备文档维护、task 查询、索引初始化及重建权限的 Admin Key；两个 Key 均不得发送给前端，权限限制在正式索引及其重建临时索引范围内。
- 前台搜索连接 Meilisearch 的连接超时为 1 秒、单次请求超时为 2 秒且不在同一 HTTP 请求内自动重试；失败时快速返回 `503 SEARCH_UNAVAILABLE`。
- 后台索引同步的连接超时为 2 秒、提交请求超时为 5 秒，提交后最多等待 Meilisearch task 30 秒；临时错误通过 Outbox 按 `5 秒、30 秒、2 分钟、5 分钟` 递增退避，之后最长每 5 分钟重试一次。
- 搜索接口使用进程内令牌桶限流：每个登录用户或匿名可信客户端 IP 可突发 10 次，之后每秒恢复 1 次；一次客户端请求只计数一次，后端内部补页不重复计数。
- 搜索限流状态最多保留 20,000 个桶并清理长期未使用项；超限返回 HTTP 429、`SEARCH_RATE_LIMITED` 和 `Retry-After`，限流键不得包含查询词。
- Meilisearch 容器每 10 秒检查一次 `/health`，单次超时 2 秒，连续失败 3 次标记不健康；该状态不改变后端整体存活状态，只使搜索独立降级。
- 索引同步错误只按本地校验结果、HTTP 状态和 Meilisearch 结构化 `error.type/error.code` 分类，不解析错误消息文本。只有明确知道原请求不变就不会成功时，才标记为需要人工介入；未知错误默认低频重试并告警。
- 后端使用项目已有的 Spring `RestClient` 与 Jackson 直接调用 Meilisearch REST API，不引入 Meilisearch Java SDK、OkHttp 或 Gson；搜索与索引管理分别使用独立客户端 Bean 和受限 Key。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 迭代边界 | 搜索独立为迭代 8，原一期闭环完善顺延至迭代 9。 | 搜索的数据访问、排序和交互与发现、关注列表不同。 | 新建搜索模块，不修改迭代 7 状态。 |
| 列表隔离 | 搜索列表与发现、关注列表分别实现。 | 搜索使用有限 offset，发现和关注使用 keyset，分页语义不同。 | 搜索使用独立接口、查询状态和测试。 |
| 搜索引擎 | 使用独立 Meilisearch 服务，MySQL 保持事实数据源。 | 当前接受分词/前缀匹配、有限结果集和 offset 分页；Meilisearch 的资源与运维成本低于 Elasticsearch/OpenSearch。 | 通过 Outbox 同步可重建搜索投影，接受短暂最终一致。 |
| 搜索字段 | 仅搜索 `title` 与 `finalPrompt`，标题优先。 | 标题提供高精度主题，最终正向提示词补充画面细节；其他字段容易引入弱相关内容。 | Meilisearch 的 searchable attributes 固定按标题、最终正向提示词排列。 |
| 查询规范化 | 输入为 1～100 个规范化字符；统一空白、全半角、大小写、简繁和拉丁重音检索形式，响应保持原文。 | 消除常见输入差异并限制无边界请求。 | 前后端共享可验证的输入规则，索引文本和查询使用同一规范化方式。 |
| 基础匹配 | 采用 Meilisearch 分词、完整词和前缀匹配，不保证任意中间子串。 | 产品不再要求以 n-gram 支持所有连续子串。 | 保留 prefix search，不建立 n-gram 索引。 |
| 多关键词 | 使用 `matchingStrategy: frequency` 逐步放宽。 | 先满足完整查询，再优先保留更有区分度的词，比按输入顺序删除或严格 `AND` 更适合探索。 | 不承诺每个单词子集都被完全对称召回。 |
| 查询语法与符号 | 不开放 Meilisearch 高级查询语法；标点、Emoji 和其他符号只作分隔，无有效文字或数字时执行 placeholder search。 | 避免普通输入触发引号短语、减号排除等操作符，同时保证纯符号查询仍有结果。 | 展示查询保持用户提交文本，安全检索查询只保留文字、数字和组合附加符号；placeholder 按图片点赞数、发布时间和 ID 倒序。 |
| 拼写容错 | 启用 Meilisearch 默认 typo tolerance，纯数字关闭容错，查询原文不被改写。 | 降低英文长词和模型名称输入错误造成的无结果率，同时避免年份、尺寸和版本数字产生误匹配。 | 沿用默认词长阈值并设置 `disableOnNumbers: true`；不生成“纠正后关键词”。 |
| 不支持范围 | 不支持拼音、同义词和语义搜索。 | 控制首版索引、词库和模型成本。 | 不配置拼音字段、同义词或向量能力。 |
| 结果排序 | 使用 Meilisearch 原生文字相关性顺序，完全同级时按 `likeCount DESC, publicAt DESC, imageId DESC`。 | 搜索意图始终优先，图片自身点赞数只作为同等文字相关作品的质量参考。 | 索引维护图片点赞数；后端和前端均不重新计算相关性或重排。 |
| 作者热度 | 作者总获赞数和粉丝数不参与关键词搜索。 | 作者级动态指标需要扇出更新其全部作品，并会让热门作者持续获得额外曝光。 | 作者热度只在作者主页、发现或后续推荐能力中另行设计。 |
| 分页与上限 | 首次 20、后续 40，直接使用 Meilisearch offset 分页且每个查询最多开放前 200 条。 | 用户不会无限浏览搜索结果，有限范围内原生 offset 成本可控且契约直接。 | 后端固定 limit；响应返回可空 `nextOffset`，客户端切换关键词时重置 offset。 |
| 数据一致性 | MySQL 与 Meilisearch 最终一致，不建立搜索结果快照。 | 搜索索引可重建，优先降低写链路耦合和分页状态成本。 | 发布/撤销通过 Outbox 重试同步；返回 DTO 前重新校验当前公开状态。 |
| 异步通道 | 搜索索引同步由 Outbox 调度器直接调用 Meilisearch，不经过 RabbitMQ。 | 搜索同步是短时、幂等、可重建的外部投影写入；现阶段再增加消息队列不会改善业务正确性。 | 复用 Outbox 的认领、重试和失败记录；RabbitMQ 继续只承载确有长耗时和削峰需求的生成任务。 |
| 事件载荷 | 索引同步事件只保存 `imageId`，消费时重新读取 MySQL 当前状态。 | 避免点赞、审批和撤销事件乱序时用旧快照覆盖新状态。 | 当前仍公开则按最新字段 upsert，否则删除对应索引文档；重复执行结果一致。 |
| 初始化与重建 | 正式索引不存在时自动初始化；已存在时仅允许管理员通过显式命令重建。 | 首次部署保持简单，同时避免应用重启或多实例启动意外触发全量重建。 | 日常增量同步自动运行；恢复、字段或配置升级时才执行低频重建命令。 |
| 无停机切换 | 后续重建写入临时索引，补齐增量后通过 Meilisearch index swap 原子切换。 | 直接清空正式索引会造成搜索不可用；仅全量复制又可能遗漏重建期间的业务变化。 | 切换前短暂停止索引调度、等待在途任务并补齐事件；失败时保留原正式索引。 |
| 失效候选补页 | MySQL 过滤失效候选后，后端继续读取后续 Meilisearch 候选，尽量补足本页。 | 允许最终一致时，撤销删除尚未同步不应让用户看到明显缺项或假空页。 | `nextOffset` 指向已检查的原始候选位置；保持搜索顺序、请求内去重并受 200 条总上限约束。 |
| 部署与持久化 | Meilisearch 使用固定版本的独立容器和独立持久化卷，初期可与后端同机部署。 | 独立服务便于升级和故障隔离；持久化卷避免容器重建后无谓地全量恢复。 | 只接入私有容器网络，不开放公网端口；版本升级必须显式执行，不使用 `latest`。 |
| 故障隔离 | Meilisearch 故障不阻止后端启动，搜索单独降级为 503。 | 搜索是可降级的派生能力，不应连带阻断发现、关注、详情、发布和撤销。 | 搜索不回退 MySQL；Outbox 保留并重试，服务恢复后继续同步。 |
| 初始化并发 | 多个后端实例只能由一个实例初始化缺失的正式索引。 | 多实例可能同时观察到索引不存在，必须避免重复全量导入和配置竞争。 | 使用 MySQL 跨实例锁包围“复查索引并初始化”，未获得锁的实例不重复执行。 |
| 索引备份 | 首版不单独要求定时导出 Meilisearch dump 或 snapshot。 | MySQL 是事实数据源，搜索索引可通过显式命令重建。 | 服务器磁盘备份可覆盖持久化卷；备份不是搜索正确性的唯一恢复手段。 |
| 密钥分权 | Master Key 只管理实例密钥；后端日常搜索和索引管理使用两个受限 Key。 | 搜索链路不需要写权限，分权可降低密钥误用或泄露后的破坏范围。 | Search Key 只允许查询正式索引；Admin Key 只允许维护正式索引和重建临时索引；前端不持有 Key。 |
| 超时与重试 | 前台搜索 1 秒连接、2 秒请求且不重试；后台同步 2 秒连接、5 秒提交、30 秒 task 等待并通过 Outbox 退避重试。 | 用户请求应快速失败，后台投影则应在服务恢复后自动追平。 | 临时错误持续重试并封顶为每 5 分钟一次；确定不可恢复的错误直接失败并告警。 |
| 搜索限流 | 每个登录用户或匿名可信客户端 IP 使用容量 10、每秒恢复 1 个令牌的进程内桶。 | 允许正常连续输入，同时限制单一来源高频消耗搜索、数据库和签名 URL 资源。 | 超限返回 429 与 `Retry-After`；内部补页只算一次；多实例后再迁移到网关或 Redis。 |
| 健康与告警 | 容器检查 `/health`；后端监控搜索可用状态、Outbox 积压和索引数量偏差。 | 首版没有集中监控平台，先通过有限的结构化日志暴露可操作异常。 | 只记录状态变化；Meilisearch 故障不拖垮后端；后续可平移到 Prometheus 或日志告警平台。 |
| 错误分类 | 只将本地非法事件、明确 `invalid_request` 和 `auth` 错误判为需要人工介入；未知、`internal` 与 `system` 错误继续低频重试。 | 保证相同请求确定无效时不会无限刷请求，同时避免新错误码或环境故障被误判后丢失同步。 | `index_not_found` 进入初始化恢复；失败事件保留，修复后允许管理员重放。 |
| Java 客户端 | 使用 Spring `RestClient` 直接调用 Meilisearch REST API，不引入官方 Java SDK。 | 项目已有相同 HTTP 调用方式，可复用 Jackson、超时和异常处理模式，并精确控制本迭代所需 API。 | 建立 Search/Admin 两个专用客户端 Bean；业务服务不直接拼接 URL、认证头或解析底层错误。 |

## 5. 设计与实现

| 职责 | 关键类/文件 | 说明 |
| --- | --- | --- |
| 接口入口 | `InspirationSearchController` | 匿名/登录搜索、客户端限流键与禁止缓存的 JSON 响应。 |
| 核心业务 | `InspirationSearchService`、`SearchTextNormalizer`、`SearchRateLimiter` | 输入规范化、候选补页、公开状态复核、分页与限流。 |
| 数据访问 | `GenerationImageMapper`、`OutboxEventMapper`、`V13__expand_outbox_retry_count.sql` | 索引全量读取、当前公开候选读取、事件认领与长期重试。 |
| 外部集成 | `MeilisearchSearchClient`、`MeilisearchAdminClient`、`SearchIndexInitializer` | 搜索/管理 Key 分权、结构化错误、首次初始化。 |
| 异步与运维 | `SearchIndexOutboxDispatcher`、`SearchIndexRebuildService`、`SearchHealthMonitor` | 增量同步、互斥重建、原子切换和状态告警。 |

Meilisearch 的 HTTP 路径、认证头、请求/响应 DTO 和错误解析集中在专用客户端层；业务服务不依赖底层 HTTP 细节。项目复用 Spring `RestClient` 与 Jackson，没有引入 Meilisearch Java SDK、OkHttp 或 Gson。

## 6. 数据模型与配置

Meilisearch 搜索投影只保存搜索所需数据：数值类型的 `imageId`、规范化标题、规范化最终正向提示词、`likeCount` 和 `publicAt`，不保存 OSS 对象键、签名 URL、作者总获赞数、作者粉丝数或完整公开 DTO。标题搜索属性排在最终正向提示词之前；启用 prefix search 和默认 typo tolerance，纯数字关闭容错，查询使用 `matchingStrategy: frequency`，`maxTotalHits` 固定为 200。排序规则固定为 `words → typo → proximity → attributeRank → wordPosition → exactness → likeCount DESC → publicAt DESC → imageId DESC`。

`application.yaml`、`application-local.example.yaml` 和被 Git 忽略的 `application-local.yaml` 同步维护 `app.meilisearch` 配置结构，包括启用开关、端点、两个受限 Key、索引名、前后台超时、批量大小、启动重建开关和转发地址信任开关。默认关闭搜索集成且不保存真实 Key；Master Key 只属于 Meilisearch 部署环境。

作品审批为公开、撤销公开以及公开图片实际点赞状态发生变化时，在业务事务内写入 `PUBLICATION_SEARCH_INDEX_SYNC` Outbox 事件。事件载荷只包含 `imageId`；不把标题、提示词、点赞数或公开状态快照写入事件。搜索索引调度器直接认领该类 Outbox 事件，不投递 RabbitMQ，并在处理时重新读取 MySQL：作品当前仍为 `APPROVED` 且 `public_at` 非空时，用最新投影覆盖式 upsert；否则幂等删除对应 Meilisearch 文档。这样即使事件重复或处理顺序与业务发生顺序不同，索引最终也会收敛到数据库当前状态。

Meilisearch 写操作返回异步 task 后，调度器必须等待并确认 task 成功，才能把 Outbox 事件标记为已发布；临时故障按 Outbox 规则持续退避重试，确定不可恢复的错误才保留失败记录供监控和人工重放。这里不设置 RabbitMQ 死信队列。高频点赞产生的重复同步先依靠幂等覆盖保证正确性；若真实负载表明确有必要，再按 `imageId` 合并待处理事件，不在首版引入额外聚合表。

后台调度器连接 Meilisearch 的连接超时为 2 秒，新增、更新或删除的提交请求超时为 5 秒；取得异步 task UID 后最多等待 30 秒确认结果。连接失败、超时、HTTP 429、服务端 5xx 或 task 暂未完成视为临时错误，Outbox 依次延后 5 秒、30 秒、2 分钟和 5 分钟，之后最多每 5 分钟重试一次，服务恢复前不因固定次数耗尽而丢弃事件。每次重试仍按 `imageId` 读取 MySQL 最新状态。

无法解析的内部事件、Meilisearch 拒绝文档结构或权限不足等确定不会自行恢复的错误不得无限重试，应标记为需要人工介入并记录不含密钥、原始正文和签名 URL 的错误摘要。事件必须保留，修复配置、代码或数据后允许管理员重新置为待处理并重放。task 等待超时不等于 task 已失败；允许后续幂等重提并以最终数据库状态覆盖。

错误分类必须使用固定规则而不是匹配异常消息文本：本地事件无法解析、缺少或非法 `imageId`、无法从 MySQL 当前数据生成合法投影时直接进入人工介入状态；网络异常、连接或读取超时、HTTP 408/429/5xx 进入临时重试；HTTP 401/403 进入人工介入状态。Meilisearch task 为 `enqueued/processing` 时继续等待，超过期限后按临时错误处理；`succeeded` 时完成事件；`failed` 时依据结构化 `error.type` 和 `error.code` 分类。

task 的 `invalid_request` 与 `auth` 默认需要人工介入，但 `index_not_found` 例外进入“复查、初始化索引、重试”恢复流程；`internal`、`system` 和尚未识别的错误类型继续按最长 5 分钟间隔低频重试并产生告警。未知错误不得直接标记失败，避免 Meilisearch 版本变化引入新错误码后停止同步。磁盘满、文件句柄耗尽等 `system` 错误可能需要运维处理，但修复环境后原事件应自动恢复。

应用启动时检查正式索引是否存在：不存在时创建索引、写入完整设置，并按 `imageId` 稳定分批读取 MySQL 当前公开作品完成首次初始化；任一 Meilisearch task 未成功都不能把初始化视为完成。正式索引已经存在时，启动过程只校验其可访问性，不自动清空、覆盖或全量重建。

多实例部署时，初始化前使用 MySQL 跨实例锁串行化“再次确认索引不存在并完成初始化”的流程；没有取得锁的实例不得并行创建或导入，但这不阻止该实例继续提供搜索以外的接口。初始化失败保留可诊断状态，后续重试仍需重新取得锁。

后续恢复或索引字段、匹配和排序配置升级时，由管理员显式执行低频重建命令，不暴露公开 HTTP 管理接口。命令创建带唯一后缀的临时索引，先写入完整设置和 MySQL 全量公开投影，再暂停搜索索引 Outbox 调度器并等待在途任务结束；随后按事件 ID 补齐重建期间产生的 `PUBLICATION_SEARCH_INDEX_SYNC` 事件，确认所有 task 成功后通过 Meilisearch index swap 原子切换。切换完成后恢复调度器，切换水位之后产生的事件继续更新新的正式索引。

重建命令必须可重复执行且同一时刻只允许一个实例运行。全量导入、增量补齐或原子切换任一步失败时，原正式索引继续提供搜索，临时索引保留供诊断或安全清理；旧正式索引在切换后短期保留以支持回切，确认新索引稳定后再由管理员删除。

## 7. API 与权限

搜索接口返回公开作品 DTO 列表和可空 `nextOffset`。首次请求不带 offset，最多返回 20 项；后续请求携带服务端上次返回的 offset，最多返回 40 项。客户端不传 `limit`、匹配策略或排序参数；offset 必须是非负整数且小于 200。

Meilisearch 每次返回候选 ID 后，后端按原始顺序查询并校验 MySQL。若候选被过滤，则从已检查位置继续分批查询，直到有效 DTO 达到本页上限、Meilisearch 没有更多候选或已检查到第 200 个结果。响应中的 `nextOffset` 是下一条尚未检查的 Meilisearch 原始位置；因此它可以大于本页 `items` 数量。单次请求内重复出现的 ID 只返回一次，但其原始位置仍计入 offset 推进。只有确认没有后续可检查候选或达到 200 条上限时才返回 `nextOffset: null`。

搜索接口为 `GET /api/inspirations/search?q={keyword}&offset={nextOffset}`，允许匿名和登录用户访问。登录用户返回当前用户的点赞状态；匿名结果的点赞状态固定为未点赞。缺少查询词、纯空白、规范化后超过 100 个字符或 offset 非法时返回统一参数校验错误；纯符号合法输入执行 placeholder search。Meilisearch 不可用时返回 `503 SEARCH_UNAVAILABLE`，不回退到 MySQL 搜索。响应使用 `Cache-Control: private, no-store`，该响应头只约束搜索 API JSON，不改变 OSS 图片响应的浏览器缓存策略。

前台搜索连接 Meilisearch 的连接超时为 1 秒，单次请求总超时为 2 秒，同一个用户 HTTP 请求内不自动重试。连接失败、超时、429、5xx 或 task 服务不可用均统一映射为 `503 SEARCH_UNAVAILABLE`，不得把底层状态和异常正文透传给客户端。

后端必须根据 MySQL 当前公开状态校验候选作品并即时生成所需签名 URL。

搜索接口在调用 Meilisearch 前执行令牌桶限流。登录请求以 `userId` 为键，匿名请求以可信客户端 IP 为键；桶容量为 10，每秒恢复 1 个令牌。一次客户端 HTTP 请求只消耗一个令牌，服务端因 MySQL 过滤而继续获取候选不再次计数。超限返回 HTTP 429、统一错误码 `SEARCH_RATE_LIMITED` 和 `Retry-After` 秒数。

进程内最多保存 20,000 个搜索限流桶，超过边界时优先清理长期未访问项；桶只保存限流标识、令牌和时间，不保存查询词或结果。部署反向代理后只能采用由受信代理覆盖写入的客户端地址，不得无条件信任外部传入的 `X-Forwarded-For`。首版单实例限流不承诺跨实例全局精确，扩展为多后端实例时迁移到网关或 Redis。

## 8. 异常场景、可靠性与安全

- Meilisearch 不可用时只影响搜索接口，不影响发现、关注、详情、发布或撤销；错误响应不得暴露服务地址、索引名或底层异常。
- Meilisearch 连接失败或正式索引尚未初始化完成时，不把后端整体标记为不可用；搜索 readiness 单独反映并统一返回 503。
- Outbox 同步失败必须可重试和监控；索引可以从 MySQL 重建，不能反向覆盖 MySQL。
- 重复、延迟或乱序的索引事件必须通过消费时读取 MySQL 最新状态收敛，不能按事件产生时的旧状态盲目写入。
- 自动初始化只能在正式索引确实不存在时发生；重建失败不得删除、清空或替换仍可用的正式索引。
- 索引短暂滞后导致已撤销 ID 被召回时，后端按当前公开状态过滤；已加载旧项打开详情时仍按详情接口的当前状态处理。
- 补页查询只允许沿 offset 向后推进并受 200 条总上限约束；不得因失效候选从头重查、无限递归或改变 Meilisearch 的原始相关性顺序。
- 查询最多开放前 200 条结果，不允许客户端扩大 limit、offset 或 `maxTotalHits`。
- 限流状态和日志不得使用原始查询词作为键；来自不受信来源的转发 IP 请求头不能用于绕过匿名限流。
- 非法或超过范围的 offset 返回统一参数校验错误。
- 签名 URL 即时生成且不持久化，不得进入搜索索引、日志、埋点或错误监控。

Meilisearch 容器每 10 秒访问一次自身 `/health`，单次检查超时 2 秒，连续失败 3 次后标记不健康。后端只在搜索从可用变为不可用时记录一次 `WARN`，恢复时记录一次 `INFO`，不得对每次健康检查或重试重复刷日志。需要人工介入的 Outbox 事件首次产生时记录一次 `ERROR`；最老临时重试事件滞留超过 10 分钟时记录 `WARN`，追平后记录一次恢复信息。

每 10 分钟比较 MySQL 当前公开作品数与正式索引文档数，数量差异连续超过 10 分钟才告警，不因短暂最终一致自动触发重建。数量相同不代表内容完全一致，该检查只用于发现明显异常。首版告警输出为结构化控制台日志；日志只允许包含错误分类、task UID、Outbox ID、`imageId` 和持续时间，不记录查询词、标题、提示词、API Key、签名 URL 或 Meilisearch 原始错误正文。
