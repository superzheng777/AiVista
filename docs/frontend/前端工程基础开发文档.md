# AiVista 前端工程基础开发文档

> 对应迭代：前端迭代 0——工程基础
> 当前状态：已完成
> 维护规则：本文记录工程运行、通用架构、请求、认证和联调约定；通用能力变化时必须同步修改。

## 1. 项目入口与常用命令

在 `frontend/aivista` 目录执行：

```powershell
pnpm dev
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm test:architecture
pnpm build
pnpm start
```

PowerShell 执行策略阻止 `pnpm` 时使用 `pnpm.cmd`。开发服务默认地址为 `http://localhost:3000`，也支持 `http://127.0.0.1:3000`。`next.config.ts` 通过 `allowedDevOrigins` 显式允许 `127.0.0.1` 访问开发资源，避免 Next.js 拦截 HMR 请求导致客户端初始化受阻、登录入口停留在加载状态。

## 2. 基础能力

| 范畴 | 当前约定 |
| --- | --- |
| 框架与样式 | Next.js App Router、TypeScript、Tailwind CSS、shadcn/ui。 |
| 数据与表单 | TanStack Query 管理浏览器端服务端状态与内存缓存；正式表单使用 React Hook Form + Zod，`@hookform/resolvers/zod` 连接两者。 |
| 请求与类型 | Axios 处理浏览器请求；接口 DTO 在 feature API 层映射为领域模型。 |
| 本地状态 | 跨页面客户端状态统一由 Zustand 管理；组件按 selector 读取认证、登录弹窗和实时状态，局部 UI 保留组件状态。 |
| 测试 | Vitest + React Testing Library 做组件/交互单元测试；`pnpm test` 单次运行、`pnpm test:watch` 监听；配置见 `vitest.config.mts` 与 `vitest.setup.ts`，测试文件与被测模块同目录命名 `*.test.tsx`。缓存优化曾使用一次性 Playwright 脚本完成桌面/移动视口验收；验收后已清理脚本、专用依赖与运行命令，长期回归保留在 Vitest 中。 |
| 主题 | 使用语义 token，如 `bg-background`、`text-foreground`、`bg-card`；颜色实际值由 `globals.css` 集中管理。 |

## 3. 工程结构与关键代码位置

```text
src/
├── app/       # App Router 路由、_ui 应用壳和路由适配、_bootstrap 初始化
├── widgets/   # 生成工作台、资产库、个人主页、通知中心、灵感列表/搜索
├── features/  # 业务能力：api、model、ui、lib
├── entities/  # 前端领域模型
├── shared/    # HTTP、通用 UI、工具与配置
└── components/ui # shadcn/ui 生成或维护的无业务原语
```

依赖方向固定为 `app → widgets → features → entities → shared`。`components/ui` 只保留无业务原语，可以引用 shared。跨业务页面组合已归入 widgets，应用壳仍在原页面中挂载；路由、状态生命周期和布局保持原有行为。所有资源 ID 使用字符串；用户模型区分 `CurrentUser` 与 `PublicUser`，不新增万能 `User` 类型。

模块内使用相对路径，跨模块使用 `@/`。文件/目录用 kebab-case，组件/类型用 PascalCase，Hook 用 `useXxx`。api 放 HTTP 与 DTO 映射，model 放模型、状态及业务派生，ui 放组件，lib 放辅助函数；没有内容的分段不建空目录。只提取已有职责，不为行数拆散一个表单或状态机。

`architecture/boundaries.mjs` 接入 ESLint，对别名和相对路径统一解析后检查依赖方向、feature 横向依赖、widgets 隔离、两个跨实体类型例外和测试 fixture。普通导入、动态导入、re-export 和内联 `import("...").Type` / `typeof import("...").Value` 均受检查；内联限定名按最左侧公开导出判断，整模块类型不能绕过符号白名单。`architecture/public-api.json` 是明确到文件及导出符号的公开入口清单；新增跨模块调用时需同时评估归属和登记入口，禁止用通配目录绕过。修改规则后运行 `pnpm test:architecture`，其中包含真实 ESLint 解析测试。

| 核心模块 | 职责与阅读入口 |
| --- | --- |
| `app/_ui/app-shell.tsx`、`app/_bootstrap/` | 页面导航壳、认证与原生 WebSocket 初始化、事件分发及重连清理 |
| `widgets/generation-workspace/` | 会话选择、桌面侧栏/移动抽屉、对话历史与详情；生成表单仍在 `features/generation` |
| `widgets/asset-library/`、`widgets/user-profile/` | 页面组合、查询与操作编排；卡片、分组、资料表单和内容区域分别有独立文件 |
| `widgets/notification-center/` | 消息中心、分类列表、分页与图片详情；两类通知 API 仍在各自 feature |
| `features/notifications/api/notification-api.ts` | 官方/互动共用的联合未读查询与类型；URL 和缓存 key 保持现有契约 |
| `entities/image-resource/`、`entities/creation-session/` | 图片资源/缓存/详情基础组件，以及创作会话/事件/表单类型 |
| `entities/user-event-stream/` | 一个跨业务事件流 store，持有连接状态、会话提示和刷新信号 |
| `features/image-access/` | 私有/公开缩略图读取与按需提前 60 秒续签；保留有效旧图，不下沉为无业务 UI |

`QueryProvider` 位于 `src/shared/api/query-provider.tsx` 并在根布局接入。Query 缓存仅保存浏览器内存中的服务端响应；业务请求统一在 feature 的 `api` 层将 DTO 映射为领域模型。页面局部交互使用组件状态；跨页面客户端状态统一使用 Zustand，不在 Store 镜像接口资源列表或聊天历史。
会话进入 `anonymous` 时清空 Query 缓存；登录身份变化时重置已有查询，连同公开列表中的当前用户点赞字段一并隔离。同一账号资料编辑与 Token 刷新不重置列表。

图片资源列表分别使用个人 30 分钟策略与公开浏览保留策略，完整清单、局部修改的状态保留规则和失效事件见 [资源列表缓存模块](modules/资源列表缓存模块.md)。不修改生成会话、轮次与通知的全局默认策略。

### 状态归属与初始化

| 归属 | 内容 | 生命周期 |
| --- | --- | --- |
| `auth-store.ts` | Access Token、当前用户、认证阶段与认证操作 | 内存 Store，不持久化 Token。 |
| `auth-dialog-store.ts` | 跨页面登录弹窗开关 | 组件按 selector 订阅；内容关闭后卸载，初始化组件卸载时关闭弹窗。 |
| `user-event-stream-store.ts` | 连接状态、重连次数、会话结果提示、REST 刷新信号、快照同步/重连入口 | 账号变化、退出或连接初始化组件卸载时复位。 |
| TanStack Query | 会话 turns/items、资产、作品、通知等服务端快照和请求状态 | WebSocket 合并或使查询失效，不复制到 Zustand。 |
| 组件状态 / RHF + Zod / URL | 局部开关和选择、表单草稿及校验、可导航的会话/图片/搜索参数 | 由页面语义决定，不因使用 Zustand 而全部全局化。 |

根组件在 QueryProvider 内平铺 AuthInitializer、UserEventStreamInitializer、页面与 AuthDialog。前者恢复认证、配置 Axios 回调并隔离身份缓存；后者负责 原生 WebSocket、连接序号、心跳和重连计时器，向实时 Store 安装 syncCreations/retryNow 操作，清理时撤销操作并复位状态。连接回调同时校验生命周期、连接序号与当前用户，避免旧账号事件污染新状态。初始化组件不包装 children、不提供业务 Context；组件直接使用 Store selector，多字段派生对象使用 useShallow，避免订阅整个 Store。以上操作只在客户端 effect/事件中执行，不在服务端渲染期间写入全局 Store。

## 4. 通用开发约定

- 页面和 UI 只使用领域模型；`shared/api` 只处理无业务归属的 HTTP 基础设施与统一响应，具体业务请求归入对应 Feature 的 `api`。
- 浏览器请求只使用 `/api/*` 相对路径，不在业务代码写 Spring Boot 地址。
- 私有签名 URL 仅保存在 SPA 内存；不得写入持久化存储、URL、日志、埋点或错误监控。页面使用 `Referrer-Policy: no-referrer`。
- 公开页面按实际目标选择渲染方式；当前 `/inspirations?imageId={imageId}` 是客户端单图详情，`/users?userId={userId}` 是客户端作者主页，不做单作品 SSR SEO。已登录业务页以客户端请求为主。

## 5. 配置与环境

开发环境中，REST 与原生 WebSocket 均由 Next.js `/api/:path*` rewrite 转发至 BACKEND_ORIGIN（默认 http://localhost:8888，不含 /api）；Next 内置升级转发支持 /api/ws/events，不保留专用流式 Route Handler。浏览器始终同源访问，手机局域网访问也沿用页面主机。`.env.local` 不提交。

认证成功后，每个浏览器标签页维持一条用户级 WebSocket。首帧发送 Token，收到 user.ready 后 sync 活动创作；creation.text.delta 追加文字，creation.item.upserted 校正完整项，creation.snapshot 修复重连/序号缺口，creation.updated 更新状态。审核与互动事件触发 REST 缓存失效。创建、取消和表单通过 HTTP 独立执行，不等待连接就绪。15 秒心跳、45 秒失联判断、带抖动的指数重连上限 15 秒；账号切换/退出清理旧连接。具体帧见[创作通信协议](../architecture/creation-protocol.md)。

本轮只保证单实例开发环境联调。未来静态部署仍需另行实现和验证同源 REST 与 WebSocket Upgrade 代理；当前保留 Next rewrite，尚未启用 output: export，不引入生产代理配置。

## 6. 认证、请求与联调

- Access Token 仅保留在内存，请求使用 `Authorization: Bearer <accessToken>`。
- Refresh Token 由 HttpOnly Cookie 管理。认证 Store 统一执行 Single Flight 刷新，同一标签页内 Axios 与 WebSocket 共用进行中的刷新请求；Axios 收到 `40100` 时调用该入口并最多重放一次原请求，WebSocket 鉴权失败后调用该入口并重连。刷新接口返回 `40102` 时由 Store 清除会话；跨标签页不共享单飞，刷新结束后允许再次刷新。
- 浏览器完整刷新后，`AuthInitializer` 只请求 `GET /api/users/me`；不得绕过拦截器直接调用刷新接口。
- 网络、超时或服务端异常保留当前登录状态并提供重新连接；匿名受保护路由由 `AppShell` 返回首页。
- 认证具体契约以 [后端用户模块](../java/modules/用户模块.md) 为准。
