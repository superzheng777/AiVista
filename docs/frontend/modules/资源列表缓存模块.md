# AiVista 资源列表缓存模块

> 对应迭代：跨模块优化——资源列表缓存
> 当前状态：已完成（自动化回归通过，真实 OSS / 后端联调边界见第 9 节）
> 维护规则：本文统一记录列表缓存期限、局部更新、失效事件和验证结果；各页面文档链接本文，后端业务事实仍以 Java 模块文档为准。

## 1. 目标与范围

在同一浏览器标签页内切换页面时复用已加载列表及其图片 URL，减少列表请求和重复签名；已知操作结果直接修改内存，只有需要服务端完整快照时重新请求。覆盖资产、引用图片选择器、本人作品与点赞、发现、关注、搜索和他人主页。生成会话、创作轮次与消息列表保留原实时策略。

## 2. 已确认约束

- Query 缓存保存响应对象和 URL，仅存在运行时内存，不写入 localStorage、sessionStorage、IndexedDB 或 Service Worker。整页刷新后重新获取。
- `staleTime` 从最近一次完整查询成功起计算；过期表示可重新请求，不会删除旧数据，也不是定时轮询。
- `gcTime` 从最后一个订阅者卸载后计算；期间重新订阅会取消回收，再次离开重新计时。持续使用的列表不会因为超过 gcTime 被回收。
- 局部收藏、点赞、删除、单图 URL 刷新不延长整份列表的 freshness，也不清除已经存在的失效标记。
- 图片 URL 到期时间、Query 数据保留时间和浏览器 HTTP 图片缓存是三个独立机制。列表仍在缓存并不表示 URL 永久有效。
- 删除个人资产与撤销发布是独立操作；删除资产不会撤回已有公开作品及其点赞。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 个人资源 | staleTime 与 gcTime 均为 30 分钟。 | 已知变更可及时更新，未覆盖的跨设备变化接受暂时陈旧。 | 重新挂载、恢复焦点或网络时，仅在失效/过时时重新请求。 |
| 公开浏览 | staleTime 为 Infinity，gcTime 为 10 分钟；关闭挂载、焦点和网络恢复自动请求。 | 用户来回浏览保持已有结果。 | 不使用“staleTime 10 分钟＋每次访问重写更新时间”模拟续租；续租只由 gcTime 自然完成。 |
| 局部更新 | 只修改已存在的 Query 数据，不创建缺少其他成员的伪完整列表。 | 避免更新一张图片后把未读取过的列表误标为已加载。 | 更新字段、列表成员时保留分页元数据、更新时间和失效标记。 |
| 查询隔离 | 发现、关注、规范化搜索词、作者和点赞可见性分别建键。 | 不混用不同来源的分页和权限结果。 | 登录身份变化时重置缓存，退出时清空。 |
| URL 复用 | 缓存可用时不请求列表，直接复用原 URL。 | 避免签发无用的新 URL。 | 不采用“请求新 URL 后丢弃”的策略，不新增专门的刷新请求合并器。 |

## 5. 页面、路由与交互设计

| 列表或入口 | 策略 | 返回页面时的行为 |
| --- | --- | --- |
| `/assets` 资产列表 | 个人 30 分钟；键 `['assets']` | 缓存新鲜且未失效时零列表请求；过时/失效时先显示缓存并后台更新。 |
| 生成页资产引用选择器 | 与资产页共用键和个人策略 | 使用同一份列表；生成成功、删除或收藏在两个入口同步。 |
| 本人主页作品 | 个人 30 分钟；键 `['publication','mine']` | 发布提交和审核事件可提前失效；撤销发布直接移除。 |
| 本人点赞 | 个人 30 分钟；键包含本人 ID 与 `self` | 已加载列表按点赞成功结果增删，不为已知结果重拉列表。 |
| 发现 / 关注 | 公开 Infinity / 10 分钟；独立键 | 缓存仍在则复用已加载页；关注关系变更主动更新关注流。 |
| 搜索 | 公开 Infinity / 10 分钟；规范化关键词独立键 | 重复提交相同关键词复用；其他已缓存关键词也可恢复其已加载页。 |
| 他人主页作品 / 公开点赞 | 公开 Infinity / 10 分钟；作者 ID 隔离 | 缓存仍在则复用；允许暂时显示其他用户修改前的快照。 |
| 生成会话摘要 / 会话详情 | 摘要默认 staleTime 0；详情 staleTime Infinity，gcTime 保持默认 5 分钟 | 详情复用 turns/items 缓存，由 SSE 合并；首连/重连主动 REST 对账。完整规则见《生成工作台模块》。 |
| 官方 / 互动消息及未读数 | 保持原有按需读取和事件刷新 | 不套用图片资源长缓存。 |

公开列表的“手动刷新”当前指浏览器整页刷新；本次没有新增页面刷新按钮。缓存被回收、首次访问或显式业务更新仍会请求。10 分钟内返回再离开会重新开始未使用回收计时；这不意味着浏览器永久保留所有列表。Query 缓存保存 DTO，不保存图片二进制；大量搜索词、作者和无限分页仍会增加内存，当前不新增持久化或无限保留所有历史页面。

## 6. API、前端模型与状态管理

| 触发 | 处理 | 是否请求列表 |
| --- | --- | --- |
| 收藏 / 取消收藏 | 乐观修改已有图片的 favorited，失败回滚对应状态。 | 否。 |
| 点赞 / 取消点赞 | 乐观同步卡片、详情与已有列表的点赞字段；成功后增删本人已缓存点赞列表成员，失败回滚。 | 否；不改变他人点赞列表的成员归属。 |
| 删除个人资产 | 乐观移除资产；成功后同步引用选择器及生成轮次的无 URL 占位。 | 否；公开作品、本人发布及点赞列表保留。 |
| 取消审核 / 撤销发布 | 从已有发布、发现、关注、搜索及点赞列表移除；资产保留图片并重置发布状态，生成轮次保留原图片引用。 | 否；不把已删除资产恢复到资产列表。 |
| 发布提交成功 | 局部更新图片为 PENDING，失效本人作品列表，以服务端快照补齐文案、排序等信息。 | 活跃作品列表立即请求，未活跃列表下次使用时请求。 |
| 携带图片资产的 creation.item.upserted SSE | generation 项有 assets 时失效资产共享查询，不用展示项拼出完整图片 DTO；父创作取消后的迟到图片同样处理。 | 活跃列表立即请求，否则下次使用时请求。 |
| 发布审核终态 SSE | 在事件回调中失效资产和本人作品查询；通知保留原有刷新版本信号。 | 活跃列表立即请求，否则下次使用时请求；不在页面挂载时重复消费历史版本。 |
| 关注 / 取消关注 | 更新作者信息，并以 refetchType: all 失效关注流。 | 已缓存关注流即使未活跃也请求，避免关闭自动刷新后长期保留旧关注集合。 |
| 点赞列表隐私改变 | 删除对应公开点赞查询并刷新作者资料。 | 按新的权限和页面使用情况读取。 |
| 已读取到公开单图 40401 | 移除已缓存公开列表中的失效作品；保留个人资产。 | 不重拉全部列表；网络故障不当作撤销发布。 |
| 缩略图过期或加载失败 | 按访问上下文获取私有/公开单图 DTO，将 URL 同步到已有缓存。 | 否；已知过期缩略图接近视口时才申请，实际读取失败限制重试。 |

资源查询键与数组、分页、单图三种数据形状统一定义在 `resource-queries.ts`，各功能 API 重新导出既有键，保持缓存身份不变。缓存读取、取消与修改复用这份定义；不按页面另写一套查询族判断。

点赞卡片与公开详情共用 `useImageLike({ image, sourceQueryKey, userId })`。点击时固定目标点赞状态与 `publicationVersion`；`onMutate` await 取消查询后，仅通过 `readResource` 读取这次点击的来源缓存，不根据不同缓存的更新时间猜测数据来源。来源图片消失或发布版本变化时停止提交，提示刷新；缓存已达到目标状态时不重复加减计数。其他已有缓存只同步相同发布版本的点赞字段。同一 QueryClient 内以图片 ID 共享 pending 状态，重复点击不排队，不同图片可并行。列表详情传递所属列表键；通知等列表外入口和直达详情使用自己的单图查询键。资产页收藏复用资源字段保护。

`cancelResourceQueries(client, imageIds)` 取消资产、本人发布、作者作品、点赞列表及灵感分页查询，包括当前尚未包含目标图片的列表，以覆盖尚未返回的首屏和分页请求。两类公开单图详情只取消目标图片 ID，不影响其他图片详情；会话、作者资料和通知查询不在范围内。取消阻止 Query 的旧结果写回，不代表底层 HTTP 必然中断。

`optimisticResourceUpdate` 仅允许修改 `favorited`、`likedByCurrentUser`、`likeCount`，按缓存和图片保存这些字段的快照。提交期间只处理发生变化的 Query，将待确认字段覆盖到新数据上，保留标题、URL、分页等其他内容；初始应用、提交确认和回滚才遍历已有资源缓存。点赞保护及回滚均校验原发布版本，避免旧操作覆盖新发布数据。结束前再次取消期间发起的相关查询，成功保留目标字段，失败只恢复本次字段，然后解除订阅。点赞成功且来源仍为同一发布版本后，才改变本人已加载点赞列表成员；已有不同版本的成员不受影响。登录身份变化前释放已安装的保护，旧操作的迟到结果不能再通过该保护修补新身份缓存。这里不提供跨标签页协调，也不改变删除操作现有的整列表回滚边界。

局部更新集中使用 `query.setState({ data })`，有意保留 `dataUpdatedAt` 与 `isInvalidated`；普通 `setQueryData` 默认会把整份查询视为刚刚更新，可能掩盖已收到的失效事件。完整查询仍由 TanStack Query 正常维护状态。删除后的公开详情保留当前快照供关闭和错误展示，不把详情数据清空来隐式触发新请求。

服务端列表 API 的 `Cache-Control: private, no-store` 不妨碍应用在运行时内存保留已解析数据。图片 HTTP 响应的缓存规则则由 OSS 对象元数据控制；复用完全相同的 URL 才有机会命中已有图片响应，签名参数变化可能形成新缓存键。图片缓存是否命中由有效期、响应头及浏览器决定；签名过期阻止后续向 OSS 请求，不能删除客户端此前已缓存的图片字节。

## 8. 异常场景、可靠性与安全

- 网络失败保留已有数据；收藏/点赞失败回滚局部字段。图片加载失败不触发整表循环刷新。
- 公开流不订阅全站作品变动。其他设备或其他用户的撤销、点赞、隐私变化可在旧快照中延迟反映；下次完整读取以服务端权限为准，不能用客户端缓存代替鉴权。
- SSE 不回放所有历史事件。断线期间遗漏的资产/作品变更由个人列表后续过时刷新或整页刷新补齐；消息与生成会话继续执行其原有重连对账。
- 登录身份变化重置查询；匿名时清空，避免复用上一个账号的资产及当前用户点赞字段。同一用户资料编辑和 Token 更新不清空列表。
- 不把“禁止应用持久化签名 URL”解释成禁止浏览器遵循 HTTP 响应头缓存图片。本次未修改 OSS 权限、对象元数据、签名算法或签名有效期。
