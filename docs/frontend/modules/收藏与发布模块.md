# AiVista 收藏、审核发布与官方消息模块

> 对应迭代：前端迭代 4——收藏、异步文本审核发布与官方消息

> 当前主页入口：`/profile` 跳转到 `/users?userId={currentUserId}`；本人在作者主页的“作品”页签查看 `PENDING` 与 `APPROVED`，审核中作品在卡片右上角标注状态。SSE 与列表缓存更新以本文第 6 节及资源列表缓存模块为准。
> 当前状态：已完成（实现与真实后端联调验收通过）
> 维护规则：本文记录当前迭代的前端范围、交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

本迭代让用户从资产图片提交发布审核，在个人中心查看自己的发布结果，并通过全局官方消息获知审核终态。

- 资产页提供发布入口及当前发布状态；发布后的作品浏览统一进入作者主页。
- 作者主页依次展示资料 Hero、作品工具栏和图片内容区；“作品”展示审核中与已公开图片，“点赞”及其隐私规则由社区模块维护。
- 发布图片不创建公开副本。图片始终在私有 Bucket，后续灵感页使用后端签发的短期 URL。
- 资产收藏已持久化在图片自身的 `isFavorited` 字段；支持单图和批量收藏/取消收藏，不增加“只看收藏”筛选。
- 删除资产与删除发布独立。删除发布不会删除原图；删除资产后，已发布图片仍可在后续灵感页展示。

本迭代不实现灵感流、公开作品详情、点赞、关注或跨标签页自动同步。

## 2. 已确认约束

- 资产、个人发布和公开作品共用统一图片 DTO。列表与详情字段不拆成两套 DTO，但 URL 按用途裁剪。
- DTO 字段为 `imageId`、`imageUrls`、`createdAt`、`favorited`、`finalPrompt`、`finalNegativePrompt`、`generationConfig`、`publicationReviewStatus`、`publicationVersion`、`publicAt`、`title`、`description`。`imageUrls` 固定含 `thumbnail`、`display`；列表渲染 `thumbnail`，详情直接复用 `display`，原图不随 DTO 返回而由下载接口单独签发。`generationConfig` 包含 `width`、`height`、`requestedImageCount`、`promptExtend`。
- `null` 只表示业务值不存在，不表示权限裁剪。所有图片详情都展示最终正负提示词和生成配置。
- 资产和个人发布列表均全量请求，不分页。资产按 `createdAt DESC, imageId DESC` 显示；个人发布按提交审核时间及 `imageId` 倒序显示。审核通过只改变状态，不改变该项位置。
- 个人发布列表只包含 `PENDING` 与 `APPROVED`。前者显示“审核中”，后者显示“已发布”；`REJECTED`、`FAILED` 仅通过官方消息告知。
- `PENDING` 详情提供“取消审核”，`APPROVED` 公开详情的更多菜单提供“撤销发布”；两者调用同一个删除发布接口，不删除资产原图。
- 发布审核以图片的 `publicationReviewStatus` 为唯一防重依据：`PENDING` 时再次提交直接返回 `202 PENDING`，不会创建第二个审核任务；`APPROVED` 时必须先撤销发布。
- 签名 URL、提示词、发布文案和消息正文只保留在内存，不写入本地持久化存储、页面 URL、埋点或错误监控。

## 5. 页面、路由与交互设计

### 5.1 资产页 `/assets`

资产页右上角的“批量操作”中提供下载、删除和收藏。所选图片中只要有一张未收藏，操作显示“批量收藏”并将全部选中项设为收藏；全部已收藏时显示“取消收藏”并将全部选中项设为未收藏。发布可从单张资产卡片或详情发起，不支持批量发布。

资产详情吸顶工具栏提供下载、收藏与更多菜单；菜单中的“发布”打开模态表单，复制与删除也位于该菜单。标题为必填 `1–100` 字，描述为必填 `1–500` 字，字段下方说明文案会发送至内容安全服务审核。

表单提交期间禁止重复提交并显示进行中反馈。成功收到 `202 PENDING` 后关闭表单，立即将详情对象与资产缓存同步为 `PENDING` 并提示审核已提交。资产 DTO 为 `PENDING` 时，前端不打开表单而提示“该图片正在审核中”；为 `APPROVED` 时“查看发布”进入公开详情。若前端快照过期或响应丢失，后端仍会对 `PENDING` 返回 `202 PENDING`，且不会创建第二个审核任务。验证与其他业务错误均保留输入并显示后端返回的安全业务文案；网络错误显示网络重试提示。

发布表单成功后局部同步 PENDING；发布终态 SSE 在全局回调中使资产与本人作品缓存失效，活跃列表立即请求，其余下次使用时请求。收藏成功不再全量重拉列表。

### 5.2 本人作者主页 `/users?userId={currentUserId}`

`/profile` 仅作跳转入口。本人主页从上到下为资料 Hero、作品工具栏和内容区；作品页签读取本人发布列表，仅含审核中与已公开作品，不显示独立发布数量栏。点击已公开作品时，以当前页为背景打开本地公开详情覆盖层，History state 记录图片且保留来源 URL；公开作品与审核中作品分别在其可用集合内上下切换，公开详情使用 `replaceState`，审核中详情不改变 URL。公开卡片链接仍为 `/inspirations?imageId={imageId}`，供新标签直接访问。

窄屏按同一顺序收缩布局，保留可访问控件与可见焦点。列表加载中显示骨架或等效占位；空态区分作品和点赞，请求失败保留已显示数据并提供重试。完整主页规则见[社区身份与互动模块](社区身份与互动模块.md)。

审核中详情展示图片、提示词、尺寸、生成数量、时间、等待审核提示与“取消审核”；取消前确认资产仍保留。已公开详情展示标题、描述、作者工具栏与公开日期，作者从更多菜单直接撤销发布。两类成功操作均关闭当前详情并同步移除已有发布/公开列表项，失败保留内容并显示错误。详情布局复用 ImageDetailShell，按场景组合操作。

### 5.3 官方消息抽屉

认证用户在桌面端侧边栏底部、移动端底部导航看到铃铛。无未读时不显示角标；有未读时用数字角标，超出两位显示 `99+`。点击后从左侧打开抽屉，桌面端紧贴侧边栏右侧展开，移动端占满屏宽；官方与互动消息分为两个页签，只有当前页签请求列表。

抽屉打开时按游标读取消息列表。每条消息显示标题、正文、创建时间与未读状态。点击正文或“查看图片”才标记已读；审核通过作品打开本地公开详情覆盖层，History state 保持来源页，拒绝或失败作品读取私有资产详情。支持全部已读、单条删除和管理模式下所选消息的批量删除，删除均需确认，不提供一键清空全部历史。图片不存在时提示不可用。抽屉不显示审核供应商原始分类、对象路径、异常栈或签名 URL。

## 6. API、前端模型与状态管理

跨页面局部更新、个人 30 分钟策略与公开列表移除规则以 [资源列表缓存模块](资源列表缓存模块.md) 为准。删除资产不等于撤销发布；两种操作分别同步各自的缓存范围。

| 目的 | 接口 | 查询键与前端行为 |
| --- | --- | --- |
| 全量资产 | `GET /api/generation-images` | 复用 `assetQueryKeys.all` 和 30 分钟策略。提交发布局部标为 PENDING；URL 到期或失败只刷新单图。 |
| 单图详情 | `GET /api/generation-images/{imageId}` | 只返回本人未删除资产；不存在、已删除或非本人统一返回 `40401`。已公开作品通过公开单图接口读取。 |
| 设置收藏 | `POST /api/generation-images/favorites` | 请求体为 `{ imageIds: string[], favorite: boolean }`，将单图或多张图片设为目标收藏状态；重复设置成功，资产页先取消相关资源查询，再同步缓存的 favorited 并保护提交期间的刷新，失败仅回滚该字段；生成页详情仍在成功后更新。见 [资源列表缓存模块](资源列表缓存模块.md)。 |
| 提交发布 | `POST /api/generation-images/{imageId}/publication` | 请求体为 `{ title, description }`，响应为 `{ imageId, status }`。图片处于可提交状态时创建审核并返回 `202 PENDING`；已处于 `PENDING` 时也返回 `202 PENDING`，但不重复创建审核；`202` 后不伪造审核完成状态。 |
| 删除发布 | `DELETE /api/generation-images/{imageId}/publication` | 成功后从已有公开列表、本人发布和点赞列表移除；私有资产及生成轮次保留图片并重置发布状态。 |
| 我的发布 | `GET /api/users/me/publications` | `publicationQueryKeys.mine`，全量数组，不分页，30 分钟策略。缓存新鲜时返回不请求；发布提交或审核终态使查询失效。 |
| 消息未读数 | `GET /api/users/me/notifications/unread-count` | 返回官方、互动及总未读数。认证成功后读取，收到发布终态或互动消息 SSE 后失效并重新请求。 |
| 消息列表 | `GET /api/users/me/official-notifications?cursor` | 返回 `{ items, nextCursor }`，每项包含通知 ID、事件、关联图片、文案、已读与创建时间。`officialNotificationQueryKeys.list` 为 Infinite Query；抽屉打开时读取，事件/重连后只保留并重新请求第一页。 |
| 标记单条已读 | `POST /api/users/me/official-notifications/{notificationId}/read` | 成功后更新当前消息项和未读数，不等待下一次全量刷新。 |
| 全部已读/删除消息 | `POST /api/users/me/official-notifications/read-all`、`DELETE /api/users/me/official-notifications/{notificationId}`、`POST /api/users/me/official-notifications/deletions` | 批量删除只提交勾选的 notificationIds；成功更新当前列表与未读数，删除前要求确认。 |
| 发布终态 | `GET /api/events` 中的 `publication.updated` | 解析终态事件后失效资产与本人发布查询；REST 快照决定最终成员和状态。 |

`eventType` 只按 `PUBLICATION_APPROVED`、`PUBLICATION_REJECTED`、`PUBLICATION_FAILED` 展示，拒绝消息的 `metadata.violations` 仅可用于安全地标注标题或描述字段。

在 `features/publication/` 新建 `api/`、`model/`、`ui/`。API 层将完整 DTO 映射为现有 `GenerationAsset` 领域模型；只为状态建立窄类型 `PublicationReviewStatus = "NONE" | "PENDING" | "APPROVED" | "REJECTED" | "FAILED"`，不另建重复图片模型。

现有 `GenerationEventStreamProvider` 改造为认证驱动持续连接：认证成功后保持单条连接，统一解析生成任务和 `publication.updated`；重连成功后由生成工作台与消息模块完成各自 REST 对账；本人作品列表不因历史刷新版本重新挂载而重复请求。断线期间遗漏的审核事件由个人列表过时刷新或用户整页刷新补齐。SSE 只触发内存合并或缓存失效，REST 响应是图片和消息的权威数据。

发布接口返回 `40903`（当前用户协议尚未确认）或 `40902`（协议版本已更新）时，当前表单保留输入并展示安全业务错误。共享协议确认能力尚未接入发布表单的自动恢复流程，此项属于后续完善范围。

## 8. 异常场景、可靠性与安全

- `40100`、`40102` 按工程基础文档统一处理。会话进入匿名状态时清空发布、消息和资产的 Query 缓存。
- 发布提交结果未知时，用户再次提交同一图片会由服务端的 `PENDING` 状态返回原始的 `202 PENDING`；提交明确失败时保留表单输入。
- `PENDING` 删除发布后，迟到的审核终态不得重新加入当前发布列表。终态信号只触发读取当前服务端快照，不依据迟到事件重新插入列表成员。
- 发布区正在阅读另一项详情时，终态更新不得重置列表、滚动位置或关闭该详情。当前详情被 `REJECTED`、`FAILED` 移除时，仅保留结果提示，用户关闭后回到列表。
- 不做跨标签页消息、发布列表或图片状态同步；其他标签页由用户手动刷新。
- 全量列表请求、消息读取和图片 URL 刷新失败时，保留当前可见快照并给出重试，不清空界面。
- 模态表单、确认框和抽屉已使用可访问 Dialog：支持 Escape、焦点进入、焦点约束和关闭后的焦点回归，并保留可见焦点样式和语义化标签；状态不只依靠颜色区分。
- 私有签名 URL 不写入持久化存储、页面 URL、埋点或日志。

## 9. 测试与验收

自动化验证：本迭代引入 Vitest 与 React Testing Library，覆盖 SSE 事件解析、消息文案映射、双用途图片 DTO 展开与资产/发布/官方消息/协议 API mapper。本轮未以测试数量作为文档状态依据；构建验证以本次 `pnpm build` 结果为准。

以下记录已覆盖的发布链路；当前页面自动化结果及未覆盖项见 [资源列表缓存模块](资源列表缓存模块.md)：

1. 从资产详情提交发布，收到 `202` 后详情与资产缓存同步 PENDING，个人中心作品区出现“审核中”/“已发布”。
2. 审核通过后，已打开的发布列表原地变为“已发布”（SSE 信号→全量重拉），不改变排序或滚动位置；未读消息角标更新。
3. 审核拒绝或服务失败后，图片从发布区移除，官方消息可阅读，资产页可重新提交。
4. 对审核中和已发布图片均可执行“删除发布”，且资产原图仍存在。
5. 同标签页未活跃的本人发布缓存收到终态后标记失效，下次使用读取后端快照；不做跨标签页自动同步。
6. 打开消息抽屉、点击消息、查看图片（含资产已删的“该图片已删除”）、SSE 断线自动重连，以及桌面和窄屏键盘操作均符合本文约定。
