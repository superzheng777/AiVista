# AiVista 个人资产模块

> 对应迭代：前端迭代 3——个人资产
> 当前状态：实施中
> 维护规则：本文记录个人生成资产的页面交互、接口消费与验收；代码、测试、接口契约或交互规则变化时必须同步修改。

## 1. 目标与范围

接入已完成的个人资产后端能力，使已登录用户能浏览自己的成功生成图片、查看图片与最终提示词，并按单张或手动多选删除。

当前已接入作者收藏、单图发布和复制；对应规则见[收藏与发布模块](收藏与发布模块.md)。本页不承载公开点赞、关注，也不提供按全部历史一键删除。

后端业务事实与接口契约以 [个人生成历史与资产模块.md](../../java/modules/个人生成历史与资产模块.md) 为准。

## 2. 已确认约束

- 资产最小单位是单张成功图片；资产列表只显示当前用户且未删除的图片。
- 列表按成功保存时间和图片 ID 倒序，前端使用 `Asia/Shanghai` 按日期分组。
- 资产列表全量请求，不使用游标分页；页面计数取当前已加载全量数组长度。当前产品规模接受一次性返回全部图片和签发 URL 的成本；资产量明显增长后再评估分页或虚拟滚动。
- 列表和单图 DTO 一律提供卡片缩略图与展示图；资产页点击图片时若展示图未过期，直接复用现有 DTO，不额外请求单图详情。
- 私有签名 URL 仅在内存中使用；列表使用有效期 1 天的 `imageUrls.thumbnail`，详情展示与复制使用有效期 1 天的 `display`。下载原图时才调用作者专属下载接口签发 10 分钟 `original` URL；读取失败时按 `imageId` 刷新单图 DTO 一次。
- 删除使用统一批量接口；只提交用户手动勾选的 `imageIds`，重复删除按成功处理。
- 删除成功即从资产页移除；OSS 后台清理不阻塞前端，也不能恢复可见性。

## 3. 关键决策记录

| 决策事项 | 最终结论 | 原因与取舍 | 对实现的影响 |
| --- | --- | --- | --- |
| 详情数据来源 | 优先复用列表 DTO 的有效 display；过期或读取失败才按 imageId 刷新单图。 | 列表已包含 thumbnail/display，原图下载独立申请。 | 列表由 Query 内存缓存保留，详情关闭不清除列表。 |
| 桌面端详情布局 | 保持首页侧边栏；右侧主体切换为左右双栏，左栏居中展示图片并提供纯图标上下箭头，右栏展示提示词与操作。 | 详情仍属于资产浏览上下文，不离开当前页面；用户可按资产数组顺序连续查看，图片周边留白可作为直观关闭区域。 | 不新增详情路由或全屏遮罩；以当前图片 ID 推导前后位置，第一张/最后一张禁用对应箭头，左栏空白区域点击关闭详情，右栏操作不触发关闭。 |
| 批量操作入口 | 资产页右上角提供“批量操作”按钮；进入后才显示图片复选框、已选数量和“取消选择”。 | 默认点击图片保持预览语义，避免与删除混淆。 | 管理模式中可对手动勾选的图片执行删除或下载。 |
| 批量操作范围 | 本迭代实现删除与下载；迭代 4 已加入图片表持久化收藏及批量收藏。发布可从单张资产卡片或详情发起，不支持批量发布。 | 收藏属于图片创建者，使用明确目标状态的批量接口；发布是单张图片的审核提交。 | 删除和收藏均复用批量接口；下载时逐张调用作者专属接口申请原图 URL，读取失败时最多重新申请并重试一次；迭代 4 移除批量发布占位。 |
| 批量下载 | 多选下载逐张触发浏览器下载，不生成 ZIP 包。 | 不新增压缩文件生成服务，也避免后端暂存私有资产。 | 用户选择多张图片后依次触发下载；浏览器拦截时提示用户允许多文件下载。 |
| 图片复制 | 复制图片二进制到系统剪贴板；失败时提示用户下载图片。 | 详情操作栏需要直接复用当前图片，不引入链接复制语义。 | 浏览器从 OSS 短期签名 URL 读取 Blob 后写入 Clipboard API；OSS 需允许前端站点 Origin 的 `GET` 跨域请求，无需按用户 IP 配置或新增 Nginx 代理。 |
| 详情右栏信息结构 | 吸顶工具栏下依次显示已公开作品的标题/描述、提示词和生成参数；详情高度受浏览器视口约束，右栏整体可滚动。提示词按“正向提示词 / 负向提示词”分块显示原文。 | 长提示词只增加右栏滚动距离，不能撑高详情或把顶部信息顶出视口；前端不翻译或改写提示词。 | 图片区域左上角提供返回；右栏顶栏左侧下载，右侧星形收藏和更多菜单。菜单包含发布/查看发布、复制、危险色删除。未公开作品不显示标题/描述，空负向提示词不占位；返回与点击图片周边留白使用相同关闭行为。 |
| 共享详情 Shell 的场景差异 | 私有资产详情使用下载、收藏与更多菜单；公开详情复用布局与导航能力，隐藏顶部重复下载和生成时间，由作者工具栏提供公开日期、下载与作者撤销发布。两种场景的返回均位于图片区域左上角。 | 共享图片舞台、滚动和关闭逻辑，按场景组合业务操作。 | 私有操作通过 `headerActions(onCopy)` 插槽与 `OwnedImageDetailActions` 组合；公开互动与下载规则以《灵感社区模块》为准。 |
| 详情交互主题 | 上下切换使用近黑浮层；返回、下载和复制共享暖色悬停及陶土焦点，收藏选中使用陶土强调。 | 图片上的切换控件需要稳定对比度，其余操作应与全局暖色编辑主题一致。 | 禁用态不可表现为可操作；删除继续使用语义红，不与收藏强调色混用。 |
| 生成参数数据 | 详情展示尺寸、生成数量和生成时间，不单列比例或提示词优化开关。 | 保留主要生成信息，完整配置仍由领域模型承载。 | 统一图片 DTO 的 `generationConfig` 包含 `width`、`height`、`requestedImageCount` 和 `promptExtend`；`createdAt` 用于生成时间。 |
| 资产网格 | 使用明确响应式断点：手机2列、640px起3列、768px起4列、1024px起6列。 | 桌面提高浏览密度，小屏逐级降列并保持方形卡片可识别。 | 列表和 Skeleton 复用同一断点；1024～1319px 的悬浮操作收为图标按钮，1320px以上恢复文字。 |
| 删除确认 | 单图与批量删除使用同一确认弹窗。 | 统一不可撤销操作的风险提示。 | 文案为“将永久删除 N 张图片，此操作无法撤销”，操作为“取消 / 删除 N 张图片”。 |
| 日期分组 | 前端按北京时间分组，后端按 UTC 的 `created_at DESC, id DESC` 返回全量结果。 | 保持用户展示习惯与稳定顺序。 | 首次加载后直接完成日期分组。 |
| 删除交互 | 单图与多选复用确认和同一接口。 | 删除语义一致，减少重复链路。 | 成功后从本地列表乐观移除；失败则恢复并提示。 |
| 已删除快照 | 资产页不展示已删除图片。 | 当前页仅展示可管理资产。 | 任务/会话中的无 URL 占位由生成工作台模块处理。 |

## 5. 页面、路由与交互设计

路由为 `/assets`，仅认证用户可访问。页面应包含日期分组的图片网格、全量加载状态、空状态、错误重试、图片详情视图和删除操作。桌面端打开详情后，保留左侧固定导航；右侧主体分为左右两栏，左栏在留白画布中居中展示图片，点击图片周边留白关闭详情。右栏宽度建议固定在 `360px`～`400px`，包含吸顶操作栏、提示词区和生成参数区；右栏内的操作不得触发关闭详情。

| 场景 | 前端行为 |
| --- | --- |
| 首次加载 | 请求全部资产；空列表显示“尚无生成图片”及前往生成入口。 |
| 查看详情 | 优先复用列表的 `display` 大图；仅 URL 过期或图片读取失败时请求单图详情一次。 |
| 详情操作栏 | 图片区域左上角提供返回；右栏顶部左侧下载，右侧收藏和更多菜单，菜单包含发布/查看发布、复制与删除。返回与图片周边留白均关闭当前详情。 |
| 详情参数 | 展示尺寸、生成数量和生成时间；已公开图片另显示标题与描述。 |
| URL 到期 | 不继续使用失效 URL，只刷新当前单图详情，不重拉资产列表。 |
| 生成完成 | 收到 `creation.item.upserted` 中携带资产的 generation 项后，使共享资产缓存失效；活跃列表立即请求，未活跃列表下次使用时请求；新图加载完成后确认本标签页的新结果提示。图片任务可在父创作取消后完成，不依赖父创作成功事件。 |
| 批量操作 | 点击右上角“批量操作”进入管理模式；顶部显示“已选 N 张”和“取消选择”，卡片显示复选框。 |
| 删除单图/多选 | 明确永久删除确认，提交用户选中的 ID；成功后从网格移除。 |
| 下载单图/多选 | 逐张调用作者专属下载接口取得原图 URL；读取失败时仅重新申请并重试一次。 |
| 图片复制 | 卡片及详情的更多菜单均可复制。读取 `display` 图片 Blob 并写入系统剪贴板；URL 已过期或 OSS 读取失败时最多按单图刷新一次，浏览器权限、图片格式或 CORS 仍失败时提示用户下载。 |
| 收藏/发布 | 收藏支持单图和批量，提交明确目标状态并持久化到服务端，已有缓存乐观更新；发布可从单张卡片或详情提交审核，不支持批量发布。 |
| 删除失败 | 保留原项与选择状态，显示安全错误消息并允许重试。 |

当前 Web 网格随视口切换为 2/3/4/6 列，详情在窄屏上下排列、桌面左右排列；完整移动端人工验收仍按第 9 节跟踪。React Native App 属于后续独立规划。删除菜单项与图片预览区域分离，并保留确认步骤。

## 6. API、前端模型与状态管理

资产页与生成引用选择器共享 `assetQueryKeys.all`，`staleTime/gcTime` 均为 30 分钟。有效缓存返回页面直接复用原 URL；收藏、删除修改已有内存数据并保留整表更新时间与失效标记。删除资产只移除私有资产和生成快照中的 URL，不撤销已发布作品。完整规则见 [资源列表缓存模块](资源列表缓存模块.md)。

| 目的 | 接口 | 前端约定 |
| --- | --- | --- |
| 全量资产列表 | `GET /api/generation-images` | 直接消费全量图片数组；响应按 UTC 的 `createdAt DESC, imageId DESC` 排序，前端完成北京时间分组。 |
| 单图资产详情 | `GET /api/generation-images/{imageId}` | 供官方消息“查看作品”按需读取；成功 DTO 与资产列表单项相同，`404` 显示“该图片已删除”。 |
| 删除图片 | `POST /api/generation-images/delete` | 请求为 `{"imageIds":["101","102"]}`；成功 `data` 为 `null`。 |

领域模型保留 `imageId`、`imageUrls.thumbnail/display`、`width`、`height`、`createdAt`、`finalPrompt`、`finalNegativePrompt`。原图 URL 不属于图片 DTO；不得将 URL 存入本地持久化缓存；删除请求不按资源存在性展示差异，以符合后端归属隔离语义。

## 8. 异常场景、可靠性与安全

- `40100`、`40102` 统一遵循工程基础文档的认证处理。
- 全量资产请求失败时保留当前已展示快照并提供重试；不使用游标或 `limit` 参数。
- 删除接口的“已删除、他人或不存在均成功”是安全约束，UI 不得试图区分资源存在性。
- 签名 URL、提示词和图片不得写入持久化存储、URL、埋点或错误监控；详情页面使用 `Referrer-Policy: no-referrer`。

资产缓存、收藏、删除、URL 刷新及跨页请求次数的自动化记录见 [资源列表缓存模块](资源列表缓存模块.md)。完整模块仍需验收：空列表、全量结果日期分组、详情展示、URL 过期刷新、单图/多选删除、重复删除、删除失败恢复和认证失效。执行 `pnpm lint`、`pnpm build` 并使用真实后端完成联调。

## 10. 后续边界

收藏是图片作者的私有标记，单图和批量操作均已持久化；发布是独立的审核与公开生命周期，两者契约见[收藏与发布模块](收藏与发布模块.md)。公开作品详情复用图片 Shell、滚动、导航和关闭能力；作者行、点赞、更多菜单、展示图下载与撤销发布由[社区身份与互动模块](社区身份与互动模块.md)维护，私有资产详情保留作者原图下载。
