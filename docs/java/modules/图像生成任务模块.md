# 图像生成与创作执行模块

> 当前状态：已完成。本文记录 Java 的业务入口与跨服务边界，执行和结算实现见 AI Runtime。

## 1. 目标与范围

普通生成和 Agent 共用创作资源，支持文生图、图生图、表单确认、取消、历史恢复和资产交付。Java 接收浏览器请求，TS 执行并落库，不建立两套生成生命周期。

## 2. 已确认约束

每会话最多 30 轮用户创作；失败、取消也占一轮，表单恢复和工具调用不占新轮。会话列表和单会话历史全量返回。普通生成明确画幅及 1–6 张数量；Agent 可省略两者由模型选择。同一会话有活动创作或尚未收口的生图时不能提交下一轮。

## 3. 关键决策记录

生成资产和额度与执行终态由 TS 在同一 MySQL 事务结算，避免跨 Java 提交完成结果。Java 继续负责上传资产、资产授权和后续管理。普通和 Agent 采用同一个 executions 表，父子关系区分用户创作和实际生图。聊天与工具正文只保存在原生 Pi 文件。

## 4. 实施计划与进度

已接入统一 REST、内部鉴权、原生会话投影、SSE 和新 V1。自动化覆盖领取幂等、额度退款与前端流更新；真实普通与带表单 Agent 联调均交付一张图片，已核对持久化历史及四区 UI。

## 5. 设计与实现

- CreationController：统一浏览器会话和创作接口。
- CreationRuntimeClient：携带可信用户 ID 和内部令牌调用 TS。
- CreationImageService：提交选图授权、unsigned URL 生成和展示响应补签名。
- CreationRuntimeController：只接收 TS 事件批次，补充图片签名后推送 SSE。
- TS CreationRuntimeService / ExecutionRepository：创建、暂停、恢复、取消和执行。
- TS GenerationSettlement：额度预占及结果、资产、退款的原子提交。

Java 不负责消费生成 MQ，也不维护 Agent WebSocket、历史消息表或完成提交接口。社区异步事件沿用自身 Outbox。

## 6. 数据模型与配置

`generation_sessions` 保存用户、标题、最近活动和 creation_count。`executions` 保存 kind、mode、parent_id、tool_call_id、状态、revision、请求、实际模型参数、额度预占/结算时间与错误。`image_assets.origin_task_id` 指向 GENERATION 执行；同一来源序号唯一。`user_generation_daily_usage` 记录业务日请求额度，退款只减原业务日。

仅保留 `V1__initialize_schema.sql`，开发环境创建新库，不保留历史升级版本。Java 的 app.creation-runtime.base-url 指向内部 TS；两端共享 worker-api.token。TS 直接复用本地 YAML 的固定令牌时，不应另用不一致的环境变量覆盖。模型、额度与并发配置由 TS 读取共享配置或环境变量。

## 7. API 与权限

全部方法、字段和状态以 [创作通信协议](../../architecture/creation-protocol.md) 为准。Java 从 JWT 获取当前用户，不接受浏览器 userId；打开会话、提交到会话、读取或取消执行、回答表单都校验归属。所选 assetIds 必须属于当前用户且可读。TS 只接收内部令牌和 Java 提供的可信用户、图片引用。

## 8. 异常场景、可靠性与安全

CAS 领取使重复 MQ 不重复执行；resume 提高 revision，使旧消息失效。未交付结果退款，已交付部分按实际张数结算。取消 Pi 不撤回已由图像服务接受的请求，图片可继续保存为资产。数据库与文件异常中断、进程崩溃采用人工核对处理，不自动重跑付费模型。

生成额度与并发限制在 TS 实际执行时检查，失败进入执行/工具结果；Java 不再维护旧同步生图的配额和工具冲突错误码。会话忙、30 轮上限和表单版本冲突仍由创建/更新接口返回，前端据此提示。

## 9. 测试与验收

Java 单元测试保护 JWT、用户协议和资产/社区业务。TS 隔离库测试覆盖 CAS、会话上限、归属及结算幂等，Faux Pi 验证暂停、恢复与实时/历史一致投影。已通过 Java 122 项单元测试和 TS 5 项独立临时库集成测试；真实验证仅调用一次普通生成和一次带表单的 Agent 生图。完整验证命令和真实调用限制见 [AI Runtime](../../worker/AI-Runtime.md)。

Java `failsafe:integration-test failsafe:verify` 已执行，但本机 Docker 不可用，5 项 Testcontainers 数据访问测试按 disabledWithoutDocker 跳过；不能将其记为通过。启用 Docker 后仍需补跑该组测试，TS 的临时 MySQL 库测试不替代 Java Mapper 集成覆盖。

## 10. 后续边界

不实现 MongoDB、分布式会话锁、自动事故恢复或无限会话。多实例部署需重新设计文件访问与执行归属。
