# 图像生成与创作执行模块

> 当前状态：已完成。本文记录 Java 的业务入口与跨服务边界，执行和结算实现见 AI Runtime。

## 1. 目标与范围

普通生成和 Agent 共用创作资源，支持文生图、图生图、表单确认、取消、历史恢复和资产交付。Java 接收浏览器请求，TS 执行并落库，不建立两套生成生命周期。

## 2. 已确认约束

每会话最多 30 轮用户创作；失败、取消也占一轮，表单恢复和工具调用不占新轮。会话列表和单会话历史全量返回。普通生成明确画幅及 1–6 张数量；Agent 可省略两者由模型选择。同一会话有活动创作或尚未收口的生图时不能提交下一轮。

## 3. 关键决策记录

生成资产和额度与执行终态由 TS 在同一 MySQL 事务结算，避免跨 Java 提交完成结果。Java 继续负责上传资产、资产授权和后续管理。普通和 Agent 采用同一个 executions 表，父子关系区分用户创作和实际生图。聊天与工具正文只保存在原生 Pi 文件。

## 4. 实施计划与进度

已接入统一 REST、内部鉴权、原生会话投影和 SSE。创作通过 Node 本地调度，普通生成与 Agent 生图工具共用图片 MQ，数据库通过 V2 增量迁移保存图片执行恢复信息。验收范围见第 9 节。

## 5. 设计与实现

- CreationController：统一浏览器会话和创作接口。
- CreationRuntimeClient：携带可信用户 ID 和内部令牌调用 TS。
- CreationImageService：提交选图授权、unsigned URL 生成和展示响应补签名。
- CreationRuntimeController：只接收 TS 事件批次，补充图片签名后推送 SSE。
- TS CreationRuntimeService / ExecutionRepository：创建、暂停、恢复、取消和执行。
- TS CreationDispatcherService：创作本地调度、启动及周期补扫描。
- TS GenerationTaskService / GenerationQueueService：图片任务幂等创建、结果等待、可靠派发及异步消费。
- TS GenerationRateLimiterService：在图片请求发出前平滑控制每秒启动次数。
- TS GenerationSettlement：额度预占及结果、资产、退款的原子提交。

Java 不负责消费生成 MQ，也不维护 Agent WebSocket、历史消息表或完成提交接口。社区异步事件沿用自身 Outbox。

## 6. 数据模型与配置

`generation_sessions` 保存用户、标题、最近活动、creation_count 和 deleted_at。会话 DELETE 采用逻辑删除：有活动创作或图片任务时返回 409，成功及本人重复删除返回 204；之后禁止历史和创作访问，保留执行、图片、作品、额度及原生 JSONL。前端侧栏删除入口已接入，成功后清理会话缓存和状态提示，删除当前会话返回新对话页。`executions` 保存 kind、mode、parent_id、tool_call_id、状态、revision、请求、实际模型参数、额度预占/结算时间与错误。`image_assets.origin_task_id` 指向 GENERATION 执行；同一来源序号唯一。`user_generation_daily_usage` 记录业务日请求额度，退款只减原业务日。

Flyway 使用 `V1__initialize_schema.sql` 创建基础表，再执行 V2 图片任务及 V3 会话逻辑删除增量迁移；本轮用户统计与通知重构已修改 V1，旧开发库按已确认方案重置后初始化；需保留数据的环境应另写增量迁移，不可直接升级或 repair 绕过。Java 的 app.creation-runtime.base-url 指向内部 TS；两端共享 worker-api.token。TS 直接复用本地 YAML 的固定令牌时，不应另用不一致的环境变量覆盖。模型、额度与消费配置由 TS 读取共享配置或环境变量。图片消费者 `AIVISTA_GENERATION_PREFETCH=200`，图片模型请求默认最多 2 次/秒，不另设模型并发门槛。

## 7. API 与权限

全部方法、字段和状态以 [创作通信协议](../../architecture/creation-protocol.md) 为准。Java 从 JWT 获取当前用户，不接受浏览器 userId；打开会话、提交到会话、读取或取消执行、回答表单都校验归属。所选 assetIds 必须属于当前用户且可读。TS 只接收内部令牌和 Java 提供的可信用户、图片引用。

## 8. 异常场景、可靠性与安全

创作与图片任务分别用 CAS 领取；表单回答提高 revision 并唤醒本地调度器。图片消息重复投递不重复调用模型或结算，终态可靠保存后 ACK。未交付结果退款，已交付部分按实际张数结算。未发出模型请求的图片任务可取消；取消 Pi 不撤回已发出的图片请求，它们继续保存为资产。模型响应先持久化再转存，重启可继续处理已保存结果；请求可能发出但结果未知时明确收口，不自动重新付费调用。运行中 Agent 中断后不承诺无感续跑；SQL 与 JSONL 异常仍需人工核对。

生成额度与每用户已预占未结算图片任务限制在 TS 图片消费者调用模型前检查，失败进入执行/工具结果。会话忙、30 轮上限和表单版本冲突仍由创建/更新接口返回，前端据此提示。全局 prefetch 限制与每用户业务额度是不同的约束。

## 9. 测试与验收

Java 测试保护 JWT、用户协议、会话删除 REST 状态码、迟到事件过滤和资产/社区业务。TS 隔离库测试覆盖 V1→V2→V3 升级、CAS、会话上限、归属、删除与新创作并发、删除后访问拒绝、资产/作品/额度保留、取消及结算幂等；Faux Pi 验证本地异步创作、暂停恢复与实时/历史一致投影。图片队列测试覆盖统一限速、延迟 ACK、重复投递、已保存响应复用和结果未知收口。完整验证命令、运行结果和真实调用限制见 [AI Runtime](../../worker/AI-Runtime.md)。

Java 数据访问与社区事务测试使用本地 MySQL 随机临时库，当前为 `DataAccessIntegrationIT` 和 `SocialInteractionIT`；TS 数据库测试通过 `AIVISTA_NATIVE_SCHEMA_TEST=true` 显式启用。已有实际验收记录及覆盖范围见[用户统计与通知去重模块](用户统计与通知去重模块.md)，不要把默认命令跳过数据库测试计为通过。

## 10. 后续边界

不实现 MongoDB、分布式会话锁、Agent 崩溃后自动续跑或无限会话。多实例部署需重新设计文件访问、执行归属、全局图片速率和总在途上限。

数据层集成验证不依赖 Docker；Java 使用 `mvn test-compile failsafe:integration-test failsafe:verify`，TS 使用已启用数据库开关的 `pnpm test:schema`。
