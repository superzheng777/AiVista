# 个人生成历史与资产模块

> 当前状态：已完成。会话展示协议见创作通信协议；本文负责资产查询、管理和删除边界。

## 1. 目标与范围

用户按单张图片管理生成资产。资产列表全量返回，按 created_at DESC、id DESC 排序；收藏不决定是否保留，发布与删除资产互相独立。

## 2. 已确认约束

私有资产 API 只允许所有者访问，缺失和无权限统一返回资源不存在。公开作品通过发布状态授权。原图、展示图和卡片图存放在私有 OSS；签名仅在响应中产生。

## 3. 关键决策记录

image_assets 是上传和生成图片的唯一资产实体。上传由 Java 建立临时资产；生成由 TS 原子登记，来源指向 executions 中的 GENERATION 行。资产列表和详情从同一来源执行获取实际提示词和生成参数。

聊天历史由 TS 从原生 Pi JSONL 投影，Java 转发并补图片访问链接。删除资产不删除会话、工具消息、执行或原始结果位置；前端当前缓存将对应位置置为不可用。

## 4. 实施计划与进度

资产查询、下载、收藏、发布、软删除和异步 OSS 清理保留，来源 JOIN 已切换为 executions。会话不再通过数据库消息/活动/表单表拼装。

## 5. 设计与实现

GenerationAssetController 提供私有资产 API；GenerationAssetQueryService 组装统一图片 DTO；ImageAssetMapper 查询资产和发布状态。GenerationAssetDeletionService 标记删除，GenerationAssetOssCleanupService 异步清理。

图片列表 DTO 为 GenerationAssetImageResponse，前端映射为 GenerationAsset；包含实际正负提示词、数量、promptExtend、尺寸、收藏和发布状态，以及 imageUrls.thumbnail/display。会话响应只携带轻量图片引用；用户打开会话图片详情时单独读取资产 DTO。

## 6. 数据模型与配置

image_assets 保存 user_id、origin/lifecycle、origin_task_id/source_index、对象键、尺寸和文件大小，以及删除/到期/清理状态。来源序号唯一保证同一生成结果不重复登记。执行记录和会话文件保留生成事实；资产删除不退款已经交付的历史生成。

生成图片对象组为 `{prefix}/{userId}/tasks/{generationId}/{sourceIndex}`，包含 original.png、card.webp、display.webp。上传路径包含随机 UUID，存入临时生命周期。重建测试数据库需使用新的 OSS 命名空间，避免 ID 重置复用旧对象路径。

## 7. API 与权限

- GET /api/generation-images：当前用户全部可见资产。
- GET /api/generation-images/{imageId}：私有详情与刷新后的展示链接。
- GET /api/generation-images/{imageId}/original-download：作者按需获取原图临时地址。
- 图片上传、批量收藏、删除和发布沿用 GenerationAssetController 及发布模块接口。

thumbnail/display 签名默认 1 天，下载原图默认 10 分钟。会话中保存 unsigned 原图 URL，浏览器不能自行指定任意 URL 让后端签名。

## 8. 异常场景、可靠性与安全

删除先改变数据库可见性，OSS 清理由后台重试；已公开或审核中的资源按发布保护规则保留。活动执行仍引用的上传图不提前清理；引用从 executions.request_json 中检查。

会话历史引用不逐图重新查询资产归属；会话所有权和最初引用授权构成信任边界。删除后已有签名可能在到期前继续读取，已加载浏览器像素也不会自动撤回。重新打开历史时已清理图片通过加载失败和单图读取返回不可用，不承诺即时撤销历史签名。

## 9. 测试与验收

资产查询、删除、收藏和 OSS 清理单元测试保留。TS 集成测试验证生成登记与重复完成不重复创建资产。前端资源缓存同步删除会话图片引用；URL 到期或首次加载失败时刷新一次单图数据。

## 10. 后续边界

资产规模增长时再评估分页。全局图片立即撤销、CDN 和多地域存储不属于当前实现。
