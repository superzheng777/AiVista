# AiVista 文档规范

> 适用范围：项目总览、工程基础、业务模块、跨服务架构、Worker 和视觉设计文档。
> 当前状态：生效中。
> 维护规则：修改本规范前先讨论确认；代码、测试、接口、数据结构、交互或运行约定变化时，按影响范围同步文档。

## 1. 入口与事实归属

- 根目录 README 负责项目介绍和快速启动；[文档导航](../README.md)负责分类与索引，不复制模块实现。
- 前端文档记录页面、交互、接口消费和客户端状态；后端业务事实与接口契约以 Java 模块文档为准。
- Java 文档记录业务规则、数据模型、事务、权限与对外 API；Worker 文档记录 AI Runtime、Tool、外部 I/O 和内部执行。
- 跨服务架构文档解释职责和完整链路；通信协议文档描述双方实际交换的消息及版本、重投和失败语义。重复部分只保留摘要和链接。
- 每个业务模块只维护一份贯穿设计、实施和完成的模块文档；已推翻的临时方案不作为最终规范保留。
- AGENTS.md、CLAUDE.md、Pi SYSTEM.md、SKILL.md、配置样例和数据库迁移依赖原有位置，不作为普通文档搬迁。

## 2. 状态、命名和元信息

业务模块状态只使用“设计中 → 实施中 → 已完成”。设计中应明确待确认项，不能把尚未确认的接口或数据结构写成事实；实施中须确认范围、约束、关键决策、异常与验收；已完成须整理最终参考、验证结果和未覆盖项。已完成模块新增能力时建立新迭代文档，不回退原状态。

业务模块文件名采用“中文业务名 + 模块.md”。标题下记录对应迭代、当前状态和维护规则。文档不维护最后同步日期或独立版本号，历史以 Git 为准。跨服务架构、视觉和 Worker 文档可按用途命名，不强制套用模块标题。

关键决策只记录最终有效且影响维护的结论，说明原因、取舍和实现影响。实施计划可记录“待开始、进行中、已完成、阻塞”；模块完成后压缩为实施摘要与验证结果，不保留流水账。

## 3. 项目总览与工程基础

前端和 Java 各自的项目总览只包含文档索引、一期目标、跨模块边界、迭代路线、同步规则和后续方向；数据表、接口、组件和测试细节归对应模块。

工程基础文档记录项目入口与常用命令、基础能力、工程结构、通用开发约定、配置与环境、部署联调、测试验收及后续工程边界，不承载业务模块设计。通用运行方式变更只更新受影响的工程基础文档。

## 4. 前端模块文档

前端模块使用以下章节：

1. 目标与范围
2. 已确认约束
3. 关键决策记录
4. 实施计划与进度
5. 页面、路由与交互设计
6. API、前端模型与状态管理
7. 组件与实现位置
8. 异常场景、可靠性与安全
9. 测试与验收
10. 后续边界

交互设计覆盖正常、加载、空、错误和认证失效状态，以及必要的桌面、移动端和可访问性差异。接口章节记录 DTO 映射、分页、缓存、实时状态对账和重试等前端行为；服务端业务真相应链接 Java 文档。实施中和已完成模块列出路由、功能、领域模型及通用组件的关键代码位置，不填写不存在的文件。

## 5. Java 模块文档

Java 模块使用以下章节：

1. 目标与范围
2. 已确认约束
3. 关键决策记录
4. 实施计划与进度
5. 设计与实现
6. 数据模型与配置
7. API 与权限
8. 异常场景、可靠性与安全
9. 测试与验收
10. 后续边界

实施中和已完成模块列出接口入口、核心业务、数据访问、迁移及异步/外部集成的关键实现位置；设计中不填写不存在的代码。跨服务协议的字段和重投语义由对应协议文档维护，模块文档链接引用。

## 6. 验证、同步和安全

测试与验收应分别记录自动化验证的范围、命令和结果，真实环境或人工联调的链路与结果，以及未覆盖项的原因和后续条件。前端需记录测试、lint、构建及必要的桌面/移动端验收；Java 和 Worker 记录相应测试与集成验证。

- 业务规则、接口、数据结构、前端状态、可靠性或测试变化：更新拥有该事实的模块或协议文档。
- 迭代状态、模块边界或文档入口变化：同时更新对应项目总览与文档导航。
- 工程启动、配置或部署变化：更新对应工程基础文档或 Worker 文档。
- 页面视觉令牌变化：更新前端全局视觉规范；具体页面文档只记录局部结构和变化。
- 未受影响的文档不机械修改；迁移文档时检查所有相对链接和图片引用。

任何文档不得包含密码、Token、真实 API Key、OSS AccessKey、RabbitMQ 密码、临时或签名 URL，以及完整的生产提示词。
