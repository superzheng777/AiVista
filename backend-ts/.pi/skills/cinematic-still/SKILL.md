# 电影感摄影图

把用户的主题转化为像真人剧情长片正片中截取的镜头。电影感来自摄影机为何在这里、观众与事件的距离、空间如何约束人物、光色从哪里产生，以及连续镜头如何推进理解；不是宽银幕黑边、蓝橙滤镜、重颗粒或“cinematic”关键词的堆叠。

Skill 提供电影镜头领域方法；系统提示词负责通用交互方式，Tool Schema 和 Harness 负责参数、权限、数量与画幅等硬约束。

## 一、先判断任务边界

- 用户只需要故事分析、镜头建议或 Prompt：直接回答，不调用生图工具。
- 用户要求生成单张真人电影剧照：设计一个完整镜头后调用生成工具。
- 用户要求三联、连续镜头、分镜式组图或同一事件的多个视角：先设计共享的电影 DNA，再为每个镜头分别生成。
- 用户要求片名海报、电影封面或发布主图：主要交付属于 `poster-design`，不要把剧照组直接拼成海报。
- 用户要求商品广告、品牌识别或 Logo：除非明确要求叙事电影场景，否则不要使用本 Skill。
- 用户要求模仿具体导演、现成电影镜头、受保护角色或标志性视听系统：改为描述摄影行为与视觉特征，不复刻署名风格或具体镜头。

“自由发挥”“随机”“其他细节你来定”不是信息不足。先在内部提出三个彼此不同的电影 DNA 候选，每个候选只写事件状态、观众位置、构图压力和色彩来源，再选择最符合主题且最不模板化的一项继续；不要把候选清单原样展示给用户，也不要因此固定生成三张图片。

不要为了显得专业而强制追问焦段、胶片和色温。关键故事事实缺失或冲突时才询问；可以由摄影指导合理决定的内容直接做出有依据的选择。

### 需求确认门槛

一句话只要已经包含可见主体、事件或处境，就足以开始设计，不要把简短请求误判成信息不足。仅在以下未决信息会改变故事事实、人物连续性或交付结构时调用 `request_user_input`：

- 核心人物、关系或关键事件存在互相冲突的解释，且无法通过一个合理镜头同时容纳。
- 用户要求连续镜头，但单张剧照还是多张独立镜头无法从请求和 Runtime 数量约束中确定。
- 附件要保持人物或空间身份，还是只提炼构图、色彩或气氛无法判断。
- 用户要求准确复现某个时间、地点、服装、道具或行为，但必要事实缺失。

不要询问焦段、机位、景深、胶片、光源、色温、叙事节奏或普通色彩偏好，这些属于本 Skill 的专业判断。表单只加入尚未解决的字段，可按需使用：`storyPremise`（故事或当前事件）、`characterRelationship`、`outputMode`（单镜头 / 连续镜头组）、`referenceUsage`（保持身份 / 仅参考构图 / 仅参考色彩 / 仅参考题材）、`requiredFacts` 或 `mustAvoid`。用当前理解形成初始值，不让用户重新描述整段请求；用户跳过后自行完成摄影与叙事选择，不立即重复询问。表单不能修改 Runtime 画幅和图片总数，也不能替代图片上传或授权。

## 二、遵守当前生成能力

当前生成 Tool 只接受 `1:1`、`4:3`、`3:4`、`16:9` 和 `9:16`：

- 用户或 Runtime 已指定画幅时，以该硬约束为准。
- 用户选择自动且没有其他画幅要求时，电影剧照优先使用 `16:9`。
- 用户明确要求 `21:9` 或 `2.39:1` 时，不得把 21:9 作为 Tool 参数，也不得静默替换；说明当前最宽支持 `16:9`，得到接受后再生成。
- 不通过画内黑边、白边或后期裁切假装已经交付 `21:9`。

图片数量同样服从本轮约束：

- 用户明确要求单张或一个镜头时生成一张。
- 用户明确要求“一组”“三联”或连续镜头，且数量为自动时，通常设计三张独立镜头。
- 用户没有表达镜头组意图时，默认一张关键镜头，不把“三张”作为所有电影感请求的固定值。
- Runtime 已指定总数时，镜头数量必须与其一致。若用户明确要求的镜头数与硬约束冲突，不调用不能改变约束的表单，也不静默漏镜头、重复镜头或改成单画布拼贴；说明冲突并请用户以匹配数量或“自动”重新发起请求。

同一镜头的多个变体可以一次调用生成 Tool 并设置 `imageCount`。具有不同叙事功能、机位或 Prompt 的 Shot 1/2/3 必须使用独立 Tool Call，不能用一次多图调用冒充连续镜头。

## 三、选择正确的图片路径

当前请求直接附带的图片已经提供给模型，同时 Runtime 会注入本轮允许使用的 Asset ID：

- 不依赖任何图片创建新镜头：使用 `text_to_image`。
- 当前请求已授权的人物、产品、建筑或空间必须保持身份并参与画面：使用 `image_to_image`。
- 本轮只把参考图用于构图、配色或题材灵感，而不要求保持具体视觉身份：只抽取其中一个维度，把它转译为文字后使用 `text_to_image`；不要为了“用到参考图”机械调用图生图。
- Context 中只有历史 Asset ID 且确实需要理解其画面：先使用 `inspect_image`。
- 历史图片需要成为图生图输入但本轮未授权：请用户重新选择，不得绕过授权。

参考图的复用范围以用户意图为准。参考图只提供灵感时，一次只抽取一个维度，并按以下边界原创其余部分：

- 只抽构图：更换题材、人物关系、动作、道具、综合色与时代背景。
- 只抽配色：更换构图、机位、题材、人物、动作、道具与空间骨架。
- 只抽题材：更换构图、综合色、人物关系、镜头位置、关键物件与剧情结果。

用户明确要求保留人物、产品、建筑或空间身份时才使用 `image_to_image`。不得同时复用参考图独特的人物数量与位置、人物关系、动作节点、道具组合、空间骨架、标志性机位、综合色和剧情结果。

## 四、先建立导演稿与电影 DNA

写 Prompt 前，先在内部形成一份紧凑导演稿，不直接把它当成最终回复：

1. **交付拓扑**：单镜头或连续镜头组、准确数量、Runtime 画幅、参考图用途。
2. **核心命题**：人物或主体想完成什么，空间、制度、关系或环境阻止什么。
3. **事件线**：初始秩序、可见偏差、偏差造成的关系或现场变化。
4. **连续性圣经**：人物身份、服装与关键道具、空间规则、时间段、主色域、强调色来源和成像基底。
5. **镜头职责**：每张图要新增什么信息、改变什么理解，不能只换景别或姿势。

自由发挥时，三个候选 DNA 只用于内部择优，不等于三个生成方向。需要设计连续镜头、用户没有给出足够镜头方向或需要选择成像基底时，再读取 `.pi/skills/cinematic-still/references/shot-language.md`；普通单镜头不必加载额外参考。

### 未解决状态

用一句内部陈述说明镜头发生时什么尚未解决，例如“仪式仍在进行，但负责宣誓的人没有出现”。不要用“孤独、神秘、诗意、宿命”等抽象情绪代替可见事件。

### 观众位置

确定摄影机的物理位置和观看关系：同处现场、隔着玻璃、从肩后观察、位于车内、藏在门口、从高处监视或贴近地面。每个选择都要有叙事理由。

### 视线流量

明确视线从哪里进入，被什么遮挡、放慢或加速，落到哪个决定性信息，最后从哪里离开。画面可以留有未知，但不能没有视觉落点。

### 构图压力

选择一种主要压力，例如被观察、被困住、关系疏离、权力不对等、心理失衡、事后状态或感官临界点。空间、人物比例与遮挡共同形成压力，不靠夸张表情说明一切。

### 综合色与成像基底

色彩必须能从服装、墙体、自然环境、实景灯、玻璃、水面或空气介质中解释，不使用无来源的全局滤镜。为同一组镜头选择统一的成像基底，例如克制的 35mm 印片、较软的 16mm 纪实质感、早期数字视频或长焦观察感；只有剧情需要时才使用旧广播、VHS 或特殊畸变。

电影 DNA 不使用导演姓名代替设计。把风格转译为摄影机行为、演员调度、空间压力、实景光源、色彩来源、成像介质和允许出现的局部光学缺陷。

## 五、设计单镜头或连续镜头

### 单镜头

一个镜头只保留：一个主要事件线索、一个次要线索、两至三个有叙事作用的场景细节、一个摄影机位置和一个主光源。不要用无关物件填满画面。

### 连续镜头组

所有镜头共享连续性圣经，但每张必须承担不同叙事功能。先选择适合故事的节奏，再分别确定景别、机位、视线流量和信息增量；不要机械使用“远景—中景—近景”。相邻镜头应形成可解释的剪辑关系：上一张建立的问题、动作或证据，要在下一张被推进、打断、重释或留下后果。

连续镜头不应只是：

- 同一人物更换站姿。
- 同一张图改变裁切。
- 平行换景但没有事件推进。
- 三张漂亮截图共享色调，却没有新的信息或关系变化。
- 直接生成三联拼贴、contact sheet、分镜板或带边框合成图。

## 六、编译可执行 Prompt

每个镜头使用一段独立 Prompt，并按以下顺序组织：

1. 成品类型与 Tool 支持的准确画幅，例如真人叙事长片剧照、`16:9`。
2. 与同组镜头共享的人物、空间、时间、道具、综合色和成像基底锚点。
3. 本镜头的未解决状态、叙事职责和新增信息。
4. 摄影机位置、观众关系、焦段倾向与机位高度。
5. 视线入口、阻断或加速、决定性落点和余韵出口。
6. 主要构图压力、人物比例、前景遮挡和空间关系。
7. 一个主要动作、一个次要线索和两至三个具体细节。
8. 主色域、次色域、唯一必要的强调色及其画内来源。
9. 主光源、自然反射或次级实景光，以及统一的成像基底。
10. 只针对当前风险的排除项。

Prompt 要具体但克制，并保持在 Tool 长度限制内。与其堆叠“史诗、超细节、极致电影感”，不如说明真实演员、物理场景、合理服装道具、自然皮肤、柔和高光过渡、保留阴影细节、适度微反差和轻微局部光学缺陷。

负向提示词只用于真实风险，例如排除 CG 渲染、游戏过场、数字绘画、蜡质皮肤、商业棚拍光、英雄海报姿势、无来源轮廓光和全画面过度锐化；不要把通用禁词库全部复制进去。

调用生成 Tool 前，先按系统规则输出一段安全、可展示的总体方案；同组多个 Tool Call 使用同一段 `userFacingPlan`。Tool 成功只表示生成任务成功，不等于已经完成视觉验收。若后续确实需要评价结果而上下文只有 Asset ID，先使用 `inspect_image` 查看对应图片，不凭 Prompt 猜测画面质量。

## 七、生成前检查

- [ ] 画面存在可见的未解决状态，而不只是抽象情绪。
- [ ] 摄影机位置、焦段倾向和观看关系有物理与叙事理由。
- [ ] 视线有入口、关键落点和余韵出口。
- [ ] 一个镜头只有一个主要事件、一个次要线索和有限细节。
- [ ] 主光源与颜色都能从画内环境解释。
- [ ] 多镜头共享世界与人物逻辑，同时具有真实的信息推进。
- [ ] 连续性圣经已在各 Prompt 中落成可见锚点，相邻镜头存在可解释的剪辑关系。
- [ ] 不同镜头使用独立 Prompt 和 Tool Call，同镜头变体才使用 `imageCount`。
- [ ] 画幅与图片总数符合 Runtime 约束，没有传入不支持的 `21:9`。
- [ ] 图片路径和 Asset 授权正确，没有把历史图片直接用于图生图。
- [ ] 结果目标是真人叙事剧照，而不是 CG、广告、海报、电视剧截图或旅行明信片。
- [ ] 没有复刻具体导演、现成电影镜头、受保护角色或参考图的独特表达。

工具返回参数或业务错误时，根据模型可见的 Tool Result 修正可纠正问题；不要绕过画幅、数量、素材或权限约束，也不要把失败说成已经完成。
