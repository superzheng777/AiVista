# 品牌设计

把品牌定位转化为可识别、可延展的视觉语言，并形成适合当前图片生成能力的 Logo 或品牌视觉概念。Skill 提供品牌设计方法；系统提示词负责通用交互方式，Tool Schema 和 Harness 负责参数、权限、数量与画幅等硬约束。

## 一、先判断任务边界

在设计前区分以下情况：

- 用户只需要品牌命名、口号、定位分析或设计建议：直接回答，不调用生图工具。
- 用户要求设计 Logo、品牌标志、字标、图形符号或品牌视觉方向：完成下述品牌判断后调用合适的生成工具。
- 用户提供完整、可直接执行的 Prompt：只检查品牌事实、素材和本轮约束，不擅自改写定位。
- 用户要求把既有品牌应用到活动海报：既有品牌是约束，主要交付仍属于海报设计，不要重新发明 Logo。
- 用户要求完整 VI 手册、多页品牌规范或可编辑矢量源文件：可以先生成关键视觉概念，但不能把单张位图结果冒充完整手册、SVG 或生产源文件。

品牌设计不是把行业图标、公司名和渐变色拼在一起。每个方向都必须从品牌的真实业务、受众、承诺与性格推导，而不是套用通用“高级感”模板。

## 二、锁定品牌事实

构思前在内部建立一份简短 Brand Brief，不要把清单机械地展示给用户。

### 不可改写事实

- 品牌或公司名称的准确拼写、大小写、语言和字序。
- 所属行业、核心产品或服务、使用场景和地域文化语境。
- 目标人群，以及品牌希望解决的真实问题。
- 用户明确的品牌定位、差异点、价值承诺和性格关键词。
- 必须保留或禁止使用的图形、颜色、文字、符号和既有资产。
- 交付是图形标、字标、组合标、Logo 概念，还是品牌视觉方向图。

不得虚构品牌历史、认证、奖项、口号、产品能力、价格、联系方式或商标状态。名称、业务或必须保留的素材存在冲突时先确认；缺少可以由设计师合理决定的风格、构图或配色时直接做出有依据的选择。

### 需求确认门槛

仅在以下未决信息会改变品牌身份或交付定义时调用 `request_user_input`：

- 交付需要出现品牌名称，但准确名称、大小写、语言或字序尚未给出。
- 核心业务或品类过于含糊，以至于无法形成与品牌有关的视觉母题。
- 附件中的既有 Logo 究竟需要原样保留、允许优化，还是只作风格参考无法确定。
- 用户提出的必须保留与禁止元素互相冲突，或 Logo 概念、品牌方向图、完整 VI 等交付范围不清。

目标人群、品牌性格在完全缺失且不同选择会实质改变品牌方向时可以询问；如果能从业务和语境合理推断，则直接形成明确设计判断。不要为了颜色、字体、Logo 架构、渐变、圆角等专业选择而机械追问。表单只加入尚未解决的字段，可按需使用：`brandName`、`business`、`audience`、`existingAssetUse`（原样保留 / 允许优化 / 仅作参考）、`requiredElements`、`forbiddenElements`。已有推断写入初始值供用户修正；用户跳过后不得编造品牌事实，只对设计选择采用合理默认值。

### 把抽象词变成视觉原则

不要直接把“专业、年轻、科技、高端、温暖”等词堆进 Prompt。先把它们转化为可执行选择，例如：

- “可靠”可以对应稳定重心、克制比例、清晰边界和低噪声色板。
- “亲和”可以对应开放轮廓、柔和转角、自然节奏和温暖但不过甜的色彩。
- “先锋”可以对应非常规切割、强对比、动态负形或具有识别度的字形结构。
- “精密”可以对应严谨几何、可复现网格、有限笔画和一致的视觉校准。

只保留真正影响设计的三到五个特征，并明确“是怎样的”和“不是怎样的”，避免相互冲突的气质同时出现。

## 三、选择正确的图片路径

当前请求直接附带的图片已经提供给模型，同时 Runtime 会注入本轮允许使用的 Asset ID。按以下规则选择工具：

- 不依赖任何图片，从 Brand Brief 创建新视觉：使用 `text_to_image`。
- 当前请求已授权的 Logo 草图、图形、产品、空间或风格参考要参与设计：使用 `image_to_image`。
- 需要理解某张历史品牌图，而 Context 中只有 Asset ID：先使用 `inspect_image` 查看，再继续判断。
- 历史图片必须实际参与图生图，但没有成为本轮授权输入：请用户在当前请求重新选择该图片，不得直接把历史 Asset ID 交给 `image_to_image`。

使用既有 Logo 时，先明确它是必须保持不变的正式资产、允许优化的草稿，还是仅供风格参考。正式 Logo 不能被无意重绘、改字或变形。多张参考图参与时，在内部明确每张图的角色，`inputAssetIds` 的选择与顺序必须和 Prompt 中的用途一致。

## 四、提炼品牌核心

在内部用一句话概括：为哪类人，在什么品类中，以什么独特价值，呈现什么性格。然后从中选择一个能长期延展的视觉母题。

视觉母题应满足：

- 与品牌业务或价值存在可解释的联系，但不必把产品画成字面图标。
- 轮廓或负形具有记忆点，缩小时仍能识别。
- 能延展到字标、图标、色彩、图案和应用场景，而不是只在一张效果图中成立。
- 避免没有品牌专属性的行业陈词滥调，例如随意使用灯泡、火箭、地球、盾牌、叶子或无限符号。

## 五、选择 Logo 架构

每个设计方向选择一种主要架构，不要在同一方向里堆叠所有形式：

- **字标 Wordmark**：名称本身具有辨识潜力，需要通过字形比例、笔画或连接关系建立个性。
- **字母标 Lettermark / Monogram**：名称较长、首字母组合有结构机会，或需要紧凑识别时使用。
- **图形标 Symbol**：品牌概念能被提炼为简洁、独立的图形语言时使用。
- **组合标 Combination Mark**：需要同时建立名称识别与图形记忆时使用。
- **徽章 Emblem**：品牌强调传统、组织归属或封闭式章印感时使用，避免无依据地增加年份与口号。
- **角色标 Mascot**：品牌确实依赖角色人格、社群亲和或儿童场景时使用，不把所有品牌都卡通化。

不同方向应改变核心概念或 Logo 架构，例如字标、负形图形和字母组合三个方向；仅换颜色、字体或背景不算不同方向。

## 六、建立最小品牌视觉系统

即使只生成 Logo 概念，也要同时考虑以下关系，但不要强行把所有内容塞进同一画布：

### 图形语言

明确基本几何、曲直关系、轮廓、负形、对称或动态方式，以及图形和品牌含义的联系。优先简洁、可复现的结构，避免依赖微小纹理、复杂插画或光效才成立。

### 字体与字标

明确字体气质、字宽、字重、字距和必要的定制笔画。品牌名称属于不可改写事实。图片模型可能无法稳定生成准确文字；对拼写要求严格时，把结果视为构形概念，并在最终说明中如实提示需要后续专业字形或矢量校正。

### 色彩角色

建立主色、辅助色、中性色和必要的强调色角色，而不是罗列无关系的色值。颜色应符合行业语境、受众和品牌性格，同时考虑浅色、深色与单色背景上的识别。不要默认使用渐变、金色或霓虹来表示高级和科技。

### 延展原则

考虑主标、紧凑版、图标版、单色版和反白版的逻辑是否一致，但当前任务未要求时不必在一张图中展示全部变体。清晰空间、最小尺寸和禁用方式属于后续规范，不要伪造已经精确测量的数值。

## 七、编译可执行 Prompt

每个方向按以下顺序写成一段自然、连贯、具体的 Prompt，只保留与当前任务相关的内容：

1. 成品定义：Logo 概念、字标、组合标或品牌视觉方向，以及准确画幅。
2. 品牌事实：准确名称、行业、受众、核心价值和不可改写要求。
3. 核心概念：一个视觉母题及其与品牌的真实联系。
4. Logo 架构：字标、图形标、字母标或组合标，以及图文关系。
5. 形式语言：轮廓、负形、几何、比例、笔画和视觉重心。
6. 字体策略：字体气质、字宽、字重、字距及定制字形方向。
7. 色彩策略：各颜色的角色、背景与单色适配倾向。
8. 再现要求：简洁轮廓、小尺寸可识别、平面化、避免依赖效果成立。
9. 排除项：只加入当前任务高风险限制，例如随机文字、拼写错误、无关 mockup、水印、复杂场景、过度 3D 或模板化行业符号。

Prompt 必须与 Tool 的画幅、图片数量和输入素材一致。除非用户明确要品牌展示板或应用场景，不要让模型生成办公用品 mockup、整套 VI 手册或多个无关物件，以免掩盖 Logo 本身。

## 八、组织单方向与多方向生成

- 同一 Logo 架构和视觉母题的多个变体使用一次生成 Tool，通过 `imageCount` 请求多张。
- 不同概念或不同 Logo 架构可以拆成多个 Tool Call；每个方向都使用独立、准确的 Prompt。
- 所有 Tool Call 的图片总数必须遵守本轮用户约束。用户选择自动时，根据决策价值选择足够且克制的数量，不固定生成四张。
- 用户只要求一个明确方向时，不为展示“丰富度”擅自扩展成多个不相关方向。

## 九、生成前检查

调用生成 Tool 前逐项检查：

- [ ] 品牌名称、大小写、语言和行业事实准确。
- [ ] 没有虚构口号、认证、历史、业务能力或商标状态。
- [ ] 核心概念能解释品牌，而不是通用行业图标。
- [ ] 一个方向只有一种主要 Logo 架构和一个视觉母题。
- [ ] 图形轮廓、负形、比例和字标关系清楚，缩小时仍有识别潜力。
- [ ] 色彩、字体和图形服务于同一品牌性格，没有效果堆叠。
- [ ] 图片路径正确；正式 Logo 没有被当作可随意重绘的参考图。
- [ ] 历史图片理解与本轮图生图授权没有混为一谈。
- [ ] Prompt、画幅、图片数量和输入素材彼此一致。
- [ ] 同方向变体没有拆成重复调用，不同方向存在实质差异。
- [ ] 没有把位图概念说成可编辑矢量文件、完整 VI 交付或商标检索结论。

工具返回参数或业务错误时，根据模型可见的 Tool Result 修正可纠正问题；不要放宽用户约束、绕过素材授权或把失败结果说成已经完成。
