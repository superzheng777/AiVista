# 海报设计

把主题、图像和文字组织成一张有明确视觉观点、信息层级和传播目标的完成稿。Skill 提供海报领域的设计方法；系统提示词负责通用交互方式，Tool Schema 和 Harness 负责参数、权限、数量与画幅等硬约束。

## 一、先判断任务类型

在设计前区分以下情况：

- 用户只需要文案润色、设计建议或方案分析：直接回答，不调用生图工具。
- 用户要求设计并生成海报、活动主视觉或宣传主图：完成下述设计判断后调用合适的生成工具。
- 用户已经给出可直接执行的完整 Prompt：只检查事实、素材和本轮约束，不重新发明主题、文案或版式。
- 用户要求多页图册、手册、折页、PPT 或跨页物料：不要擅自压缩成单张海报。
- 用户要求商品白底图、详情页套图或以商品展示和转化为核心的电商资产：不要套用海报设计方法。

“一张海报”可能指一张独立完成稿，也可能与“生成多个方案”同时存在。先理解交付拓扑，不要把多张独立方案误做成单画布拼贴，也不要把用户要求的一张拼贴画布拆成多次独立生成。

## 二、锁定不可改写事实

构思风格前，在内部建立一份简短清单。不要把清单原样展示给用户。

### 交付事实

- 交付是一张完成稿、多张独立方案、一个单画布拼贴，还是同一设计的多个尺寸。
- 用户指定的画幅和最终图片数量属于本轮硬约束；以 Runtime 注入的受信任约束为准。
- 用户没有指定的风格、配色和构图可以由你决定，不必为非关键信息反复追问。

### 文字事实

区分三种授权：

1. 用户要求逐字保留：原文、顺序、标点、语言和数字都不能改写。
2. 用户允许提炼：可以压缩解释性内容，但不能改变事实和承诺。
3. 用户只给主题并允许创作文案：可以设计简短标题或口号，但不能虚构日期、地点、价格、联系方式、主办方、产品型号或品牌承诺。

禁止使用“完整保留正文”“展示全部要点”等占位句代替用户要求逐字出现的真实文字。文字过多时用分区、分栏、字号层级或更合适的画幅解决，不要擅自删成氛围封面。

### 主体与素材事实

- 锁定人物、产品、Logo、场景和其他主体的身份、数量、位置、归属及用途。
- 用户明确的左右关系、人物关系、产品外观、材质、安装方式和品牌归属不能被风格模板覆盖。
- 设计可以改变构图、镜头、光线、色板、字体气质和图形关系，不能无依据创造新的品牌、人物身份、活动事实或产品属性。

事实存在冲突、必需文字不明确或关键素材无法绑定时，先向用户确认；缺少可由设计师合理决定的非关键内容时直接做出选择。

### 需求确认门槛

仅在以下未决信息会改变海报事实或交付结构时调用 `request_user_input`：

- 用户要求逐字出现标题、日期、地点、价格、主办方或行动信息，但内容缺失或互相冲突；或者用户给出较长文案，却无法判断应逐字保留、允许提炼还是只作为主题参考。
- “一张海报”“多个独立方向”“单画布拼贴”等交付拓扑无法从请求和 Runtime 数量约束中确定。
- 多张附件的角色无法可靠判断，可能把人物、产品、Logo、风格参考或版式参考错误绑定。
- 用户明确要求保留或禁止某个元素，但现有要求之间不能同时满足。

不要为了风格、普通配色、字体气质、构图或口号候选而暂停；用户只给主题且允许自由创作时，直接提出合理方案。表单只加入尚未解决的字段，可按需使用：

- `copyPolicy`：`VERBATIM`（逐字保留）/ `CONDENSE`（允许提炼）/ `CREATE`（只保留主题并创作文案）。
- `requiredCopy`：必须出现的准确文字；把已提取的内容作为初始值。
- `deliveryType`：`SINGLE_POSTER`（单张完成稿）/ `MULTIPLE_DIRECTIONS`（多个独立方向）/ `SINGLE_CANVAS_COLLAGE`（单画布拼贴）。
- `assetUsage`：各附件的身份和用途，仅在映射确实不明确时询问。
- `requiredElements` 或 `forbiddenElements`：必须保留或禁止出现的内容。

把已有判断作为初始值供用户修正，不要把所有建议字段机械塞进每张表单。用户跳过后，保留已知事实并为其余部分采用合理默认值，不立即重复询问。

## 三、选择正确的图片路径

当前请求直接附带的图片已经提供给模型，同时 Runtime 会注入本轮允许使用的 Asset ID。按以下规则选择工具：

- 当前任务不依赖任何图片：使用 `text_to_image`。
- 当前请求已授权的图片要参与画面、被修改或作为风格/主体参考：使用 `image_to_image`。
- 本轮需要理解某张历史图片，而 Context 中只有 Asset ID：先使用 `inspect_image` 查看，再继续判断。
- 历史图片必须实际参与图生图，但没有成为本轮授权输入：请用户在当前请求重新选择该图片，不得直接把历史 Asset ID 交给 `image_to_image`。

“沿用”“保留”“保持”“修改为”等表达是图片依赖信号，但不是自动授权。先判断用户指的是本轮附件、某张历史结果，还是可用文字描述延续的抽象风格：本轮已授权附件可以直接进入图生图；历史图片可以先用 `inspect_image` 理解，但若要作为图生图输入，仍须请用户在新请求中重新选择。不得把这些表达只改写进 Prompt 后静默使用文生图。

`request_user_input` 可以确认图片的身份和用途，但不能上传图片、授予 Asset 权限或替代真实图片输入。缺少必需图片时，不要用表单伪造已经绑定素材；停止生成并明确请用户重新附加对应图片。

不要因为用户说“新海报”“重新设计”就丢弃本轮明确要求沿用的图片。不要为了用完附件而加入无关素材；每张采用图片都要有明确且唯一的用途。不得猜测、改写或面向用户展示内部 Asset ID。

多张参考图参与任务时，在内部维护最小来源映射：用户对图片的称呼、本轮授权 Asset ID、输入顺序、身份与用途、必须保留内容、允许变化内容。`inputAssetIds` 的选择与顺序必须和 Prompt 中的用途一致；映射不明确时先解决歧义，不能静默漏图或交换身份，也不要把内部映射或 Asset ID 展示给用户。

## 四、建立海报设计系统

### 1. 写一句视觉命题

先用一句内部命题概括：谁或什么是主角、它与画面发生什么关系、观众应感到什么。命题用于统一设计决策，不要把它机械地写成画面文案。

### 2. 选择一个主要原型

每个方案只选一个主要原型，避免把多套版式逻辑叠在一起：

- **Campaign 主视觉**：人物、产品或核心道具形成强视觉锚点，适合品牌活动、发布会和单张广告。
- **编辑人物海报**：先让人物肖像成立，再加入一种主要图形干预，适合文化、时尚和人物主题。
- **概念字体海报**：标题是主视觉，主体与字形发生遮挡、穿插、托起或负形关系。
- **活动信息海报**：用明确阅读动线组织标题、核心利益、时间地点和行动信息。
- **科普信息海报**：以清楚的模块和图形解释知识，模块数量服务于理解，不做成后台仪表盘。
- **拼贴多画面海报**：先定义总画布、网格、主次格、边距和连接方式，让多个画面共享视觉规则。

### 3. 只保留一个第一焦点

缩小画面时，第一眼只能有一个最强锚点。其他元素通过尺度、位置、对比、虚实和留白主动降级。元素很多时按“核心主体—叙事支撑—气氛点缀”组织，不要平均放大所有内容。

### 4. 让文字参与画面

按实际内容建立主标题、辅助信息和微型标识层级，不为凑版式虚构信息。明确文字的准确内容、位置、对齐、相对字号、字重、颜色以及与主体的遮挡或留白关系。标题应成为构图的一部分，而不是后贴的标签。

### 5. 控制色彩与效果

使用有明确角色分工的有限色板：背景、主文字、主体色、强调色和必要的中性色。一个方案只选择一种主要质感或效果，例如纸张油墨、柔和棚拍、玻璃折射、颗粒印刷或单束体积光；其他效果保持辅助，避免风格堆叠。

### 6. 把品牌视为系统

用户提供 Logo 或 VI 时，保留真实素材，从品牌色、字体气质、形状语言和光影方式建立统一视觉。Logo 应清晰可识别，但不默认放大成第一焦点，也不能擅自重绘、改字或增加副标。

## 五、编译可执行 Prompt

每个设计方向按以下顺序写成一段自然、连贯、具体的 Prompt，只保留与当前任务相关的内容：

1. 成品定义：单张完成海报、使用场景、主题和准确画幅。
2. 不可改写事实：准确文案、主体数量、参考图用途、模块数量与顺序。
3. 视觉命题：一个主要概念和希望传达的情绪。
4. 构图骨架：主体位置与占比、阅读动线、前中后景和留白用途。
5. 文字系统：逐层描述内容、字形、字号关系、位置、对齐和与主体的互动。
6. 色彩与质感：有限色板、主要材质、光源方向和阴影逻辑。
7. 模块或拼贴拓扑：仅在需要时说明格数、边距、跨格关系和视觉连续性。
8. 排除项：只加入本任务高风险的限制，不堆砌通用负面词。

Prompt 必须与 Tool 的画幅、图片数量和输入素材一致。负向提示词保持可选，只用于当前任务确实需要规避的问题。

## 六、组织单方向与多方向生成

- 同一视觉方向的多个变体使用一次生成 Tool，通过 `imageCount` 请求多张。
- 不同视觉方向可以拆成多个 Tool Call；每个方向必须在视觉命题或构图机制上真正不同，不能只换配色、背景纹理或字体。
- 所有 Tool Call 的图片总数必须遵守本轮用户约束。用户选择自动时，根据任务需要选择足够且克制的数量，不固定生成四张，也不为了凑数量发明无意义方向。
- 一张单画布拼贴应在一个 Prompt 中写清总画幅、网格、模块数量、接缝和统一视觉规则，不得误拆为多个独立结果。

## 七、生成前检查

调用生成 Tool 前逐项检查：

- [ ] 交付拓扑没有被擅自改变。
- [ ] 必须出现的文字准确，允许提炼和禁止改写的边界清楚。
- [ ] 没有虚构日期、地点、价格、联系方式、品牌或人物身份。
- [ ] 主体数量、位置、关系、材质和参考图用途符合用户原意。
- [ ] 图片路径正确；没有用文生图替代需要参考图的图生图。
- [ ] 历史图片理解与本轮图生图授权没有混为一谈。
- [ ] Prompt、画幅、图片数量和输入素材彼此一致。
- [ ] 只有一个主要视觉焦点，信息层级和阅读动线清楚。
- [ ] 标题参与构图，正文仍然可读。
- [ ] 色彩和主要效果受到控制，没有模板化堆叠。
- [ ] 多个方向存在实质差异，同方向变体没有被拆成重复调用。
- [ ] 物理关系、接触阴影、透视和光源方向没有明显冲突。

工具返回参数或业务错误时，根据模型可见的 Tool Result 修正可纠正问题；不要删除必要素材、放宽用户约束或把失败结果说成已经完成。
