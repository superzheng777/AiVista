# 日系生活碎片

把每张生活照片转译为“真实摄影 × INS 柔和色调 × 亚克力收藏物 × 动态 Scene Map × 可爱注释 × 合理留白”的独立作品。Skill 负责从照片提取生活记忆、设计物件关系和编辑排版；系统提示词负责通用交互，Tool Schema 与 Harness 负责素材授权、画幅、数量、取消和错误等硬约束。

## 一、任务边界与交付拓扑

- 本 Skill 必须以当前请求已授权的照片为输入，并使用 `image_to_image`。没有照片时，请用户上传或重新选择照片，不要用 `text_to_image` 猜测原图。
- 每张输入照片制作一张独立海报：每次只绑定该照片对应的一个 `inputAssetId`，分别调用一次 `image_to_image`，每次 `imageCount` 为 `1`。
- 不得把多张照片拼进同一画布，不得把一张照片拆成多张无关结果，也不得把不同照片提取出的物件混进同一张 Scene Map。
- 用户或 Runtime 指定的总图片数量是硬约束。若它与需要逐张处理的照片数量不一致，不静默漏图、拼图或重复结果；说明冲突并请用户以匹配数量或“自动”重新发起。
- 默认成品为 `3:4` 竖版；只有 Runtime 画幅为自动时才使用 `3:4`。用户已指定其他受支持画幅时严格服从，但摄影区与 Scene Map 仍上下各占画面 `50%`。
- 当前图生图是生成式重构。可以要求高度保留主体身份、结构和姿态，但不能承诺上半部分与原照片像素级一致。用户要求精确原图拼版时，应如实说明当前生成能力边界。

## 二、只确认真正阻塞的信息

照片齐全且用户直接要求日系生活碎片风格时，不调用 `request_user_input`，直接设计并生成。可由设计师决定的物件选择、路线、背景色、标签和版式节奏不要反问用户。

仅在以下未决信息会改变交付事实时暂停确认：

- 用户上传多张照片，却明确只想处理其中一部分，而具体选择无法判断。
- 用户提供准确文案，但无法判断应逐字保留、只作为生活主题参考，还是不在画面中出现。
- 用户同时要求多图拼贴和“每张照片独立输出”，无法同时满足。

需要表单时只加入尚未解决的字段，可以按需使用：

- `selectedPhotos`：要处理的照片名称或顺序，只解决用户可理解的选择歧义，不展示内部 Asset ID。
- `copyMode`：`AUTO_LABELS`（生成生活标签）/ `VERBATIM`（逐字使用文案）/ `NO_TEXT`（不显示文字）。
- `requiredCopy`：必须逐字出现的准确文字，把用户已给内容作为初始值。

表单不能上传照片、授予 Asset 权限或修改 Creation 的画幅和总数量。用户跳过后保留已知事实，对非关键设计选择采用合理默认值，不重复询问。

## 三、设计上半真实摄影

- 保留原图最具识别性的主体身份、结构、姿态、主体关系、真实材质、自然光影和原有色彩氛围。
- 只做轻微、统一的高级摄影调色，使照片接近日系生活方式杂志、独立出版物和生活记录摄影，而不是覆盖原图的滤镜。
- 为适配画幅可以自然延展环境背景，但不得拉伸、扭曲、镜像、替换或改变主体。
- 摄影区域严格占成品上半部分 `50%`。裁切应保住主体和关键关系，不能为了整齐破坏动作、视线或重要物件。

## 四、提取生活记忆点

从该照片中选择约 `4–7` 个最值得记住的元素，不完整复制原场景。候选可以是：

- 人物局部、互动动作或主体关系。
- 食物、饮料、器物、植物、动物、建筑细节或交通工具。
- 能代表地点、季节、习惯和情绪的微小线索。

选择标准是识别度、叙事价值和形状差异，而不是把画面中所有物体都摘出来。优先保留能让用户一眼认出这段生活经历的元素；删除无关背景、重复物件和没有记忆价值的装饰。

不得虚构照片中不存在的地点、人物关系、品牌、日期或事件。允许由可见物件产生轻巧的生活联想，但文字不能把联想冒充事实。

## 五、制作真实亚克力收藏物

- 每个元素保持真实、清晰、可触摸的摄影物件质感，不转成扁平卡通、矢量图标或普通贴纸插画。
- 统一使用柔和自然光、干净高光、奶油感亮部、轻微柔雾、清透阴影与舒适冷暖关系；适度降低生硬对比并提亮颜色。
- 外围加入透明圆润的亚克力或树脂包边、轻微厚度、细腻边缘高光和柔和接触阴影，让它像真实的小型收藏物。
- 亚克力边缘必须与物件轮廓贴合，厚度和阴影方向保持一致；避免光滑塑料玩具、廉价滴胶、夸张玻璃反光和电商抠图素材感。

## 六、组织动态 Scene Map

下半部分严格占成品 `50%`，但内部不使用固定四宫格、等距横排、统一尺寸或平均分布。根据元素的形状、方向和视觉重量选择一种主要运动结构：

- 斜向流动或 S 形路线。
- 环形围合或中心辐射。
- 上下错落或阶梯节奏。
- 双组聚类、边缘切入或不对称漂浮。

元素之间允许明显大小反差、轻微旋转、局部遮挡、贴边和克制裁切。始终保留一个第一阅读起点、一条可跟随的阅读路径和足够留白，做到活泼但不凌乱、松弛但有秩序。

可加入少量细虚线、弧形箭头、路线节点、定位符号、圆点、括号和自然手绘小线条：

- 线条服从整体运动方向，可以绕行、跳接、断开或形成局部回路。
- 不要求所有元素全部串联，也不要让每个物件都带箭头和编号。
- 路线帮助阅读和记忆联想，不能变成业务流程图、复杂信息图或 UI 面板。

## 七、从照片生成色彩系统

- 从上半照片的主导色相、综合色温、光线和情绪推导下半背景，不套固定浅米色模板。
- 背景可以是奶油色、雾蓝、鼠尾草绿或蜜桃粉，也可以是砖红、焦糖棕、暖橙、灰蓝或深绿；选择取决于当前照片。
- 让背景、真实物件、透明边缘、路线和文字共享统一的综合色彩关系。可以适度提亮、提纯和柔化，但不能消除原图辨识度。
- 避免脏灰、死黑、荧光色、高饱和撞色、廉价滤镜和所有照片共用同一色卡。

## 八、让文字参与构图

- 默认根据每个物件的身份、动作、情绪或生活联想，生成少量短标签、词语、小句或符号；不固定词库，不要求所有元素使用相同格式。
- 字体使用轻巧、圆润、有少量自然手写偏差的生活记录字形，可以搭配少量细体小字、便签式文字或微型符号。
- 文字沿 Scene Map 的空隙和路线自然落位，与物件和标记形成灵活图文混排，不能遮挡主体或把下半部分填满。
- 用户提供准确文字并要求保留时逐字使用，不改写、不翻译；没有事实来源时不虚构日期、地点、人名、品牌和事件。
- 用户要求无文字时，明确排除标题、标签、字幕、水印和乱码，但可以保留不具文字含义的克制路线符号。

## 九、编译并执行 Prompt

为每张照片编写一段独立、完整且不超过 Tool 长度上限的 Prompt，按以下顺序组织：

1. 独立海报、准确画幅、上下各 `50%` 的双区域结构。
2. 上半摄影需要保留的主体身份、结构、姿态、关系、材质、光影和原有色彩。
3. 允许的轻微调色、背景延展，以及禁止拉伸、扭曲、镜像和改变主体。
4. 下半选出的 `4–7` 个生活记忆元素及其叙事联系。
5. 每个元素的真实摄影质感、INS 柔和调色、亚克力包边、厚度、高光和接触阴影。
6. 当前作品使用的动态 Scene Map 结构、大小反差、路线、遮挡、裁切和留白。
7. 从上半照片派生的背景综合色和冷暖关系。
8. 准确文案或生活标签的内容、字形、位置及其与路线的关系。
9. 当前任务最重要的排除项，例如多图拼接、固定四宫格、平均排布、统一尺寸、扁平卡通、复杂 UI、箭头泛滥、塑料玩具、电商素材和模板化构图。

每张照片分别调用：

- Tool：`image_to_image`
- `inputAssetIds`：只包含该照片的一个本轮授权 Asset ID
- `imageCount`：`1`
- `aspectRatio`：服从 Runtime；自动时使用 `3:4`
- `userFacingPlan`：用一段简短说明概括真实摄影保留、生活元素提取和亚克力 Scene Map 转译；同批照片使用同一总体说明，不逐张重复解释

## 十、生成前检查

- [ ] 当前请求至少有一张已授权照片，没有绕过权限使用历史 Asset ID。
- [ ] 每张照片独立生成，每次只绑定一张照片且只输出一张结果。
- [ ] 总图片数量与输入照片数量、Runtime 硬约束一致。
- [ ] 上下区域严格各占 `50%`，自动画幅使用 `3:4`。
- [ ] 上半摄影保留主体、关系、姿态、材质、光影和原有气氛，没有拉伸、镜像或身份替换。
- [ ] 下半只提取约 `4–7` 个有记忆价值的元素，没有完整复刻原场景。
- [ ] 物件保持真实摄影质感，亚克力边缘、厚度、高光和接触阴影可信。
- [ ] 排版具有明确阅读路径、大小反差和留白，不是固定网格、流程图或复杂 UI。
- [ ] 背景和文字从当前照片派生，没有套用固定色卡或虚构事实。
- [ ] Prompt、输入照片、画幅、文案和结果数量彼此一致。

工具返回参数、权限或业务错误时，根据模型可见的 Tool Result 修正可纠正问题；不得移除必要照片、放宽用户硬约束、改用文生图或把失败结果说成已经完成。
